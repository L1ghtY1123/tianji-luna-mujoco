# 数据库驱动的单臂抓放（2026-11-11）

本文描述当前本轮实现。历史实验中的固定输入队列、失败换臂与强制观测回位不作为当前指令。

## 物体事实与下一目标

ObjectDatabase 是永久实例、原始 RGBD、独立身份掩码、操作、加工谱系与几何来源的唯一持久事实来源。ObjectMemory 只作数据库读取缓存和事务提交前的暂存。TaskSpec 表达任务要求；任务账本只记录本任务已承担的输入、执行臂、转移和完成回执。task_bindings 只保存任务引用，不再复制已选物体队列。

每轮查询当前数据库与已关联观测，排除非任务输入、已完成和消耗实例。用户指定顺序时遵守顺序；否则 selection_order=visual。多个候选用一个 Decisions choice 比较原始 RGB 和可选独立掩码，优先暴露抓取面、少遮挡、周围间隙大的对象。只有一个合格候选时直接选。候选 ID 只是本轮选项，不形成固定后续顺序；移除障碍后下一轮重新选择。视觉选择不证明 IK 或路径可行。

二值/多选按概率最大项，不设 0.8 门槛；平分、拒答和明确 unknown 保留未知。没有当前候选也不能直接宣布 all 任务完成，仍需当前来源余物核验。

## 数据库与空间同步

SQLite object_changes 在物体创建或物理状态变化时记录单调 revision，和物体状态在同一个事务提交。提交后通知空间记忆，重复事件及相同物理状态不产生虚假更新；事务失败不会发通知。描述等元数据直接更新空间状态及版本，不重建几何。位置、几何来源、CAD、运输、加工或退役变化将相关几何标为失效。

数据库记录当前测量的采集编号、点云指纹及 CAD 位姿；原始 RGBD 与掩码保存在数据库对应表中，避免重复保存点云。建图只接受已提交且来源一致的几何。GPU 发布绑定开始建图时的数据库 revision；期间数据库变化则拒绝将旧结果标成当前场景。规划前再消费提交日志，防止使用未同步的场景。

SQL 提交不隐藏 GPU 建图或机器人动作。状态立即同步，失效碰撞层在显式 build_scene、已验证 attachment 或绑定的容器占据发布完成前不可执行。空间记忆保留的是从数据库事实和测量生成的碰撞投影，不另维护物体集合。

## 单臂流程与重试

single_arm_transfer_v1 处理一个目标与一个目的地。choose_arm 必须确认同一臂的工作空间同时覆盖目标实测位置和控制台固定的释放 TCP XYZ；盒子释放高度采用当前 CAD 盒顶加配置相对高度，桌面采用实测高度加配置相对高度。没有共同臂时停止，不交接。初步位置可达仍不能替代抓取姿态 IK、携物路径及碰撞检查。

第一次选择的执行臂绑定到本次转移。重新识别、空抓恢复及重新规划都保留该臂；同一转移修改执行臂直接报错。

第一次 plan_grasp 失败或未知，显式 generate_grasps 重新计算，再以同一臂 plan_grasp 一次；第二次失败结束。新规划使用实际当前关节状态，保持目标、场景、坐标和碰撞绑定。没有失败后换臂规则。

## 观测恢复触发条件

| 情况 | 当前处理 |
| --- | --- |
| 身份/支撑/目的地不明确 | 先在当前位置 fresh observe_scene，再重试绑定 |
| Lift 后 verify_grasp=no | 校验同动作空抓且无 attachment，清理临时状态；当前位置观测、更新几何、恢复同臂后重抓一次 |
| Lift 后 verify_grasp=unknown | 保留未知并结束；不能当作空手回位或重抓 |
| verify_place=unknown | 先在当前位置 fresh observe_scene，再核验；不重放抓取、搬运或释放 |
| 当前位置补观测后仍缺少必需 ID、深度几何或 RGB | observation_recovery 程序 router 检查是否已确认空手、是否与配置观测位姿不同，满足后才允许图中的回位路线 |
| 已在观测位姿、证据已充分、未确认空手或恢复次数耗尽 | 停止，不因失败或低概率盲目移动 |

回位前仍必须建立有效移动地图并通过实际数值运动检查，无法建立地图就不能回位。程序的缺证据检查不声称知道遮挡原因，也不覆盖原始视觉判断。额外腕部视角若由自定义 graph 声明，仍有其独立前提。

正常批次每件完成后在当前位置重新观测，不再例行强制返回观测位姿。用户要求的最终回位、VLA 处理姿态等独立任务前提仍须由 graph 显式执行。

## 几何与官方接口

生产配置为 cad_esdf。桌面使用实测 cuboid，盒子/黑件使用 FoundationPose 当前 CAD 位姿和 CAD 碰撞；CAD 抓取使用分臂离线库。未知物体掩码深度通过官方 Mapper 融合 TSDF，导出表面点供 GraspGen，并生成 ESDF 参与碰撞。缺少当前 TSDF 时直接报错，不回退原始点云或 OBB 表面。OBB 仅保留数值包络、attachment 等明确用途，不再作为未知静态物体的碰撞替代物。

Mapper、IK、MotionPlanner、BatchMotionPlanner 均使用锁定 cuRoboV2-Fast v0.9.0 / 42498cf4 的公开接口，SDK 源码只读。Mapper 保留官方默认 TSDF 5 mm、ESDF 50 mm 和其他算法参数，仅提供观测尺寸、相机数及空间范围。ESDF 分辨率与 TSDF 表面分辨率不同，部分观测不代表已恢复遮挡表面。抓取前允许源支撑接触、Lift 后视觉确认才 attachment 的原有边界保留。

Decisions 始终使用原图和按需独立 mask/depth，不做身份三维投影、裁剪、描边、曝光增强或算法视觉成功预判。数值 TSDF/ESDF 与身份判断分开。

## 已有验证与边界

证据位于 data/runs/single-arm-memory-20261111：14 项 CPU/接口检查通过；包括真实 SQLite 回滚/幂等、动态图选择、两端共同臂、同臂有限恢复、原始图像/掩码、完整图数据流和编译修订。

隔离 GPU 使用官方 Mapper 默认参数完成合成双相机掩码深度检查。历史真实 RGBD 构建混合场景成功：2 个 CAD、1 个桌面 cuboid、2 个 ESDF；两件未知物体分别导出 816、802 个 TSDF 表面点。816 点实际送入 GraspGen，返回 100 个 TCP 候选。检查没有机器人动作。

冻结原图真实 Decisions 选择合法目标，confidence=0.58 直接采用。完整 Responses 首稿通过：123.7 秒、展开 152 节点、selection_order=visual，6 个 observation_recovery 程序 router，没有换臂 router。这些是冻结输入和接口验证，不等同于完整机器人任务成功。部署和完整仿真结果在同目录独立记录。

统一终止失败收尾见 [终止失败回位](terminal-failure-return-20261111.md)，对所有耗尽和未预料失败适用；已知持物保留携物避障，原任务失败不变。
