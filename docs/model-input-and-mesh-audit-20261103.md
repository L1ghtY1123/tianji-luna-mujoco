# 模型输入与 CAD 规划耗时核查

本轮针对实际归档 P77（9791a5a15f7743b3bfcb7d310d8f58b3）及相同 P72 规划请求核查，正常流程仍由一次初始 Responses 生成，恢复由 Decisions 选择注册能力。没有改 SDK、物理净距、抓取候选集合或成功判定。

## 已确认的耗时原因与改动

P72 的 torch CPU/CUDA profiler 显示，CUDA 自耗时总计 6.475 秒，其中 swept sphere / obstacle collision kernel 为 5.446 秒（84.11%，808 次）。这是碰撞计算热点，不是 Decisions 等待。原始蓝盒 CAD 为 33,082 面，黑件 90,916 面；此前的 2,000 面资产只用于 FoundationPose，尚未用于轨迹优化。

现复用已经审计的降面数 CAD，转换到原始 visual 的米制规范坐标。蓝盒 2,000 面、黑件 1,999 面。原始到简化表面的离线抽样最大距离约 0.933 / 1.253 mm，不作为严格 Hausdorff 界。低面数只用于公开 plan_grasp / plan_pose 的优化；返回或异常时恢复原始 CAD，现有执行前碰撞与接触检查继续使用原始几何。恢复失败不得继续规划，下次刷新须重新上传完整场景。未知 OBB、桌面 cuboid、attachment 和普通障碍 5 mm 净距不变。

资产位于独立 CAD 库 `runtime/planning_meshes/`，项目 `resources/planning_meshes/` 为发布副本。manifest 校验原始 CAD、visual 网格与派生网格 SHA-256、单位、资产与坐标变换。原始 CAD、FoundationPose 资产及左右臂离线抓姿未被覆盖。

匹配版本 cuRobo commit：8e734f3ced1df898990bcd92de40abce475907db。已检查 BatchMotionPlanner.plan_grasp、MotionPlannerCfg、MeshData.load_batch/_load_mesh_into_cache、Mesh.get_mesh_data 和共享 collision checker：

- plan_grasp 内部各阶段仍由原生 SDK 调用，未覆盖其内部 self.plan_pose。
- SDK 的 Warp mesh 缓存按障碍物名称复用；临时优化网格使用独立缓存键，永久清单 ID 与发布地图名称不变。
- Mesh 同时有 file_path 与顶点时会优先读文件，因此路径和网格数组一起切换。
- 通过公开 update_world 切换，保留目标禁用集合，最终恢复完整世界。诊断逐次读取 GPU mesh ID 与实际面数，确认优化世界为 1999/2000/2000，恢复后为 90916/33082/33082。

同一历史地图、请求、batch=2、种子数与 CPU 配额下交替对照：

| 调用 | 原始 CAD | 低面数优化并恢复原始 CAD |
|---|---:|---:|
| 第一次预热后 | 6.802 s | 2.431 s |
| 第二次预热后 | 6.388 s | 2.747 s |

每批均 2/2 规划成功。低面数第一次包含冷构造为 9.349 s，未混入上述预热对比。隔离测试没有移动机器人或修改生产地图；结果为 `data/performance-unpack-20261101/timing-78-mesh-comparison.json`。完整任务耗时须另行测量。

## 实际模型输入逐项核查

核查以归档中的真实 request 为准。生产 Responses 使用 graph_context，它覆盖兼容库的旧 steps/recovery 提示。P77 实际输入是三张初始 RGB、自然语言、skills 合同/说明、状态转移、完成要求及候选清单规范。没有把仿真物体真值或 CAD 真值位姿给模型；初始清单不证明当前身份。graph、subgraph、node、edge 是任务编排标识，物体永久 ID 独立绑定。

| 判断 | 实际证据与问题范围 | 后续边界 |
|---|---|---|
| 清单关联 | 三相机 RGB、同帧 R/C 定位对照、历史参考注明时间；只判同一实例、可见性及漏列目标 | SAM3 只提候选，Decisions 绑定 ID，几何阶段才用深度 |
| CAD 检索 | 当前已绑定掩码主体与 CAD 参考图；只选一个可配准模型 | 不要求先成功配准；FoundationPose 才求姿态；永久实例 ID 不等于 CAD 型号 |
| 来源/最终目的地/输入成员 | 来源支撑与待抓输入分开；最终产物目的地与当前输入处理区域分开 | 未完成未来处理不妨碍解释目的地 |
| 区域语义 | 当前 transfer、用户原话、配置区域绑定；额外空间约束只读对应阶段语言 | 指定区域固定配置 XY；普通区域按 4→8→16 候选，XY 后求 Z |
| 执行臂与 XY | 有限选项的操作提议，保留原始 confidence；没有额外空间要求的 XY 请求无图片 | 数值工作空间、IK、碰撞和轨迹随后检查；提议不是安全证明 |
| verify_place | 一次 Decisions 同时看当前三相机 RGB与带时间标记的参考；支撑/容器关系、是否仍夹持，必要时粗略落点关系 | 不调用 SAM3、OBB、FoundationPose 或毫米级落点测量 |
| verify_unpack | 三个相机并行独立比较该相机 BEFORE/CURRENT；任一完整相机证据同时满足两个事实才通过 | 后续 observe_scene 才关联独立产物 ID；动作回执不证明产物出现 |
| 完成核验 | 当前 RGB、逐物体交付与处理凭证、输出谱系、数值回位反馈 | 已消耗粉色输入不要求仍出现在最后图像；空队列不证明成功 |
| 恢复 | 失败节点、原始目标、有效历史、当前证据、已尝试动作、满足前提的注册能力与类型参数 | 仅在视野问题时选择补视角；不得原位重拍追求 confidence，不自动重放物理动作 |

本轮修正的输入矛盾：

1. HSV 词表没有粉色类别，导致已关联的粉色清单对象被写成 color=unknown。当 HSV 无对应类别时保留清单参考颜色，同时归档 heuristic_label 与 semantic_source；已有明确像素颜色不被参考覆盖。这不重新判身份，也不把 unknown 事实变成 yes。
2. 配置区域说明曾写“区域内任意位置”，与用户指定固定 XY 冲突。改为明确：处理能力的接受范围是能力容差，current placement_mode=configured_xy 仍固定中心 XY；未修改处理能力容差数值。
3. 拆包核验每个请求仅有一个相机，却要求“综合这些视角”，并提到并未输入的 CAD。现明确只判本相机当前图，CAD 外形文字是预期外观，不再暗示已提供 CAD 证据。并行执行和原有事实判定不变。

P77 的 6 次 observe_scene 均为 graph 显式节点。其中每次释放后先观测/建图用于回位规划，回到观测位姿后再观测，另含初始与拆包后观测；没有将它们误称为运行时隐藏回位。是否减少这些几何刷新，需要保持回位轨迹的场景有效性，不能只删节点或放松检查。

## 验证记录

P78（8f61097b760e45328a97db33f781485e）在运动前失败，155.6 秒，31 次 Decisions。根因是初始 graph 的局部 build_scene 同时列了三个物体和合法桌面永久 ID，但运行时的对象层校验把桌面当成“不在清单”。恢复重复原参数未能修复，最终呈现 decisions_recovery_unknown；不能把这一根因归为模型视觉判断失败或 cuRobo 慢，也没有从统计中删除这轮。

timing-80 修复该接口不一致：局部 CAD/OBB 对象 ID 可附带清单中已有桌面 ID；桌面仍通过独立的实测支撑输入建立 cuboid，原请求与支撑 ID 保留在审计中。只包含桌面的局部“对象层”请求返回明确错误，未知实体、marker 或配置区域名字仍不能冒充对象层。参数 schema 与 skill 说明同步说明此边界，未插入任务动作或改写 graph。相关建图、映射生命周期与网格测试 90 项通过；独立 CAD 发布及恢复失败后的强制完整世界刷新另有回归覆盖。
