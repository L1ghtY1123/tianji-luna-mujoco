# observe_result

状态：拟议独立入口；现有 execute_grasp/execute_place 已有末次结果采集。遵循 [公共接口](../common.md)。

## 目的和调用条件

回答“这个抓取/放置动作之后，传感器和机器人反馈记录了什么”。仅在没有有效动作后 capture，或 JEV 判断核验需要新的时间/反馈证据时调用。

执行 skill 已返回合格结果帧时直接交 verify 使用，不要求再调用本技能。持有物体被遮住不自动构成新拍照理由。

## 输入和前提

明确的动作标识、`phase=post_grasp|post_place`、执行臂、预期验证对象/目的地引用、当前会话。动作必须已到允许观察的结束/停止状态；不能把未来帧、抓前帧或另一个动作的结果混入。

本技能每次只新采集一组结果数据，已有结果帧的复用由消费者处理，因此没有“复用时顺便重拍”的隐藏分支。

## 固定流程

1. 校验动作状态、会话和采集预算。
2. 原位采集三相机同步 RGBD 与捕获时双臂关节、夹爪位置及项目已支持的反馈窗口。
3. 绑定 action/phase/capture 版本，保存原始结果引用。
4. 返回新结果证据，标记相关核验有未消费的新输入。

不调用 SAM3、GraspGen、VLM 或运动规划，不重新移动、不重建场景。执行 skill 的固定末次采集可以共用这段算法；不会造成第二次传感器采集。

## 输出、状态和结束

输出 result_capture 和反馈，不能返回“目标已放进盒子”的任务结论。采集错误、状态变化和超时返回各自原因；一次采集即结束。是否 held/empty/unknown 或 placed 由 verify 技能计算，恢复由 JEV 决定。

## 验证场景

已有 post_grasp 帧和明确夹爪反馈时跳过本技能；结果帧丢失时补一帧；新动作后拒绝旧 action 的结果；抓后看不到物体时仍完整保存夹爪反馈；同一帧不得多次冒充新核验证据。
