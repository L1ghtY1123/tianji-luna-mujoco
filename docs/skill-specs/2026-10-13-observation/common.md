# 观测定义的公共接口

适用于本目录拟议定义；字段是接口约定，**不是已存在的 API/schema**。具体实现应沿用项目现有数据类型，显式完成兼容映射。

## 类型与坐标约定

| 输入/引用 | 逻辑类型与约定 |
|---|---|
| capture / observation / object / action / scene / preset 标识 | 非空字符串；由实际生产者返回，不由 JEV 猜测或编造 |
| generation、算法/配置/分析版本 | 项目定义的整数或版本字符串；比较时保持原类型 |
| capture 选择 | `new` 或带一个有效 capture_id 的 `existing`；两者互斥 |
| subject | 已测对象 ID，或带 world 坐标系及测量来源的区域引用；寻物时允许声明的工作区引用 |
| 图像与深度 | RGB 为 H×W×3 uint8；深度为 H×W 米制数值及同尺寸有效掩码；无效值不反投影 |
| 点云与变换 | N×3 米制世界坐标；相机外参为带方向定义的 4×4 刚体矩阵，内参以像素为单位 |
| 机器人反馈 | 捕获时双臂关节及夹爪位置，沿用项目弧度单位；不得与另一次反馈静默拼接 |
| 相机与臂 | `3` 头部、`2` 左腕 A、`1` 右腕 B；执行臂 A/B 是独立约束 |
| 计数与耗时 | 非负整数次数、秒制耗时；同步帧是一组采集，不是按相机计三次 |

## 捕获与分析

观测分析的 `capture` 必须显式为 `existing(capture_id)` 或 `new`。前者只处理已取得的像素、深度和捕获时反馈，后者在当前位置取得一组三相机同步 RGBD；不移动，不默默从复用回退为新采集。实际无法获取时返回错误。

已有帧须匹配 generation、标定、所需动作时序及相关环境变化。时间较近不足以证明有效。捕获之后发生了会改变本次查询几何或结果的动作时，旧证据不能标成当前；历史身份引用可以保留。

`observe_result` 专门负责结果采集，不分析场景；执行 skills 已经留下合格结果帧时无需再次调用。`move_to_observe` 的到位 capture 也可直接供其他技能分析。

## 必须能表达的输出

| 内容 | 说明 |
|---|---|
| outcome / reason | 完成分析、证据不足、拒绝、服务错误、超时、取消或预算耗尽；与任务结果分开 |
| purpose / subject | 本次查询目的、对象/区域或动作；不能只写“观察完成” |
| capture_id / generation / time | 本次实际使用的数据版本及反馈来源 |
| camera_sources | 逐对象记录真实贡献像素/点的相机；没有贡献不是对象不存在 |
| evidence | 实测对象、点云/图像引用、几何计算或辅助语义；可审计原始产物 |
| gaps | 具体缺失项、适用对象/区域、依据；无法判断时明确 unknown/not_evaluated |
| effects / invalidated | 是否新采集、移动、分析；哪些旧产物不能再使用 |
| cost / reuse | 新采集、分析、API、移动次数，耗时、缓存来源和剩余预算 |

可用的缺口语义包括：`not_observed`、`invalid_depth`、`association_ambiguous`、`stale_geometry`、`semantic_ambiguous`、`relevant_region_unobserved`、`no_new_information`、`not_evaluated`。程序返回缺口，JEV 决定下一技能。

只有已指定并实际检查的区域才能标 `relevant_region_unobserved`。没有路径时，观测 skill 不能声称检查过机械臂完整扫掠空间；对应项为 `not_evaluated`，路径形成后由规划/验证提供进一步证据。

## 质量证据不等于完整性保证

记录有效深度点数、掩码内有效深度比例、分布范围、来源相机、关联冲突、截断/出画情况及算法输入检查结果。比例的分母是实际图像掩码，不是不可知的完整物体表面。不要伪造“整个物体已覆盖 90%”之类指标。

这些指标可以判断数据是否满足某个算法的输入条件，但不保证生成有效抓姿或可执行路径。阈值引用经验证的算法配置；尚未验证的质量项保留 unknown，不能随意设定相机数或点数作为安全证明。

## 状态、缓存与预算

- 同一 capture 的新语义/分割结果是新分析证据，不是新拍照。结果核验是否有新证据，应按 capture、分析版本和已消费结果共同判断。
- 缓存键涵盖实际图像/深度、标定/反馈、查询对象/目的、算法及参数版本。相同 observation_id 但不同数据不得命中缓存。
- 新几何或实例掩码改变了地图依赖时，把对应地图/候选/计划标为待更新；不自动重建。结果图像的采集本身不必清掉无关地图，但抓取、释放、碰撞等相关环境改变不能被忽略。
- 场景分析保留三路原始深度供建图，不只保留识别出的目标。相机无目标掩码也不能因此丢弃它的环境深度。
- 每次最多新采集一组 RGBD；禁止 skill 内循环采集到满意。SAM3、VLM、规划和运动分别使用有界请求及项目已配置超时。预算耗尽返回证据，不自动判定任务失败。
- 同帧重分析只计分析预算；同帧 VLM 缓存命中不计新的 API 请求；重复移动无新收益必须如实记录，不能伪造 progress。

## 观测运动所需的建图接口

这是对现有 build_scene 的拟议条件扩展，并非新增自动建图步骤。JEV 显式选择 `collision_policy=observation` 后，输入当前有效 RGBD、工作区/已测区域、标定/反馈和配置；`target_id` 允许为空。已有目标时，它的测量表面也保留为障碍；无目标时处理背景/工作区，不能为了满足接口伪造一个目标。

该模式的硬前提是建图所需数据有效，不依赖 target_selected、views_ready 或已有抓姿。`selected` 和 `held` 模式仍分别要求有效目标或已验证持物身份，不能借此放宽接触策略。

固定建图流程沿用实测深度处理、机器人表面过滤、桌面估计和 TSDF/ESDF，使用所有可用同步深度；不得暗中将腕部深度置零。结果绑定 capture、分割/配置版本、区域与 observation 策略，返回场景 token 及已知/未知空间证据。尚未支持某项路径观测检查时明确 not_supported；建图成功不承诺所有观测运动可行。

move_to_observe 消费这个场景，并对具体路径做检查；缺少场景时拒绝，所需路径检查未实现时返回 unsupported_constraint，路径已检查但证据不足时返回 insufficient_evidence。当前代码的无目标建图和未知空间门控都尚不支持本定义，必须作为实施前置项，不能只通过修改文档启用。

## 重复视觉请求的统一返回

拟议接口允许读取有效缓存，运行时不再以单独的 `scene_inspected=false` 或 `result_inspected=false` 阻挡读取；这两项仍可作为 JEV 的已处理证据。

先校验 capture/action/实例和请求指纹，再查缓存。命中时返回缓存及 `no_new_information`、新增 API 次数 0，不记动作失败，不把已消费的核验证据重新标为 pending。缓存未命中才检查剩余预算并执行一次请求。不同帧或问题不能冒充缓存命中，也不能用同帧新问法自动绕开预算。

当前实现可能在外层被 inspected 前提拒绝，尚未采用上述统一返回。迁移必须同时修改契约和状态处理；不能宣称现在重复调用就一定返回缓存。
