## 明确保留的六种职责

前三项是观测目的；第四项改变视角；后两项分析已有图像。

| 定义 | 一次调用解决的问题 | JEV 何时考虑调用 | 当前状态 |
|---|---|---|---|
| [observe_scene](observe_scene/SKILL.md) | 当前任务范围里看到了哪些物体、容器和区域？ | 尚无清单；动作改变场景后需要更新清单；需要查找下一目标或核对剩余目标 | 拟从 observe 的 initial/集合路径提取 |
| [observe_geometry](observe_geometry/SKILL.md) | 指定源物体、目的地或区域的实测几何是什么？缺哪里？ | 对象已明确，但该对象/区域尚未分析、几何过期或存在具体缺口 | 拟从 observe 的 fine/定向查询提取 |
| [observe_result](observe_result/SKILL.md) | 指定动作之后的图像与机器人反馈是什么？ | 执行 skill 没有留下有效结果帧，或验证需要新的时间/反馈证据 | 当前采集是执行 skill 的内部能力，尚无独立入口 |
| [move_to_observe](move_to_observe/SKILL.md) | 将相机移到明确指定的已配置位姿，取得新视角 | 已明确固定遮挡/出视野等缺口，且该预设位姿有机会改善；JEV 选择移动 | 同名技能已有，但本定义需要修改其边界 |
| [inspect_scene](inspect_scene/SKILL.md) | 已有图像中物体类别、成员或关系的语义是什么？ | 相关像素可见，普通视觉不能消除任务语义歧义 | 已有；需要按本定义补齐契约说明 |
| [inspect_visual_result](inspect_visual_result/SKILL.md) | 已有动作后图像能否为结果提供辅助证据？ | 普通验证仍不明确，图像中有可解释的相关证据 | 已有；需要按本定义补齐契约说明 |

`verify_grasp`、`verify_place` 负责核验，`build_scene` 负责建碰撞地图，`generate_grasps` 负责生成抓取候选；它们不改名为观测技能。`observe` 迁移完成后不应与前三项长期并存成为目的不明的万能入口；当前版本继续保持原实现，不能现在删除。

## 如何决定需要哪种观测

这些是供 JEV 判断的适用条件，不是固定执行顺序。每个 skill 的程序前提只校验被选动作，不代替 JEV 选择。

| 当前缺少的东西 | 对应能力 | 明确不会解决什么 |
|---|---|---|
| 任务范围内当前可见对象清单 | observe_scene | 不能证明遮挡区没有其他对象 |
| 选中对象/区域的分割、深度或几何分析 | observe_geometry | 不证明抓姿可达或整条路径安全 |
| 抓后/放后的有效图像与反馈 | observe_result | 不直接宣布抓取/放置成功 |
| 已有数据的图像语义解释 | inspect_scene / inspect_visual_result | 不补看不到的表面 |
| 固定遮挡/出视野，需要不同方向的实际测量 | move_to_observe | 当前预设未必解决缺口；不是自动寻找位姿 |
| 有当前深度，缺碰撞地图 | build_scene | 重建同帧地图不增加几何可见性 |
| 只有当前候选 IK 无解或服务异常 | 交回 JEV 分析原因 | 不自动归因为需要观察 |

仅仅“左腕看不到”不属于证据缺口；任意相机提供的实际目标几何都可供左臂使用。对当前目标逐个判断，不让其他对象的可见性成为它的硬门槛。

## 红色之后抓绿色的具体例子

任务：“用左臂把红色和绿色物体放进蓝色盒子”。红色已放好，右腕能看到绿色，左腕在撤离位置。

1. `execute_place` 已留下 post_place capture；`verify_place` 用它确认红色结果。
2. 若该 capture 尚未分析绿色/剩余清单，JEV 可选择 `observe_scene(capture=existing)`；若已明确绿色且只缺其分析，可选择 `observe_geometry(capture=existing, subject=绿色)`。两者不用重复执行。
3. 若清单和绿色几何已由当前帧完整提供，跳过上述分析。若没有有效动作后帧，原位新采集即可，不能用放红前的帧冒充放红后的场景。
4. JEV 选择绿色，保留左臂约束。红色释放使环境几何改变，按需显式 `build_scene`，再生成和评估左臂抓姿。初次用于抓绿色的地图应反映放红后的证据。
5. 不因为左腕缺少绿色掩码调用 `move_to_observe` 或 OpenAI。只有出现具体的额外证据缺口，才考虑它们。

这是一条实例说明，不是把 JEV 替换成固定步骤链。即使有三个相机，也不能声称取得目标所有表面或整个桌面的完整可见性。

## 自动寻找观测位姿的范围

本次定义只保留已有“配置位姿”的移动能力，不新增通用自动位姿搜索。记录观测目的、缺失区域、预设位姿和移动后的实际增益；如果预设不能改善关键缺口，明确返回能力限制，由 JEV 判断下一步。

未来自动位姿规划只有一个独立职责：给定缺口和实测场景，计算有限候选及可达/碰撞/预测收益。执行仍由明确的移动 skill 完成，预测收益不能替代到位后的测量。不能以“必须凑齐三相机目标点云”为它的需求依据。

## 实现之前必须解决的接口差异

- 将三个观测目的与采集/分析操作分开；读取已有帧不能消耗新采集计数。
- 去掉双腕相机编号作为 `views_ready` 的充分/必要条件，也去掉集合中所有源物体一起决定当前目标状态的门槛。以逐对象、逐目的证据替代笼统 ready；不新增“全场完整”的替代布尔值。
- `build_scene` 的观测运动模式必须允许目标尚未找到或没有抓取就绪证据；保留所有测得障碍。否则“先建图才能看、先看全才能建图”形成循环。JEV 决定建图，移动 skill 消费已有图，不再隐式建图。
- 接入动作相关未观测空间证据；现有碰撞检测没有这项保证。没有相关路径证据时不能仅用规划成功宣称盲区安全。
- 运行时 `contract.json`、模型精简说明、参数选择、执行分支和状态失效一起更新并测试，之后才把新名字注册给 JEV。

## 连续抓放讨论记录（2026-10-13，未实现）

本节保存讨论结论，不表示上述接口已接入，也不把仍在讨论的方案当成用户已经确认的实现。

### 已要求保留的结论

- 每轮抓放后使用动作结束后的现场证据；可复用有效的放置并撤离后的 capture。取得新观测不等于双臂返回预设观测位姿。相机数量不能单独决定观测是否充分。
- 维护任务物体清单和持续 ID，区别于每帧 SAM3 掩码。确认成功的对象退出待抓取集合、进入完成记录，仍作为环境障碍；暂时不可见不等于消失或完成。持物身份由历史抓取绑定延续，不能把预测几何当作新测量。
- 用户指定执行臂、目标范围、排除项和顺序优先。未指定顺序时，默认按执行臂当前 TCP 到目标当前观测位置的距离提供最近优先证据；JEV 结合约束选择，随后检查规划可行性。该距离不代表实际路径长度。
- 禁止颜色专用或固定“先红后绿”流程。JEV 选择技能、目标和恢复；技能内部只执行明确、有界的算法。不能把下述适用条件实现为自动恢复状态机。

### 用户本轮新增设想

- 抓放成功后启动相机观测；若其他目标和盒子的位置姿态未变，希望避免重复建图。
- 若有明显变化，希望重新移动到观测位姿并建图；普通视觉判断不了时考虑 OpenAI。
- 不同物体移动后保留清单；相同工件大幅移动、掩码重合降低时，考虑重建物体清单。

### 上轮细化结论（用户要求继续保留；后续明确修订优先）

- “不全量重建”需与“不更新地图”分开：抓取源区域和放置目的区域已经改变；盒子没有移动也不代表盒内占据未变。若实现局部更新，必须使旧位置占据失效、用当前实测证据更新放置区域和受影响区域，并重新核对下一目标的碰撞过滤及持物状态。清除旧占据不等于宣布对应空间已测得空闲。未验证的历史区域只能带版本和有效性保留，不能冒充当前测量。当前没有完成上述增量更新能力的验证；不能仅添加一个跳过 build_scene 的判断。
- 当时建议位置改变不自动要求移动相机；此条的非目标变化策略已被下节用户新要求覆盖。移动前的规划仍必须有可用碰撞证据，不能依赖到达观测位姿后才建出的地图。
- 变化检测输出“未发现超出任务容差的变化 / 发现变化 / 不确定”及可见范围、深度支持、版本和误差证据；不把未看见当作未变化。比较相关环境障碍，不只比较任务目标；容差须结合深度误差、体素大小和规划余量验证，不能随意固定。
- 掩码 IoU 只作为辅助。腕部相机运动会改变投影，应使用相机标定和自身位姿，将历史实测表面投影到当前视角或转换到同一坐标系，再在共同可见、有效深度范围内比较。遮挡和分割波动可能导致低重合；部分可见点云的质心变化不直接等同于物体真实位移。对称物体不可观测的转角不应被编造成精确姿态。
- OpenAI 可在一次有限请求中辅助解释前后图像中可见对象的身份、位移或遮挡关系；是否调用由 JEV 判断。它不能补充隐藏深度，不能凭视觉描述证明精确位姿未变或碰撞地图仍有效；图像本身缺证据时应保留 unknown。
- 不同物体移动后，关联唯一时保留 ID；相同工件移动后也先尝试唯一的一对一关联。只有对应关系无法恢复时，才考虑重新枚举受影响的未完成工件、分配新 ID，并保留旧记录及“关联未知”说明。完成记录、已确认数量、未受影响 ID 不清空；旧的暂缓/失败记录保留但不强行转移到某个新 ID。若用户指定的是某几个历史实例，无法关联时不能擅自换成同类其他工件。

参考：[OpenCV 相机投影](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)、[OpenAI 官方视觉能力及限制](https://developers.openai.com/api/docs/guides/images-vision)。

### 后续用户明确修订：头部变化检测、目标层更新、其他变化必重观测

仍为设计讨论记录；此次未修改运行代码、机器人行为或远端服务。

用户明确要求：

- 优先用固定头部相机前后 SAM3 掩码比较各物体和盒子，普通视觉不能判断时调用 OpenAI 辅助。
- 已抓放目标的移动属于预期变化，希望复用该对象独立体素层，迁移到放置位置，供下一次抓取使用。
- 除本轮被搬运目标以外，其他物体、盒子或环境发生变化，必须移动到观测位姿，再重建场景。本条覆盖上一轮“看清其他对象的新位置即可原位更新”的建议。仍由 JEV 调用 skill；检测算法返回证据，不能自行调用运动或实施恢复。
- 身份关联必须说明算法和判断依据，并报告有实测依据的准确度。

待讨论的实现细化与已核对事实：

- 头部比较须验证相机内外参/采集配置一致。比较动作前基线和放置撤离后的帧；除各对象掩码重合、轮廓和像素位移外，使用同帧有效深度变化检查，覆盖未分割环境区域。机器人遮挡、无效深度及不可见区域不能支持“没变化”。本轮搬运对象可解释源区/目的区变化，但不能直接忽略整个盒子；已完成对象被后续落物推挤也属于本轮非目标变化。
- 普通视觉输出未发现超容差变化、发现非预期变化、不确定，以及范围和证据。OpenAI 在有限调用中分析相同前后图像及候选区域；它也可以返回不确定，不将其自报信心作为精确几何或空闲空间证明。若辅助后仍不能排除相关环境变化，建议由 JEV 选择重新观测；这是本轮建议，非已经实现的恢复程序。
- 代码确有独立语义物体体素层。`PerceptionMapper.build` 当前重置 capture 并重新构建，没有已验证的跨抓放物体层迁移接口。体素层只源于可见 RGBD，不是完整物体模型；迁移历史几何须保留原始测量来源和推导状态，不把历史空闲空间一并迁移为新自由空间。
- 当前 `runner.observe` 对 release_pending 使用 release TCP 变换持物点，再减去配置的释放高度来预测释放后位置；这不是物体最终落稳位姿。夹持相对变换还依赖未滑移假设。松爪后可能掉落、转动、滑动；把模型移到释放指令位置不能直接证明最终占据。建议以预测为初值，用现有动作后 RGBD 核对/修正目标局部占据；盒内不要求精确摆放，但下次碰撞场景必须反映实际占据。无法核对时不将预测升级为确认地图。
- 若其他物体/环境改变导致旧图失效，返回观测位姿之前，必须用原位当前深度更新观测运动涉及区域的碰撞证据；到位后再执行用户要求的场景重建。不能拿已知过期的图规划返回运动。
- 当前跨时刻 `associate` 按类别/颜色相同及可见点云质心距不超过 12 cm 筛候选；多候选时用 5 mm 邻域内双向表面重合各不低于 20% 筛选，唯一才接受，多对一/一对多报歧义。只有一个候选时不会强制执行上述表面重合校验。这些是算法阈值，不是准确率；当前没有经过标定的身份关联概率，也未完成多相同工件连续抓放的专项准确率验收。
- 建议关联 skill 对全部候选统一做一对一匹配，融合固定头部掩码证据、实测空间/表面证据、外观和本轮动作角色。输出候选数量、证据量、匹配代价/次优差距和明确的唯一支持/歧义/缺少观测状态；低代价仍需绝对证据门槛，不能仅凭第一名领先就认定可靠。相同工件交换等无法观察的身份变化保留未知。
- 准确度需用独立标注的连续观测序列评估，分开报告不同物体、相同工件、移动、遮挡和已完成目标等情况：已接受关联的正确率（含样本数和统计区间）、本可关联对象中的正确关联比例、拒绝/未知比例、ID 切换次数、误合并/误拆分次数。仿真身份真值仅可用于离线评分，不能进入控制决策。未标定前显示关联证据与质量等级，不显示编造的百分比。

### 后续补充：编号清单与建图区分、两种关联分别说明

用户要求继续保留前文，并补充：

- 盒内已放目标可能只有一个腕部相机可见，用户希望优先通过位姿变换复用目标独立体素，避免每次重新观测/构建局部几何。
- 任务目标从头部视角由近到远编号，编号从 1 开始；头部图像标注 ID，同时形成清单，明确已完成和未完成标记。
- 物体清单与碰撞场景是两个不同产物，不能将建立/更新清单等同于建图。
- 必须分别解释同一时刻跨相机的实例对应，以及不同时刻维持任务 ID 的对应。

本轮澄清与建议（讨论，未实现）：

- 12 cm 是现有跨时刻关联中旧观测/预测点云质心到当前候选质心的搜索门槛，不是不同物体间距的下限，也不是 SAM3 分割距离阈值。相距 5 cm 的两个物体可能同时成为一个旧 ID 的候选，因此要进一步区分，不应调成“物体必须相隔 12 cm”。
- 跨相机关联：同步 RGBD 中，各相机 SAM3 分别输出掩码，经深度和标定检验是否对应同一个当前物体，合并共同物体的可见几何，不要求三个相机都看见。跨时刻关联：将当前物体记录与历史清单一对一匹配，延续任务 ID、任务状态和历史。这两类错误、证据和准确率应分别记录。已有 12 cm/5 mm/20% 阈值说明只针对跨时刻路径。
- 建议首次编号按头部相机坐标下各目标可见深度支持的参考位置到相机原点距离升序；这是对“从头部看由近到远”的实现解释，不等于物体真实几何中心，也不等于执行臂 TCP 距离。近似等距时用图像从左到右作稳定次序。已分配的任务编号保持不变；完成后保留行并标记，不将剩余对象重编号。新发现目标追加未用编号，不复用已完成编号。对未出现在头部视野的目标，不声称已有头部掩码或该视角的完整清单。
- 初始编号次序与执行次序分开；前文的执行臂最近优先仍保留，除非用户另行指定按编号顺序抓取。相同工件对应关系彻底丢失时，仅对受影响未完成集合重新枚举并使用新编号，保留旧历史及未知对应关系。
- 清单保存 ID、描述、任务状态、位置及其测量/推导来源、当前可见性、关联状态；已完成、当前不可见和关联未知属于不同维度，不能因当前缺掩码而撤销已验证完成状态。碰撞场景保存桌面、容器、物体及其他障碍的几何、有效性和版本，按 ID 与清单关联。清单重关联不要求全量重建图，建图也不应重置清单或改变既有 ID。
- 目标层刚体变换可用于预测更新；不能由释放指令直接得到保证准确的最终落稳位姿。夹持稳定、无滑移是持物变换的假设；松爪后的下落、滚动、转动不由夹爪反馈唯一确定。现有 RGBD 可以提供少量核对或修正，不要求每次完整重建目标，也不要求三个相机共同看见。
- 盒内目标无法核对时，建议保存预测占据并明确标记未确认及假设。碰撞规划若要依赖它，需有经验证的误差范围/保守占据策略；不能随意加小裕量便声称覆盖全部可能位置。只有在该不确定性不影响下一动作已验证的相关区域时，才讨论复用继续；否则由 JEV 决定补充观测等动作。此为待讨论方案，不是已完成能力，也不是用历史体素生成隐藏深度。
