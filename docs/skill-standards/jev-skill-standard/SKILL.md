# JEV skill 规范

本规范用于开发和审查 JEV 的机器人 skills；不是机器人可调用的 skill，不加入运行时 skill_catalog。用户明确要求的原则适用于每一个 JEV skill：**内部执行稳定、有界的算法流程，外层 JEV 决定任务步骤及恢复。**

## 使用方法

1. 读取项目的实际技能目录、契约和执行分支。目录名或说明文件不证明能力已实现。
2. 按 [契约要求](references/contract.md) 写出目的、输入、前提、固定流程、证据、状态变化、失败和预算。每项都需要实际依据。
3. 涉及观察时，先按 [观测目的规范](references/observation.md) 区分场景、几何、动作结果、视角移动和图像语义分析，再决定复用帧、重新采集或移动。
4. 核对文档、contract、JEV 可见说明、参数选择和执行代码的一致性。以项目 `docs/jev-skills-guide.md` 为逐项说明入口：每次代码修改都须同步复核、更新受影响条目及索引/流程，并在其核对记录中说明变更；不影响 skill 的代码改动也记录核对范围和“skill 行为无变化”。每项写清目的/调用时机、输入/前提、固定算法、输出/状态、失败/边界；数值注明单位，不能用模糊措辞替代判据。文档修改不能代替实现；兼容入口和未接入定义必须明确标记，内部算法接口不能写成独立 skill。
5. 用具体状态演练正常、缺少证据、契约拒绝及服务失败路径；实现变更还需验证真实执行分支。报告实际通过项与未满足项，不笼统宣称全部符合。

文档引用的函数名、API、配置项或文件路径改变时，即使行为不变也须更新引用，不能仅添加核对记录。内部接口改名不新增 skill；新建、删除或重命名实际 skill 时须核对 Registry、contract、执行分支与手册索引的一致性。

## 必须遵守的边界

- JEV 在 skill 外选择步骤、目标、目的地、必要参数和恢复动作。skill 内不再询问 JEV 下一步做什么，也不由失败原因自动选择恢复。
- 稳定指接口、流程及结束条件稳定，不要求感知或随机优化每次结果完全相同。固定算法可包含明确的有限分支、候选搜索和数值迭代。
- 程序校验输入、契约、碰撞和预算；拒绝后返回证据，不暗中换成另一个 skill。预算耗尽不等于目标不存在或整个任务失败。
- 用户指定执行臂时保留该约束；提供视觉的相机可以位于另一条臂。物体由几个相机看到不能单独决定是否需要补观测。
- 使用实测 RGBD、自身反馈和明确标注的推导。历史身份、持物参考、模型推断与当前测量分开；隐藏环境真值不进入决策或碰撞几何。
- `unknown`、算法无解、动作失败和任务终止必须区分。VLM 的图像证据也可能未知，不生成隐藏深度或机器人动作。
- 每个结果必须可追溯到输入版本及证据；新帧、动作后的结果图、碰撞场景和历史身份不能混为同一个状态。
- 不为缩短提示而删掉关键约束、未知项或失败原因；运行时传递完整精简目录，具体算法细节留在文档及日志。

项目内规范的源文件是本目录。安装到 Codex 的副本应保持一致。项目专用的观测定义和现有技能差异见仓库 `docs/skill-specs/2026-10-13-observation/`；未实施的建议不覆盖当前代码事实。
