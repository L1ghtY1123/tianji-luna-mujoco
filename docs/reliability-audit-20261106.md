# Decisions、数据流与失败根因审计（2026-11-06）

本次先审计原始证据，再修改回放，并修复新实验发现的技能失败证据在 Graph/Decisions 边界丢失的问题。判断阈值、数值门槛和机器人动作流程未更改。原始结果、失败案例和历史版本均保留。

## 统计范围与方法

- 读取现存 68 份归档（2026-10-22 至 2026-11-05），共 1,457 次 Decisions HTTP 调用、4,652 个问题、1,453 个不同请求哈希。4 次 HTTP 503 没有有效判断。缓存复用不计为新的 HTTP 调用。
- 历史中 809 个请求包含多个问题，属于旧实现。最近 11 次正常入口实验共 349 次 HTTP 调用，全部每请求一题，没有 HTTP 错误。
- 对谓词统计 P(命题为真)：≥0.8 为 yes，≤0.2 为 no，中间为 unknown。0.02 通常是明确否定，不能称为“只有 2% 的判断信心”。
- 事实选择统计 choice confidence；明确选 unknown 与低于事实阈值分别记录。动作建议、抓姿算法前的选臂、数值求解前的 XY 建议及 CAD 检索候选单列，不冒充已验证事实。
- 当前归档有实际采用的 diagnostic_checks。较早归档缺少该字段时，只按上述规则重建，报告明确标记，不能倒推历史消费方一定采用相同规则。
- 不以未标注的高分回答计算准确率；不以不同代码版本的小样本计算稳定成功概率；子图逐层返回同一个失败只算一个根因。

审计原始文件：`data/runs/reliability-audit-20261106/archive.jsonl.gz`。逐题表：`answer-audit.json`。汇总及各技能执行分母：`confidence-summary.json`。可复算入口：同目录 `audit.py`。

### 高分不等于正确

- 实验 `118f00bdab634b7f828dabd9b0a4f6b0`：已移动输入 139 被否定为同一物体（0.02 / 0.16），随后登记成 140，旧 139 又阻断地图。根因包含把旧位置与移动后的当前位置并列比较，属于高置信度错误否定，不是低信心。后续输入已标明释放时序；最新旧样本中 158 搬动后保持同一 ID。
- 实验 `e5371ea72c1645be997fca2fc448b73b`：产物存在 0.95、包装消失 0.96；但下一步 C3→159 只有 0.64。产物登记只有加工回执和三张场景图，没有已定位的该产物参考掩码/裁图。不能把“确认出现一个产物”当作“这个候选已完成永久身份绑定”。
- 同一次实验另有蓝盒候选与黑色产物身份比较得到 0.71。该错误配对属于不确定，不应通过强迫提高概率变成已确认身份。
- 先前保存的产物提示词对照试验让正确配对降到 0.03，未部署。该结果进一步说明只改强调语句不能保证改善。

## 哪些故障最常终止任务

11 次正常入口实验有 1 次成功、10 次未完成。下表按每次实验的终止根因去重，而不是把一次失败经子图传播后的每个红节点重复相加。

| 根因组 | 终止次数 / 10 | 实验证据 |
|---|---:|---|
| 身份与实例连续性 | 3 | 第二输入未关联→空选择；移动物体分裂成新 ID→旧地图残留；产物首次关联 unknown |
| 开局 Responses 编译 | 2 | 不满足路径前提/修订改变任务；输出预算耗尽 |
| 碰撞几何/地图前提 | 2 | 容器 CAD 姿态导致支撑面不水平；没有全局基础场景就请求局部更新 |
| 抓取规划与恢复选择 | 2 | 当前臂候选耗尽，替代臂不可达或选择停止 |
| 物理执行 | 1 | 夹爪稳定等待超时 |

按技能实际被调用的条件分母统计：plan_grasp 2/10 失败；build_scene 4/25 缺证（其中同一次实验可以经历恢复）；execute_grasp 1/8 异常停止；identify_target 1/13 缺证。不能按这张技能表断言身份问题只有一次：身份错误还会以空选择、旧 ID 地图缺失等症状呈现。

prepare_unpack、vla_unpack、verify_unpack 各执行 4 次，全部通过；放置链条各执行 7 次，均通过。大量实验在到达这些阶段以前已停止，因而样本少，不能据此声称这些技能已经稳定。

19 次 Responses 均发生于开局（初稿与执行前修订），正式执行后为 0 次。3/11 首稿直接通过。校验记录包含 8 条路径前提错误、3 条同一源节点同一结果重复出边、1 条修订改变冻结任务，另外 1 次输出不完整。错误条数不等于失败实验数：多数修订后仍进入执行。后续版本已有图修订冻结、初次全局建图契约和 64k 输出预算；本报告不把已修过的历史失败声称为当前仍必现。

## 分层结论：已建立模块边界，尚未完全解耦

| 层/边界 | 实际实现 | 核对结论 |
|---|---|---|
| Graph | `core/graph.py`、`runtime/native_graph.py` | 解释器通过 invoke/judge/bindings 等回调执行，不直接导入物体清单或碰撞场景实现。控制图与物体 ID 区分。 |
| 时间记忆 | `object_memory.py`、`world_inventory.py` | 保存永久实例、可见性、历史与谱系；不导入 SpatialMemory、Graph 或 Decisions。 |
| 空间记忆 | `spatial_memory.py` | 保存测量、场景、失效与基础地图标志；不导入 ObjectMemory、Graph 或 Decisions。通过 ID 和生命周期输入关联。 |
| Decisions | `agent/decisions.py`、视觉判断入口 | 接收单题及只读证据投影，返回原始概率/置信度和判断；不直接修改 graph 或记忆。问题模板与动态主体/历史/图分支相结合。 |
| 执行协调 | `runtime/controller.py`、`runner.py`、`robot_skills/*` | 组合入口集中，但仍有共享 context/state 字典与多重继承，不能说已经完全隔离。 |

**尚存的具体耦合：**

1. `PolicyController._persist_inventory` 从 `task_progress.records` 复制 current_region、confirmed_observation_id、transport_status、visual_release、transfers、observed_support 后写入 ObjectMemory。虽然有 ObjectOperation 类型过滤，没有写入任务完成状态，但物理回执仍由任务账本产生/持有，再被投影回永久记忆。这不是独立物理回执驱动两个消费者的单一数据来源。
2. `PolicyTaskProgress` 继承 TaskProgress，仍保存观察位置、可见性、物理转移和加工谱系等副本。只读展示合并本身没问题；同一物理状态有多个写入位置则需要继续拆开。
3. `SpatialMemory.observe` 接收完整 observation 字典后内部转换 GeometryMeasurement；不是所有入口都只收严格类型。技能内部也通过共享 context 访问多个层。GraphSkillResult 和 DecisionQuery 只约束外部边界，不能替代内部数据所有权约束。
4. 当前 map 按已关联 ID 收录物体，移动又要求有效碰撞场景。身份/几何缺证发生在基础场景建立之前时，换位观测可能不合法。这属于实际运行前提的相互依赖，不能通过删除碰撞检查或称模块已经分层来解决。
5. 最新旧样本的产物身份缺证直接返回结束；只有部分抓取规划、来源补观测与放置核验安排了恢复。图合法不等于恢复覆盖充分。不能把另一次实验存在的分支算成这一张 graph 的能力。

### 数据应在什么时机传递

| 时机 | 生产者 → 消费者 | 数据与当前限制 |
|---|---|---|
| 开局 | 相机/记忆/技能目录 → Responses | 三张当前 RGB、深度统计及标定、历史实例摘要、契约。模型并非直接获得完整原始深度矩阵。 |
| 编译通过 | Responses → 执行器/登记器 | InitialPlan 分出 TaskSpec、Graph、EntityProposal；永久 ID 由登记器分配并绑定引用，初始提议不等于当前几何事实。 |
| 观测 | SAM3/RGBD/记忆证据 → Decisions | 当前候选、掩码轮廓、RGB、校准测量和带时序的历史。逐题身份确认后生成 ObjectObservation 与几何测量。 |
| 观测提交 | 执行层 → 时间/空间记忆 | ObjectMemory.observe 更新可见性与历史位置；SpatialMemory.observe 更新测量。未看到不删除，不改永久 ID。 |
| 动作影响场景 | 执行回执 → 空间记忆 | 失效受影响 ID 或发布带来源的预测几何；预测不是新观测。下一次规划检查新鲜度。 |
| 放置/加工核验 | Decisions + 物理回执 → 记忆/账本 | 核验结果和动作、采集、目标 ID 绑定。消费输入/创建产物保留谱系；当前转移回执仍经过任务账本，见上述耦合。 |
| 建图 | 执行层 → 空间记忆/算法 | CollisionUpdate、已确认的 ID、GeometryMeasurement、退役/失效清单；先全局基础地图，再允许局部更新。 |
| 失败恢复 | 技能结果 → graph router → Decisions → graph | last_failure、可用出边及剩余次数、当前前提；只选择已声明分支，不重新调用 Responses。 |

共享永久 ID、采集 ID 和有类型回执是必要的数据关联，不等于应删除的耦合。需要消除的是共享可变字典、重复可写状态、由任务进度反向充当物理事实，以及未经说明的前提依赖。

## 本次回放修复与验证

- 删除跨整个图共享侧边通道的长线布局。每行固定从左向右，正常连续路线用虚线折到下一行。
- 非连续边保留为带目标节点编号及用途的跳转连接，可点击定位；不丢节点、不删边、不改变后台 graph。
- 未走过的连接为灰色，实际转移有次数；只有实际失败/缺证转移着色，避免满屏备用失败边看起来像已失败。
- 节点编号只是阅读定位；技术 node ID 与参数在详情，实际调用次序与当时物体 ID 单独记录。
- 根任务结果、子图返回、单次节点结果分别显示。重复调用显示最近结果，详情保留历史失败和缺证次数。
- 新双物体实验暴露了累计视图的误导：第一件的绿色后续节点会掩盖第二件尚未执行的步骤。现在共享子图默认展示最近一次调用，可切换任一次或累计记录；按父调用的真实开始/结束事件划分，不按物体名称猜测，不改变 graph。
- 档案拓扑验证覆盖 3 次真实实验、198 个节点和 504 条边；每条边都有直接箭头或明确目标连接，节点无重叠。
- 浏览器检查覆盖最新旧样本的 3 个 scope：21/56、15/36、28/77 个 node/edge；未执行节点保留、跳转定位、SVG 完整导出、初稿状态隔离、无页面错误、无机器人/模型写请求。
- 重新运行冻结契约、全局基础地图、超时沿声明边返回的检查均通过。这些检查不能替代完整机器人实验。

### 已修复的证据丢失

`invoke` 曾先调用供界面展示的 public_summary，把超过 8 项的 attempts 压成 `{count, first}`；随后 outcome_state 又没有保留该字段。于是技能实际有完整的失败记录，Graph 中却只剩 `details: {}`。此外二次投影会丢弃已经产生的 failure_counts 和候选池计数。

现在执行适配器先从原始技能结果投影有意义的证据，不经过有损展示摘要。放置搜索保留尝试数、失败原因统计、搜索上界和可行性结论范围；Graph→Decisions 再次投影保持这些信息。失败报告正确归类为运动规划，并显示统计。

真实失败的冻结回归先复现证据丢失，再验证实际 invoke 适配器、GraphSkillResult 和二次投影都保留 12 次评估及 5/5/2 分布；通用抓取失败统计也验证重复投影不丢失。该修复未重跑物理动作，不能宣称 placement_no_candidate 本身已解决，更不能宣称成功率已达标。
