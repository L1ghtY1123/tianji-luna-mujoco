# Current task execution

At graph entry only the raw initial capture and Responses proposals exist. `observe_scene`, `confirm_inventory`, and `verify_task_completion` are explicit capabilities selected by the model graph. Initial and final evidence uncertainty can therefore reach graph recovery branches. Target loops read the confirmed inventory at entry. Completion proof is bound to both action epoch and ledger revision. See [inventory and observation evidence](inventory-and-observation-evidence.md) and [the live validation](observation-policy-verification-20261028.md).

Responses interprets the natural-language goal, constructs the entity inventory and authors the execution graph from the registered skill contracts. The runtime executes that graph and validates evidence and completion; it does not insert an unpack sequence or recovery motion. Decisions supplies bounded visual and semantic judgments. See [the skill guide](luna-skills-guide.md) for the current contracts.

The VLA input region is an invisible square configured through the UI. Both arms must reach the fixed starting joints in `resources/vla_unpack.json`. `prepare_unpack` plans, checks and executes the selected capability for both arms; `vla_unpack` rechecks both actual configurations before its instantaneous MuJoCo effect. The black output is randomly sampled inside the configured right tabletop region with table support and right-arm workspace checks. The sampled physical pose is excluded from the skill receipt and cannot establish a visual identity.

Current three-camera RGBD and Decisions must confirm the output and bind its independent ID. If occluded, the task graph determines the next explicit observation or recovery action. A verification skill does not secretly move either arm. Mapping uses observed inventory entities as TSDF/ESDF plus the measured table cuboid; CAD is reserved for MuJoCo scene authoring.

The default ordinary-obstacle hard clearance is 5mm. Soft activation distance, release height and timing are separate advanced settings. After stable gripper closure, the native lift is checked against the closed robot, environment, self-collision and joint constraints. The first lift has no carried-object attachment check. Only after lift and fresh holding verification is measured-surface attachment created for subsequent motion. The user's completion requirement is return to the task-start configurations of both arms; Responses must express the needed actions in its graph.

Physical experiment outcomes and remaining failures are recorded in [the validation ledger](superpowers/plans/2026-10-27-feedback-grasp-place.md). Unit tests and service health are not evidence of a completed grasp/place task.
