# 盒内任务范围与 skill 执行边界修正

问题记录：`86b41d3275bf45a9bd878752bbae875d`，指令“把盒子中的物体拿到桌面黄色区域”。首次 JEV 正确选择 box_table，但将红、绿、黑三个实例都标成 required。只有绿色实例具有唯一的实测盒底来源关系。绿色完成后错误清单仍包含红、黑，导致红色也被搬运；最终 choose_skill 因 `jev_input_budget_exceeded` 停止。此次最终错误不是显存不足。

## 修改

- 盒源路线的 required 参数和目标绑定都校验实测来源：沿用 original_source_bin 的唯一盒子、可见点 XY 重叠至少 90% 门槛。这个门槛不是身份正确概率，也不是物体间距。没有唯一证据的实例只能由 JEV 判 excluded/unknown，程序不自动把 unknown 排除。
- 外层 JEV 获得由可见中心、实测盒底多边形计算的平面分离距离，用于判断明显在盒外的物体。未知完整边界仍明确标注；未使用仿真物体位置、颜色或 ID 真值。
- 清单校验整批通过后才写入，不允许部分应用错误回答。已确定的初始来源保存在 initial_source，两段搬运不会因中转到桌面而失去任务身份。桌面障碍继续进入碰撞场景。
- 所有 skill 先完成外层参数决策，再发 skill_start、执行固定流程、发 skill_complete。参数失败记录 executed=false，不发该技能的开始事件；参数耗时不计入算法耗时。build_scene 的算法本身原本就没有调用 JEV，此次修正的是 runner 的真实调用与日志边界。
- 最新 assess_task 输出中的清单与当前清单完全相同时，JEV 输入改用引用；不同历史清单仍保留。原失败输入估算从 24,228 降至 21,415，完整技能目录保留。
