# Responses 原图与重复仿真验收

本次验收从 2026-11-03 持续到 11-04。每次完整任务都重新调用一次初始 GPT-6 Luna Responses；没有加载成功实验的 graph，没有运行中重编排，也没有由 runtime 修补节点或边。下列失败保留在实验回放和统计中。不同版本的开发尝试不能合并成最终版本的稳定成功率。

## 验收依据

每次执行检查实际 API 返回的原始 graph、永久 ID 绑定后的初始 skill_program、最终 policy_graph，以及每个实际执行的 node/edge。允许的绑定仅为候选引用换成永久实例 ID；不改变拓扑、技能、参数含义或 router 条件。执行期间原图不变，所有实际路线都属于初始模型图。

成功还需要独立物理验收：实际黑色 CAD 网格位于右侧盒内，完成数量与指令相符，输入和产物谱系完整，夹爪不持物，最终双臂 observation 姿态通过实际关节反馈。MuJoCo 真值仅用于事后验收，不传给模型、感知或规划。

“不拆包，只把粉色物体放到指定区域”是对照任务：检查完整 graph（包括未执行分支）没有 prepare_unpack/vla_unpack/verify_unpack，实际粉色包装未改变，没有加工谱系，实际网格落在配置区域内。

## 已定位并修改

1. 抓取候选池的拒绝证据消费方只接受旧场景标记，错误地拒绝 CAD/OBB/cuboid 场景产生的完整双臂碰撞证据。修正后允许技能按原有 256→512→1000 的有界预算继续搜索；缺少场景绑定、检查数或完整碰撞证据仍拒绝。没有改变碰撞门槛、SDK 或离线 CAD 抓取池。
2. 来源身份问题曾把识别来源与全部输入的容纳证据混在一起。现在只核对原始指令指定哪个当前实体；成员资格、支撑关系和来源完整性另行判断。冻结失败请求对照：原问题 0.72，新问题对正确来源 1.00，对错误来源 0.04。没有修改阈值。
3. 图描述明确 source 节点决定 edge outcome，禁止跨 scope 引用，建议按用途命名而不是复制数字编号。子图继承调用时事实并返回改变后的事实，不能把第二件物体当成重新获得 initial_facts。非法图仍在动作前拒绝，没有自动修图。
4. 共享子图的物理动作防重播最终改为“输入永久 ID + 子图调用节点路径 + 动作节点 ID”。不同输入、同一输入的不同声明调用处都能复用；循环重播同一调用仍拒绝。探针先复现错误，再验证不同输入、不同调用和循环拦截。完整双物体试验中，同一输入的粉色搬运和黑色产物搬运也实际复用了同一共享 body。
5. prepare_unpack 描述明确消费已验证的工作区释放回执；重新绑定目标或目的地会清除该转移确认，不能靠 prepare_unpack 重新制造回执。
6. 中等推理强度仍连续生成非法双物体长图。对冻结的失败请求仅改 high/32000 输出预算，完整 schema、拓扑、技能前提和完成证明校验通过，耗时 269.7 秒。随后正式初始 Responses 改 high，默认超时 600 秒；Decisions 超时、阈值及调用方式不变。仍为每任务一次初始编排。
7. 双物体 high 实验完成第一件后，fresh observe_scene 成功，但第二件在三个当前视图中均不可用；identify_target 返回 observed_instance_missing_or_ambiguous。已检查三幅实际图像，未凭概率推断遮挡。契约现明确：observed=true 仅表示本次采集分析完成，不代表每个输入可见；两个腕部相机会随动作改变方向，固定相机也可能被手臂遮挡。Responses 需自行选择所需观测姿态和合法恢复路径，runtime 不强插回位。

推理强度依据：[GPT-6 Luna 模型说明](https://developers.openai.com/api/docs/models/gpt-6-luna)、[Reasoning 指南](https://developers.openai.com/api/docs/guides/reasoning)。提高预算只是本轮试验变量，不是任意长图必然有效的保证。

后续试验又定位到恢复证据缺陷：图中 router 对第二件可见性缺口给出 0.96，经过 build_scene 后，移动技能却把成功建图当作 failed_result。现改为原始 last_failure，并记录失败技能及实际参数。仅修正上下文仍不足；问题中的泛称“失败操作主体”也需改为明确的永久 ID 与外观。冻结相同图片的实际新问题得到遮挡 0.83；清楚可见的黑色工件负对照得到不可见 0、裁剪 0、遮挡 0.01。此为受控问题对照，不计作完整任务成功。

## 限制

本轮是带修复的开发验证，样本少，场景范围有限；不证明任意语言任务或所有恢复分支的成功率。不得把中途终止但已交付一件的双物体任务计为成功，也不得把编排失败从分母删除。

最终完成 17 次任务尝试：单件拆包 5/5，通过“不拆包只搬运”对照 1/1，双件拆包 0/11。双件失败中 7 次在动作前编排校验拒绝，4 次在执行中停止。修复后的可见性问题已通过冻结图像正负对照，但没有完成一轮双件端到端成功，不能宣称多物体稳定。

Python 全源语法、21 个契约 JSON、Ruff F 和 diff 空白检查通过。共享调用路径与同次动作防重播、恢复原失败和显式主体问题都有针对性对照。官方 SDK、碰撞门槛和事实阈值未修改。本轮没有新增前端代码，前端构建和浏览器回放验证见前一阶段报告。

## 执行前图修订验证

静态校验现在汇总各节点的参数错误及可检查的独立数据流路径。缺少前提的路径停止推演，其他路径继续检查。结构错误仍按可确定的范围报告。Responses 收到完整被拒图和已发现错误，并需检查相关调用点及下游路径。首次通过即停止修订，最多一次初稿和两次修订。

离线控制流探针通过首轮成功、一次修订成功、第二次修订成功、耗尽上限停止、根任务或清单改动拒绝、网络及非图错误停止、并发初始调用互斥和完整长图归档。两条独立路径的四个变量/前提错误在一次反馈中全部出现。12 张历史图回归中，原来通过校验的 5 张仍通过，原来非法的 7 张仍被拒绝。证据位于 data/runs/graph-revision-probe.json 和 graph-revision-historical-validation.json。

真实模型对照复用历史 ad64f180929f4d798516b32b595171d4 的三相机、技能契约及完整被拒提议。校验反馈 x_select_product 与 x_retry_product 两处提前引用 $product，GPT-6 Luna Responses 一次修订通过，耗时 82.521 秒，输出 74 个节点，原清单和根任务逐项一致。正常 compile/discover 入口采用模型原图，未执行机器人动作。初稿为归档回放，真实新调用只有一次修订，不能计作新的完整任务成功。证据位于 Ubuntu data/runs/graph-revision-live-corrected/。

首次对照工具误用了尚未注册参数 schema 的裸 Registry，产生无关参数错误，该尝试已终止并作废。随后使用归档完整技能契约完成上述对照。生产入口由 PolicyController 注册完整参数 schema。

随后通过正常网页 API 启动双物体任务 a963983bc80345ceadbdf9f49975c156。首轮 Responses 158.546 秒生成 80 个节点、7 个子图、4 个 router，直接通过校验，修订次数为零。任务总时间 365.34 秒，其余阶段 206.80 秒。第一件完成拆包与交付，第二件补观测后仍在 identify_target 返回 observed_instance_missing_or_ambiguous，完整结果失败。独立物理验收确认右盒内一个黑件，与 1/2 完成账本一致。Responses 原图来源、绑定后的图保持不变、实际边均已声明及模型调用发生在任务技能前的审计全部通过。证据位于 data/runs/graph-revision-20261104-r01*.json。
