# 三相机可见点云抓放：分阶段 attachment 修订

本版纳入用户最新修正：grasp 使用张开夹爪模型、不做 attachment，接近与 lift 保持现有高级设置，不强制原路返回，按任务假设不新增 lift 携物碰撞处理；grasp 结束阶段建立实际闭合夹爪模型及持久 attachment，使独立 place 一开始就能使用。放置 Z 是物体离盒底的高度，默认 1 cm，默认保持物体初始姿态。仿真 RGBD 不加噪声。此前严格向下连通去浮岛算法取消，改为评估 Open3D 的成熟过滤工具。本版继续取消物体补全、箱腔拟合和容量检查。当前交付是修订实施方案，不能视为功能已经完成。

## 已确认的目标与边界

- 输入“抓取某颜色的某物体到某颜色的盒子里”，支持单臂 grasp、place、grasp_and_place；本阶段不换手。
- 保持水平双臂初始姿态。头部优先检查目标，腕视角不足时先用头部 RGBD 建图，再避障移动到观察位姿，随后重新观察。
- 只使用三个 RGBD 的实际可见环境点云。不要物体 CAD、形状补全、规则体尺寸推断、填充物体包围盒或完整体积包含测试。
- 默认物体能够放入用户指定盒子，不实施容量检查；盒子只做识别、可见放置参照点定位和点云碰撞，不拟合盒长宽高、姿态或内腔模型。
- 机器人 FK、标定、关节和夹爪实际可获得的反馈允许使用；物体/盒子的仿真真值、接触对象 ID 和编辑器尺寸不能进入控制链。
- 沿用三相机已接入标定，核对 RGB/公制深度与坐标约定，腕相机外参随同一快照的实际关节反馈/FK 更新。仿真渲染可使用世界真值生成图像，输出给控制链的环境证据仅为 RGBD。
- 沿用开口长方形物料盒编辑器，颜色/位置/尺寸仅用于构建仿真场景，底与四壁具备物理碰撞；规划端只通过 RGBD 识别和建立盒子碰撞。
- 桌面支撑平面与现有桌面 cuboid 仍从 RGBD 建立，用于桌面碰撞、裁剪和释放高度参照。物体和盒子不做实体补全。place 碰撞能力只覆盖观测表面的离散近似；grasp 的 lift 不进行携物几何检查，分别记录其验证范围。

## 观察与任务流程

1. initial：水平双臂静止，同一时刻采集三路 RGBD 及关节反馈。先在头部 SAM3 结果中确认当前任务需要的源物体/盒子；未找到直接结束，服务故障与无目标区分。
2. 检查腕相机的目标观测及场景覆盖。不足时发布仅使用实际头部数据的 observation_motion 场景，源物体、盒子和其他障碍都保留。
3. 两臂空手时按 A→B 避障到观察位姿；每次使用另一臂的实际状态。观察位姿用模型、标定和实际 RGBD 验证后保存，不直接套用 READY。若 A 到位后 B 路径证据失效，在该指定节点观察一次，再规划 B。
4. fine：重新采集三路，融合有效点云，关联原目标并更新场景；旧腕相机外参、场景和计划失效。最多一次固定观察位姿分支，仍缺必要数据则停止。
5. 生成抓姿与三种规划之一。抓取后在指定提升检查点 post_grasp 观察；放置后在短撤离检查点 post_place 观察。独立 place 开始时另有静止的 standalone_place 观察。

RGBD 不持续运行。每次观察记录用途、相机、时间和版本；同一节点允许有间隔的两次快照用于稳定性验证。JEV 保留完整技能目录与 stop，程序检查前置条件，不把预计效果写为事实。

## 可见点云与放置参照点

SAM3 负责 RGB 实例及颜色绑定，深度负责三维表面。实例保存 visible_points_world、visible_centroid_world、相机/像素来源与置信度；这些名称不能暗示完整物体的中心、尺寸或 CAD 位姿。GraspGen 直接使用测得目标点云。

grasp 闭爪后只记录夹爪反馈和暂定持物状态，不激活 attachment，也不更新该运动阶段的张开碰撞模型。lift 完成后通过指定 post_grasp 观察确认持物；在 grasp 成功返回之前，将目标实测可见点转换到当时实际 TCP 局部坐标，更新闭合夹爪模型并建立 attachment。该绑定属于持物会话，独立 grasp 结束后仍保留，plan_place 入口直接读取和校验，不到 place 才首次创建。点集体素降采样后只为有测量的表面体素建立小球，球半径覆盖体素离散化和设定测量余量。禁止遍历整个 AABB 填球；计算用的包围范围不等于实体占据。球预算不足时调整表面采样并报告分辨率，不能静默丢弃超额表面。

当前锁定 cuRobo 的标准 attachment 通过 link-local spheres 工作。世界环境仍采用 TSDF/ESDF；被持物体从静态层排除后，以随 TCP 运动的表面球参与查询。两个分支都来源于实测点云，不必先将整个 ESDF 转换为球；ESDF 非零距离体素不能被误当作物体表面。

盒子通过颜色/语义识别，从可见放置区域定位世界坐标 XY，保留像素和深度来源。用户设置的 Z 明确定义为物体底部距盒子内底面的距离 release_height_m，而非世界绝对 Z 或 TCP 的高度。无需盒子六维位姿或尺寸。将该参照、固定放置偏移及 TCP 局部目标可见点的关系组合为 native plan_place 的 TCP 目标；默认恢复抓取闭合时的 TCP 世界朝向，以在无滑动假设下保持物体初始姿态，不要求估计物体绝对旋转，也不做物体轴对齐和四分之一转容量搜索。

放置采用物体最低处距盒内底面名义 0.01 m 的释放目标，不强制贴底或力控接触。1 cm 不是 TCP 或球心距盒底。若物体原先支撑于水平桌面、闭合后未滑动、放置保持抓取时的姿态，可用 `z_tcp_release = z_tcp_at_grasp + z_box_floor - z_table + 0.01`，无需估计完整物体形状。桌面、盒底高度来自实际 RGBD，抓取 TCP 来自自身反馈；抓取支撑关系是明确的任务假设。姿态改变、支撑关系不成立或滑动时，不再声称该公式给出真实底面高度；不可静默以可见最低点冒充底面。

可见箱壁、底面仍作为点云障碍。1 cm 目标还必须与球半径、感知误差和 hard clearance 一起检查；发生冲突时报告 release_clearance_conflict，不能静默提高释放高度或关闭盒底碰撞。默认能装下不代表任何夹爪姿态/路径都无碰撞，轨迹、开爪和撤离检查保留。若无有效盒底参照深度，报告无法定位放置点，不读取仿真盒中心补位。

此处的实测表面碰撞范围不要求整个放置轨迹的每个球都完整可见。放置接近、放置、开爪和撤离分别记录实际命令的碰撞/边界检查及深度覆盖状态：遮挡区域仍为 unknown，不能据此宣称自由，也不将 unknown 本身当作碰撞。实际 world/self/peer/attachment、关节边界和开爪扫掠失败必须拒绝执行。观察和抓取的既有覆盖门槛保持不变。

verify_place 检查实际开爪、源物体与夹爪分离，以及观察支持的盒内位置关系；不再检查完整物体体积是否包含于估计箱腔。目标完全遮挡而无法确认时返回 unknown，不用真值宣布成功。

## 场景去飞点：Open3D 过滤建议

取消此前自定义严格下降图和逐点找桌面根的实现要求。现有小连通簇过滤不代表所有密集浮岛已经解决；需先对照实际原始深度、融合点云、占据体素和 ESDF 显示确定伪影来源。MuJoCo RGBD 禁止主动加噪声，新增去噪默认关闭，真实 RGBD 样本用于评估过滤效果。

Open3D 已有 remove_statistical_outlier（邻居平均距离的统计过滤）、remove_radius_outlier（指定半径内邻居数量过滤）和 cluster_dbscan（密度聚类）。前两者适合稀疏离群点；密集浮岛可能通过过滤，DBSCAN 也可能把它识别为正常点簇。不能声称任一接口会自动识别物理上没有支撑的噪声。

最简建议为：保留测量来源的降采样 → 保守统计过滤；半径过滤作为可选替代，不默认叠加多个强过滤。DBSCAN 初期只用于剩余点簇的诊断和预览，不将小点簇、label=-1 或不连桌面直接当作必删障碍。目标、盒壁、细薄边缘和稀疏远处障碍须作为误删检查重点；不采用仅保留最大簇的规则。

过滤在测得点云上、目标层排除和 ESDF 距离膨胀之前进行，不能把 ESDF 距离体素当成噪声点。保留原始索引、相机/像素/实例来源、保留与剔除掩码，提供原始/过滤/剔除叠层。被删深度不生成穿透首回波的自由射线。只在已有观察节点处理，参数由实际点间距和数据验证，不照抄文档演示半径。运行时延和 DBSCAN 内存占用需实测；此建议不是已完成的去浮岛保证。

## grasp 与 place 的阶段边界

plan_grasp 和其运动阶段不使用 attachment，规划碰撞几何固定为张开夹爪。approach/lift 的坐标系、轴、偏移保持现有高级设置，默认 approach 为工具坐标轴、lift 为世界坐标轴。不要求两段同轴或同路径，不新增反向轨迹功能。用户已明确按任务假设认为 lift 可行，不新增携物 lift 检查或复杂的桌面接触离开过程；现有机械臂规划流程保留。

观察运动保留所选目标的碰撞；grasp 规划才按 RGBD 实例分割从该请求的世界碰撞层排除目标。桌面、盒子、其他物体以及机器人各连杆/夹爪碰撞球保留，不把目标排除扩大成整手碰撞豁免。

grasp 结束阶段在 post_grasp 观察确认持物后更新实际闭合夹爪碰撞球、排除原目标静态层并建立 attachment，再返回 grasp 成功。绑定持续存在，独立 place 与组合任务读取同一持物状态；place 不负责首次 attach。若几何准备失败，保留已完成抓取的动作事实及持物状态并报告，不虚报 place-ready 或自动松爪。place 校验携物起点和后续路径；若冲突，返回规划失败。

## 夹爪模型更新与性能

保留各 link 原有局部碰撞球。grasp 运动使用用户指定的固定张开规划模型；grasp 结束建立 attachment 时，通过实际驱动关节、mimic 关系和 FK 更新球位置，不能默认闭到底。place 从这个实际闭爪模型开始，开爪扫掠及撤离仍需检查。

更新位置/锁定关节参数与销毁、重建整个规划器是不同成本。当前 carrying_scope 在进入/退出时清缓存，应改造为可复用的模型和数据更新。优先使用锁定 SDK 的公开更新接口、固定拓扑及预分配 attachment 容量；核对 IK、轨迹优化、graph 与最终检查器得到同一夹爪状态。

若该版本不能安全热更新某配置，使用有明确配置键和内存上限的缓存后端，在实际状态转换时一次构建；不能为了缓存复用随意量化夹爪反馈。对初次构建、预热、反馈更新、球上传、attach/detach、过滤建图及规划分别计时，测冷启动与重复运行。没有实测数据前不承诺毫秒级或“完全无影响”。

已核对的固定容量 attachment 更新有公开接口；detach 恢复 reference spheres，因此缓存模板必须使用未激活的 attachment 槽，而不是用本次物体的正半径球作为 reference。锁定关节更新必须保持张量维度并覆盖相关 IK、优化器、graph 和检查器，不能只更新 MotionPlanner 暴露的一个 kinematics 对象便声称全部同步。

## 抓放与生命周期

plan_grasp 规划接近、抓取和按现有高级设置配置的不带 attachment 的 lift；执行结束时建立绑定。plan_place 对实际 held 且 attached 状态规划持物移动、释放和撤离；plan_grasp_and_place 组织同一只手的分阶段抓放。抓前可进行假设状态下的目的地可达性/候选预检，不能称为实际闭爪模型下已完成正式 place 规划；grasp 结束后以实际持物绑定正式规划/更新剩余 place。移除容量/箱腔检查，保留该阶段声明范围内的路径、碰撞、开爪与撤离检查。

闭爪合理反馈产生 provisional，指定提升观察产生 held/not_held/unknown。开爪到位产生 release_pending，取消正常携带绑定；短撤离仍可用同一可见点集校核“仍随手”与“已留在放置区域”两种假设，不生成完整物体实体。撤离后观察确认分离及落箱位置关系，才结束持物会话。所有状态与规划假设清楚区分；unknown 不自动松爪/重抓。

持物验证只使用实际可获得的夹爪反馈和指定节点 RGBD，结合抓前目标与夹爪附近可见点集判断。没有连续相机追踪，也不以仿真接触或隐藏物体位姿补证。独立 place 使用当前持物绑定，在 standalone_place 节点更新观察，不重复两臂空手移动到观察位姿的流程。

单独 grasp 返回、规划请求退出或 place 规划失败不销毁持物绑定。开爪释放后解除 attachment；取消运动时先停止并使旧计划失效，不能因为取消或异常便把仍持物状态清成空手。仿真 Reset 按实际重置结果清理持物绑定与缓存身份。MuJoCo 保持接触、摩擦与重力，不焊接或瞬移目标。

## 验收与参考

验收重点：无真值泄漏；头部缺目标零运动；腕视角不足补观察；grasp 保留 approach/lift 高级设置并在运动结束前不激活 attachment；grasp 成功返回后绑定持续可用，place 使用实际闭爪与实测表面球；1 cm 相对释放高度和初始姿态来源可审计；盒子无拟合和容量判断；仿真 RGBD 无添加噪声；可选 Open3D 过滤不制造自由空间、不把密集浮岛检测夸大为已解决；缓存没有陈旧状态；三种任务实际 RGBD/SAM3/GraspGen/cuRobo/MuJoCo 物理闭环成功。

算法参考仅说明能力，不替代本项目实现验收：[Open3D 离群点过滤](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud_outlier_removal.html)、[Open3D DBSCAN](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html#dbscan-clustering)、[锁定 cuRobo AttachmentManager](https://github.com/NVlabs/curobo/blob/8e734f3ced1df898990bcd92de40abce475907db/curobo/_src/collision/attachment_manager.py)。
