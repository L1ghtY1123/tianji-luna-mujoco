# 三相机无特权抓放：修订设计

本版已被 [第二次审核后的可见点云设计](2026-10-09-visible-cloud-grasp-place-design.md) 取代。保留以下内容作历史记录，不再执行其中的物体补全、箱腔拟合和容量检查要求。

状态：2026-10-09 根据用户最新讨论整理的执行方案；本文件不代表功能已验收。与旧版设计冲突时，以本修订及用户后续指令为准。tianji_base 和 tianji-jev 仅作为算法接口、标定和历史实现参考，不作为必须复制的架构。

## 目标与范围

输入“抓取某颜色的某物体到某颜色的盒子里”，由一个机械臂完成抓取、提升、运输、放置、释放与验证。保留独立抓取和已持物放置。第一阶段不包含中途换手。

环境信息只来自头部和双腕 RGBD。初始姿态保持当前双臂水平姿态，不能通过改变启动姿态掩盖初始观察问题。RGBD 在显式观察节点采集；不依赖持续视频跟踪。

## 信息边界

- 允许：RGB、注册米制深度、相机内外参、捕获时间、机器人关节与夹爪可实际获得的反馈、机器人 URDF/碰撞模型及 FK。
- 禁止控制链读取：MuJoCo 物体位置/姿态/尺寸/颜色/ID、环境分割 ID、接触对象 ID、物体速度、场景编辑器对象清单及由它们生成的完整点云。
- 渲染器、场景编辑器、Reset 与独立评测可以使用真值；它们的对象元数据不得进入 JEV、规划器、执行条件或成功判定。
- 标定和机器人模型是可在真机获得的先验。环境 CAD/尺寸库只有在明确作为真机同样可用的资料时才允许使用；当前方案不依赖物体 CAD。
- 日志、错误详情、缓存与 recent_results 同样受边界限制。通过替换元数据而保持传感器输入不变的测试验证决策独立性。

## 三相机与初始观察

相机 1 为右腕 B，2 为左腕 A，3 为头部。一次观察冻结同一物理时刻的三路数据及机器人反馈；深度对齐 RGB，保留有效像素、内参及当时的相机外参。机器人自身从环境点云中剔除，但其规划碰撞模型始终保留。

1. 水平双臂静止，执行 initial 观察。SAM3 先在头部 RGB 中识别请求的源物体与目标容器；颜色来自图像。抓取任务只要求源物体，放置任务只要求目的地和既有持物证据，抓放任务要求二者。
2. 头部无请求目标立即返回明确错误，不进行观察运动。语义服务故障与“未找到”分别报告。多个无法消歧的同类同色实例不自动换目标。
3. 检查两腕有效目标观测和场景几何覆盖。视角不足时，用头部 RGBD 建立 observation_motion 场景，包含源物体、目标盒、桌面和其他观测障碍。
4. 两臂空手时，按 A→B 顺序规划并移动到观察关节位姿；每次规划使用另一臂当前反馈。已满足配置目标的臂跳过运动。观测运动不使用排除目标的抓取场景。若 A 移动后 B 的路径所依赖的场景证据不再有效，在 A 到位这一明确检查点追加一次观察并更新场景，再规划 B。
5. 到位后显式执行 fine 观察，重新融合有效视角、关联源物体与容器，并更新场景。旧相机外参、场景和轨迹失效。只尝试一次固定观察位姿分支；仍不足则说明具体原因并停止。

三台相机都参与采集，但不要求每台同时识别源物体和盒子。是否可以继续由目标几何、夹持区域、盒内放置区域及路径环境的证据决定；空掩码不能伪造点云，也不能因一个无关视角无目标而丢弃其他有效深度。

观察位姿不直接复制 READY。实施时用机器人模型、标定和 RGBD 场景在仿真中求取并验证一组 A/B 固定姿态，检查目标视角、关节限位、双臂互碰、开爪几何和从水平姿态出发的路径，然后保存有版本的观察配置。初始头部覆盖桌面是需要验证的布置条件。不能把“所有机器人碰撞球均能投影进一张图”作为环境覆盖的替代条件；必须识别真正需要环境证据的新扫掠空间。确实未观测的环境空间不得自动标记为空闲，也不能用膨胀球的初始占据证明其周围空气安全。

## 几何、抓姿与身份关联

GraspGen 使用测得的源物体局部点云，抓姿经相机外参和既有工具变换得到世界 TCP 目标。无需先恢复完整 CAD 六维物体位姿。

数据分为 measured_points、estimated_shape 和 coverage。点云的 PCA/包围盒坐标系只是几何参考系，不称为真实物体位姿。第一阶段沿用任务中已有的规则刚体类别：方块、长方体、球、圆柱；尺寸由观测估计，重力支撑和规则形状作为显式先验。拟合必须记录残差、覆盖和不确定范围；不能用固定的几毫米膨胀替代对任意隐藏几何的约束。先验不适用或完整范围无法合理约束时，补观察后仍不足就停止。

物料盒由 RGBD 识别为开口长方形容器，估计内壁、底面和可用腔体。只在有几何支持的内腔区域产生放置候选，按持物包络和余量检查可容纳性。不能直接使用编辑器尺寸。

身份关联只在离散观察之间执行，结合语义、颜色、点云几何和合理运动范围。对称物体使用相应等价几何，不用不稳定的 PCA 朝向变化直接判定滑落。观测编号不等于实体身份；无法唯一关联时返回 ambiguous/unknown。

## 三种规划入口

| 入口 | 内容 | 前提 |
| --- | --- | --- |
| plan_grasp | 接近、抓取和携物提升 | 已识别源物体、有效场景和抓姿 |
| plan_place | 持物接近、下放、释放所需开爪空间和撤离 | 本会话已验证持物、已识别容器 |
| plan_grasp_and_place | 对同一抓姿预检上述完整同臂任务 | 源物体和容器均有有效观测 |

三个入口共享 GraspGen/cuRobo 适配、碰撞检查和参数。组合入口按真实抓姿候选顺序检验携物提升、放置、开爪和撤离；某个抓姿能抓但不能放，继续下一个候选。全程无可行候选时不开始抓取。已得到组合预检不意味着在新观察后可以继续使用旧轨迹，实际持物几何或场景变化后重新检查并必要时重规划剩余部分。

保留 observe、build_scene、move_to_observe、目标选择、执行与验证等基础技能。JEV 仍面对完整技能目录和 stop，程序校验真实前置条件；不能用规划预期结果代替已经发生的事实。此次新增的是第三个规划入口，不把所有功能硬塞进三个巨型技能。

## 碰撞与 attachment

全部机器人、夹爪和腕相机碰撞球保留。空手接近使用张开夹爪模型；开闭动作检查整个扫掠；携物规划使用实际闭合反馈对应的夹爪几何，或经验证覆盖该状态的包络。不能假定全开模型一定覆盖所有闭合位置。

抓取规划按选中源物体层允许接触，其他障碍继续参与碰撞；观察运动场景始终包含源物体。携物时不在原位置重复保留同一个静态物体，而把其估计几何转换到 TCP 局部坐标，并经 cuRobo attachment 参与优化和轨迹检查。物体与实际夹持指垫的必要接触可豁免；不能豁免整个夹爪、机械臂、另一臂或容器。球近似误报通过校准包络处理，不通过扩大忽略列表掩盖。

盒子四壁和底板一直保留。离桌与最终下放仅允许明确的物体—支撑面接触过渡，限制方向、深度和阶段；不得整体禁用桌面或盒底来得到路径。夹爪打开所需空间和撤离路径在抓取之前纳入组合预检。

attachment 只改变规划模型，不使用 MuJoCo weld、物体瞬移或强制跟随。MuJoCo 中物体仍靠真实接触、摩擦和重力运动。

## 持物、释放和观察节点

| 时刻 | 状态与行为 |
| --- | --- |
| 抓取前 | initial/fine 观察保存目标点云和抓取前基线，尚未实际 attach；预检 attachment 仅在本次求解作用域存在 |
| 闭爪完成 | 检查真实可获得的开口和状态；明显空闭/故障停止，否则建立 provisional 持物几何。它是避障假设，不是抓取成功 |
| 有限提升后 | 到指定检查位置执行 post_grasp 观察；结合目标在夹持区域、抬离桌面、原区域变化和夹爪反馈判定 held/not_held/unknown |
| 抓取已确认 | 固定实际持物参考，保持 attachment；基于该次观测更新场景并检查/重规划剩余放置 |
| 到达放置位 | 检查开爪扫掠后打开，确认实际到位；状态为 release_pending，不能仅凭命令成功宣布释放成功 |
| 短撤离与检查 | 采用下述两假设检查的短撤离，到预先规划的可见检查点执行 post_place 观察 |
| 放置确认 | 验证目标在箱内、与夹爪分离并有稳定支撑；解除持物会话，以观测几何更新静态场景 |

provisional 阶段的同一段有限提升同时检查“已经抓住”与“源物体仍留在原处”两种场景，后者保留静态源物体并按阶段允许必要手指接触。不能仅凭闭爪反馈把静态源物体永久删除。

释放后不能要求被手遮挡的物体在撤离前已经完成视觉验证。放置候选优先接近测得支持面，限定释放高度，避免把高处自由落体作为默认放置。开爪到位后，操作状态进入 release_pending，临时静态障碍保守覆盖最后估计持物位置到支持面之间的可能落下范围，明确标注为推断；不能只保留最终落点包络。短撤离同时检查两个假设：物体处于该静态范围，以及物体意外仍随工具运动。后者只保留为规划检查假设，不作为“仍然持有”的事实。两者均通过才允许一次低速短撤离；开爪异常、已知未释放、无法约束滑移/旋转范围或无法找到同时可行的短撤离则停止。post_place 观察后才能确认释放/放置成功并结束该不确定状态。

初始、调整视角后、提升后和释放后撤离到检查点，是默认观察节点。已完成抓取后另起放置任务，需要在可观察的静止位置重新验证最近持物状态和目标盒；若现姿态无法提供证据，本阶段返回 unknown，不把空手观察动作套用于持物臂。执行模块不能暗中在任意位置反复拍照。为判断稳定可在同一观察节点获取两次有时间间隔的快照；它仍是有边界的观察动作。

单次视觉观察不能证明物体在一段运动中持续跟随。若启用跟随验证，必须有两个显式观察节点及其间的已知 TCP 运动；默认不把它作为唯一持物依据。运动中只使用机器人本身可获得的反馈，最近一次视觉确认需保留时间。故障/unknown 时不自动松爪，不自动重抓，不把逻辑持物清空等同于物理释放。

## 设置、展示与验收

高级设置分为共享规划、观察位姿/等待、抓取、放置与感知余量；沿用 native plan_place 的实际支持字段，抓放组合共用参数，避免两套相互矛盾的设置。观察姿态明确显示 A/B 七关节与角度单位。几何余量显示来源，不提供“一键忽略全部碰撞/未知区域”。

运行界面显示当前观察节点、三路画面与时间、目标及盒子的识别、场景版本、当前臂、provisional/held/release_pending/unknown、attachment 与静态障碍状态、阶段及明确失败原因。

验收必须覆盖真实 MuJoCo 渲染、实际 SAM3、GraspGen、cuRobo GPU 与物理接触。基础测试之外至少完成抓取、随后独立放置、单次组合抓放；分别覆盖 A/B 成功案例。负例包括缺目标/缺盒、腕视角不足、几何无法约束、同色歧义、盒太小、携物撞箱壁、开爪撞箱壁、释放未知、Reset/取消和迟到结果。真值仅进入独立评分记录，不能决定控制成功。
