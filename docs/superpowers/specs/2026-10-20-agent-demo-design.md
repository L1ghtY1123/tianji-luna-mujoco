## Goal and scope
In MuJoCo, move all or a requested number of 1–4 pink objects from a blue open bin on a small table at the robot left to a configured unmarked square on the large table. Robot forward is +X and left is +Y. Photo scale is not calibrated: dimensions are explicit demo configuration, not estimates claimed as measurements. Source bin touches the large-table edge. Runtime sensing uses registered RGBD and robot feedback; simulator object truth is available only to independent acceptance checks.

## Control
A typed program executor interprets the skill program generated by Responses from the available catalog. It validates arguments, bounds, contracts and live evidence, without imposing a single transfer sequence. No TypeSafe key or JEV request is required. Mandatory input preparation before discovery: capture all three RGBD at the current legal robot pose, construct the full obstacle TSDF/ESDF, plan synchronized dual-arm observation motion with collision checking, then capture at the observation pose. Left wrist must cover all source objects; right wrist supplies whatever it can see while parked clear of the left workspace. A camera lacking a target can still contribute obstacles.

Call gpt-6-luna Responses once after arrival, with all three RGB images, to parse the instruction, inventory visible entities across the large table and adjacent source table/bin, select the transport set, and generate a structured skill program. Nodes support whitelisted skill calls, bounded iteration over the frozen transport IDs, success/unknown/failure conditions, and stop. No arbitrary code or joint commands. Source objects are sorted in the initial left-wrist image by rows top-to-bottom and within each row left-to-right. Cross-view duplicates share one ID. IDs and task ordering do not change after removal. Requests exceeding confirmed inventory and ambiguous identities return needs_attention. Once-only discovery does not claim unseen objects are absent.

For each target: verify fixed ID with Decisions, segment with SAM3, fuse measured multi-camera RGBD, rebuild target-excluded manipulation TSDF/ESDF, select arm using offline reachability of source and destination, GraspGen, downward tool-Z filter in world coordinates, batched IK, plan_grasp_batch, grasp and lift, feedback-only grasp verification. Keep original cancellation/generation binding and execution collision validation.

For placement: preserve the grasp-time world rotation. Reuse the existing count-dependent equal-area radial partition algorithm and initial left-wrist image ordering; bind IDs to slots once and never repartition after transfers. Existing section count is the next even number (1/2 targets use two sections; 3/4 use four), not a hardcoded 2×2 grid. XY refers to the grasped-object measured reference rather than blindly centering a possibly eccentric tool: document the conversion. Compute the lowest release height compatible with support and collision clearance using attachment geometry and gripper envelope. Invoke single-goal plan_place; do not call independent place IK batches or plan_place_batch. A fixed pose may fail; never secretly change XY or rotation. Plan and validate retreat. Verify release feedback and fresh Decisions destination evidence after retreat. Region projections may indicate the unmarked intended area, but overlays are not physical outcome evidence.

After a verified placement, update the fixed ledger. If work remains, capture and build obstacles at the current pose before moving both arms back to observation. Do not rediscover with Responses. Queue completion must be consistent with current visual evidence: unknown or an extra unlisted pink object prevents an all-done claim. Specified-count tasks stop at their requested count.

## Failure and evidence
Unknown, identity conflict, missing collision geometry, empty grip, service failure, no valid candidate, cancellation, and timeout remain distinct. The first version stops with needs_attention on unresolved conditions instead of introducing implicit recovery. Retain logs tying capture, inventory, scene token, plan, gripper feedback, and placement evidence. Only a fully verified transfer increments completion.
