# 机器人坐标系下的 RGBD 与 IoU 实例关联设计

状态：实现方案。本文定义拟修改的行为，不表示运行代码已经完成改造。

## 目标和范围

自然语言中的左右、前后、上下及排序统一以机器人固定坐标系 Link_Base 为准：+X 向前，+Y 向左，+Z 向上。三路 RGBD 同步采集；头部相机提供整体上下文，腕部相机补充细节和盲区。视图优先级不决定物体身份、空间方向或证据真伪。

取消在初始 RGB 框确认后立即登记永久 ID 的流程。先提取当前候选及逐候选深度，确认同次观测的跨相机对应，再核验任务条件和历史身份；证据一致后原子提交永久 ID。没有 bbox 的相机仍参与任务相关类别的候选检索。

本方案覆盖首次定位、排序/数量/关系条件、跨时刻身份、观测恢复、数据库和回放。抓取、放置和规划算法沿用现有实现，接收已确认的实例与同次观测几何。Base 和 Simulation 协议不增加接口。

本版固定不引入 DINO/DINOv2 或其他新增外观特征模型。IoU 和覆盖比例由应用侧 NumPy 计算，复用现有模型与镜像；它们是对应证据，不是物理身份的单独证明。

## 现有实现依据

- `agent/registration.py` 的 `bind_proposals` 在 SAM3 之前调用初始 Decisions 并分配永久 ID。
- `perception.py` 的 `_segment_cached` 向 SAM3 发送完整有效 RGB、文字和时间戳，不发送 bbox；`_segmentation_queries` 当前按 kind/color 合并查询，可能混合不同形状的检索需求。
- `../tianji-algorithms/services/sam3_service/API.md` 只声明 `segment_text(rgb_jpeg, text, timestamp_us)`、health、visualize；本方案复用该接口，不假设已经支持框提示。
- `subject_assignment.py` 当前先按历史身份找单视图种子，再分组和复核。改造后当前分组不受历史永久 ID 引导。
- `association_depth.py` 已提供独立候选的可见表面测量与空间矛盾检查；历史参考缺少 mask 时不会产生逐物体历史深度证据。
- `runtime/compiled_task.py` 当前立即把 Responses refs 替换为永久 ID；需要延后到证据提交成功。
- `semantic_builder.py` 的 demo_mapping 分支当前强制 semantic_only。任务候选筛选不能因此删除未选目标的可见障碍几何。

## 一、四种引用和所有权

| 引用 | 生命周期 | 含义 | 可否驱动机器人 |
| --- | --- | --- | --- |
| `proposal_ref` | Responses 编译结果 | 用户语义目标或必要参照，例如一个来源容器 | 否 |
| `candidate_id` | observation_id + camera_id + mask 内容 | 单相机分割候选，类别相同不代表身份相同 | 否 |
| `group_id` | observation_id | 已确认对应的一个或多个相机候选组 | 否 |
| `entity_id` | 实例数据库 | 完成证据核验的永久物理身份 | 还须满足当前几何及规划检查 |

临时引用不是数字永久 ID，不写入 ObjectRecord。任务图可以引用 proposal_ref；Runtime 仅在登记成功后产生 `proposal_ref -> entity_id` 的版本化绑定。任务目标、用来比较的候选、匿名碰撞背景分别管理。

## 二、Responses 的职责和数据合同

每任务仍只有一次 Responses。当前图像顺序固定为 head(3)、left_wrist(2)、right_wrist(1)，各图附 camera_id、observation_id 和坐标约定；顺序仅改善上下文组织。

Responses 输出原有显式策略图，以及结构化 `SelectionSpec`：

- `ref`、`role`：target/source/destination/support/reference。
- `queries`：外观类别检索词及有序别名；保留任务原文。
- `scope_ref`：工作空间、配置区域或已声明来源/支撑引用。
- `relations`：可组合的空间、容器、支撑及历史状态条件；每个条件引用其他选择器或已存在的实例。
- `quantifier`：single/ordinal/count/all；ordinal 含机器人轴、方向和序号，count 含数量。
- `binding_mode`：once / each_selection。具体对象和 ordinal 默认 once；all/count 的输入集合每次选取新输入时求值，来源/目的容器等参照默认 once。用户明确要求动态重选时才对相应引用使用 each_selection。
- `view_hints`：每相机的候选框列表与 `proposed / not_seen / ambiguous`。同一选择器允许一个相机给多个待区分候选框；不要求每个相机给框。

不再让 Responses 输出具有确认效力的 existing_id。若有历史 ID 提案，只作为 `suggested_entity_id`，后续必须重新验证。框都标为 proposal，不声称跨相机相同 ref 已经是同一物体。

空间谓词的确定规则：

- `robot_left/right`：相对于 Link_Base 中线的 +Y/-Y 区域；中线不确定带返回 unknown。
- `left_of/right_of(a,b)`：比较两个候选组在 Y 轴上的测量区间。
- 从左到右：同一任务范围内沿 Y 递减排序；从前到后沿 X 递减排序；上下沿 Z 比较。
- `leftmost` 与 `robot_left` 是不同谓词；不能把“最左”自动当成 Y>0。
- `inside/on`：以已定位的来源/支撑组为参照，结合当前 RGB、可见几何和测量来源判断；二维框重叠不证明容纳或支撑。
- `and/or/not` 使用三值逻辑；没有看见或缺少证据不能作为否定事实。未支持的动作/谓词在编译时报告 unsupported，不任意改写任务。

方向含义由程序白名单解释；模型不能用图像 x 代替机器人 Y。关系图允许多层引用，按依赖解析；循环依赖采用联合约束，未得到唯一一致解就 unknown，不任意选一个容器破环。

## 三、候选提取：无框也检索，不做全物体永久登记

从所有 SelectionSpec 收集目标、来源、目的地、支撑及比较所需的外观查询。在三张同步的有效工作空间 RGB 上运行现有 SAM3 `segment_text`，按规范化文字去重和缓存，不能只按 kind/color 合并不同查询。

这意味着分割“任务相关类别的所有候选”，而非全部类别，也非只裁 Responses 框。排序/all/count 要保留范围内所有匹配候选，否则无法判断序号或数量。多次查询返回完全相同的同相机 mask 可按内容哈希去重；疑似重叠/混合物体掩膜保留歧义，不用最高 score 当身份。

Responses 框与 mask 在同一 observation/camera/image-size 下计算重叠、包含及越界信息，供定位核验和回放使用。框是软证据：不剪裁完整物体、不用框内所有深度冒充物体、不仅凭最大 IoU/最近中心分配身份，也不因候选在错误提案框之外就丢掉它。不匹配可纠正提案或报告 unknown。

### 同图 IoU 与覆盖证据

对同一相机、同一次采集，令 B 为 Responses 框，M 为原始 SAM3 二值轮廓，R(M) 为它的紧致外接框。计算以下独立指标，不合成为一个自动接受分数：

```text
box_iou       = area(B ∩ R(M)) / area(B ∪ R(M))
mask_coverage = count(M ∩ pixel_centers_inside(B)) / count(M)
box_fill      = count(M ∩ pixel_centers_inside(B)) / count(pixel_centers_inside(B))
mask_iou      = count(M1 ∩ M2) / count(M1 ∪ M2)
```

box_iou 对比两个矩形；不把不规则物体轮廓直接与整个框计算 IoU 后要求接近 1。mask_coverage 表示候选轮廓有多少落入提案框；box_fill 仅说明框内填充程度，空心或细长物体填充低不是分割失败。

归一化框乘原图宽高得到浮点 xyxy；采用半开区间，mask 外接框右/下边界为最大有效像素索引 +1。覆盖率以像素中心是否落在框内计算。原始尺寸、裁剪/缩放变换和工作空间范围必须一致；非法框、空 mask、零分母输出明确 invalid，不能伪造 0 或 1。指标使用 RGB 轮廓，不使用已经扣除无效深度的 mask，否则深度空洞会改变视觉对应。

对每个提案框保留所有兼容查询候选的指标矩阵，包括低重叠候选，不仅发送 top-1。没有框时记录 `hint_status=absent`，指标为 null；不能给 0 分造成该视图被排除。多个框同属一个选择器时逐框保存，不先把框取并集。模型输入同时包含提案编号、候选编号、标注 RGB、指标矩阵及三维证据；模型回答必须指向确切候选/组，最终程序仍执行任务和几何约束。

框对应含义限定如下：高 box_iou 且高 mask_coverage 支持“该 mask 覆盖了这项图像提案”；多个候选重叠相近说明提案可能歧义；全部重叠低说明提案与分割不一致。它们均不直接说明哪个物体满足任务。第一版不设置 IoU 大于某值就登记身份的规则，框错时仍允许选择框外、但满足完整任务证据的候选。

同图 mask_iou 用于分割完整性检查。二值 mask 完全相同才可合并为一个候选，保留全部查询来源。可配置 `suspected_duplicate_iou=0.90` 仅标记需检查的重叠候选，不执行 NMS、不合并、不选择更高 SAM score 替代另一候选。另保存两个方向的交集/各自面积，区分近重复与大小掩膜包含；容器与内容物不能因二维重叠而合并。此诊断阈值不是身份接受阈值。

不同相机之间不计算二维 IoU；相机运动或物体移动后的历史框也不直接计算二维 IoU。第一版跨时刻关联不使用图像 IoU。三维可见表面包围盒的重叠不作为必需条件，因为不同视角可能只测到不同侧面。

IoU 的公开结果绑定 observation_id、generation、camera_id、图像尺寸、提案编号、candidate_id 与 mask 指纹。作用限于提案到掩膜的可审计对应，以及同图候选完整性检查；不会生成新掩膜、跨相机身份或永久 ID。

无框视图照常检索相关类别：未见与 ambiguous 都不构成“没有目标”的证据。SAM3 没有掩膜、深度不足或外观仍不明确，均产生有原因的未解决结果。

每个候选保留原始轮廓、有效深度 mask、RGB/框/查询来源、内外参、采集时关节/夹爪反馈引用。使用现有反投影转换到 Link_Base。沿用至少 30 个有效点及有效比例 0.5 的 measured 诊断门槛，数值均进入配置和证据；不足不删除原始 RGB 候选来制造“源区域已空”。

## 四、同次三相机关联先于永久身份

`current_instance_groups` 接收该次候选，不接收 entity_id、历史身份或任务期望作为身份依据。基于兼容外观查询构建跨相机待比较集合，各候选独立计算点云；先关联后融合，不把一张图的轮廓投影成另一张图的真实掩膜。

程序计算可见表面边界、间距和有效性；Decisions 同时获得带 candidate_id 的 RGB、独立几何摘要和这些空间关系，回答对应、无对应、分割错误或 unknown。

程序在模型结果之外执行：同相机组内唯一性、传递一致性、空间矛盾拒绝、候选不得被多个组占用。保留模型原始答案与程序拒绝原因。现有 `max(0.15m, visible_diagonal)+0.02m` 规则仅用于排除明显分离，不把 not_separated 变成肯定匹配，也不作为相邻物体的精确匹配门槛。

一个物体允许只有一个或两个确认视图。模糊的额外视图不强行合入。若未解决对应可能改变目标、排序、数量或来源关系，不能把它当独立新物体继续计数；标记依赖它的任务条件为 unknown。无关视图歧义不阻塞已经充分证明的目标。

## 五、任务选择和历史身份分别核验，最后共同提交

在当前 group 上执行两种不写数据库的核验：

1. 任务定位：结构化关系图决定 group 是否满足机器人坐标系中的要求。数值排序和空间矛盾由程序计算；Decisions 检查外观、来源/支撑关系和可见范围是否足以作判断。框不能推翻相反的数值事实。
2. 历史身份：将当前 group 与带日期参考、操作回执、加工谱系比较，产出 existing / new / unknown。此时再接触历史永久 ID，不能用“任务想抓它”证明它就是某个历史物体。

涉及加工状态、曾被搬运等历史条件时，任务定位等待相应历史匹配结果。只用于比较且最终不选中的候选可以没有永久身份；其历史不明不必阻塞纯几何比较。选中的目标及必要参照有身份歧义时必须停止提交。

排序使用机器人轴上的保守位置范围，不能把不同可见表面的中位数当完整物体中心。沿用可见表面摘要作诊断，另保留完整有效点范围与误差扩张用于排序；初始误差扩张配置为 0.02m，需由标定/噪声验收调整，不能宣传为真实误差上界。区间重叠、视角更换会改变名次、来源范围不清或遮挡可能隐藏影响答案的候选时返回 unknown。缺少完整形状证据时不猜测隐藏物体中心。

all/count/ordinal 必须记录 `coverage` 证据：任务范围、哪些区域已被观测、未解决掩膜和遮挡、是否可能改变答案。SAM3 空结果不等于空场景，三张图不等于覆盖完整。count 按已确认不同物理组计数；all 沿现有任务循环根据后续观测验证来源是否还有目标。

只有任务条件、所选物体历史身份及当前分组相容，才能在一个事务中保存 capture、确认 masks、实例登记/更新、历史证据以及 ref-to-ID 绑定。保持 ObjectDatabase 的幂等语义；失败、取消、代次改变或观测过期都不得留下部分登记。

新增登记证据 `registration_basis=rgbd_grounding_v1`。已有记录和 ID 保留；旧 RGB-only 登记作为待重新核验的历史，不自动变为新证据，也不自动分配一个新 ID 掩盖旧身份失联。重核验成功可沿用 ID 并追加证据，不改写旧历史。

## 六、后续时刻和恢复

后续观测复用相同的候选提取、当前分组、历史匹配和提交路径。首次与后续的区别是有无历史参考，不是两套互相依赖的身份登记算法。

once 引用成功绑定后，初始“左侧/第二个/某容器内”等位置条件只作为历史选择依据，不在每次观测重选目标。搬运后仍追踪原 ID。each_selection 只在图显式选择下一个输入时重新求值，一次抓放进行中不能换目标；已经完成的输入由任务账本排除，不靠改写物体身份实现排除。

历史图使用当时的深度和外参；只在同一次观测内施加静态空间矛盾约束。搬运后的旧位置是有日期的先验，不能强制新位置与之重合。保留当前已验证抓取执行链继承目标身份的规则；中断、失联或不可区分物体交换后不得靠颜色/最近距离强行恢复。

初始 `ground_task` 是显式 graph 技能：使用冻结采集，不擅自拍新图、不移动机器人。结果为 success / unknown / failure，含 `missing_evidence` 与依赖的 selection refs。图上的已声明恢复技能负责补观测；重复相同输入使用缓存，不重复询问模型寻找有利答案。

若初次定位失败且尚无永久 ID，恢复仍可使用匿名当前 RGBD 建碰撞场景。额外腕部运动须走现有规划/运动安全接口；没有足够地图就报告 blocked，不能因尚未登记而跳过碰撞。额外运动不得藏在检索或 Decisions 调用内部。

## 七、解耦、地图和回放

- Responses 只写任务提案和显式图；SAM3 服务只产出 mask；几何模块只作带来源的测量。
- 当前关联、历史关联和任务定位分别返回不可变结果；无模块在判断中自行 allocate ID。
- IoU 模块是无模型、无 I/O 的纯计算模块；只返回指标与有效性，由感知层绑定来源，再提供给关联/定位模块。
- Runtime 负责执行和依赖绑定；`ObjectDatabase` / `PhysicalMemoryWriter` 是唯一持久化入口。算法不访问 Simulation 场景真值。
- FK 和机器人深度过滤沿用 cuRoboV2-Fast v0.9.0 的公开接口；机器人/RGBD/夹爪仍全部经 Base。
- 任务相关实例使用确认的 mask/CAD/TSDF；其他可见工作空间障碍使用匿名深度，不因为没有 bbox 或没被选为目标就消失。
- 同一个 Luna 工作台展示 proposal 框、candidate 掩膜、group 以及最终 entity ID 的证据链，明确显示坐标系、unknown 原因及覆盖情况。回放保存中间结果，但候选不进入永久实例数据库。

## 验收矩阵

| 输入变化或失败情形 | 必须验证的结果 |
| --- | --- |
| 头部画面左右与机器人 Y 方向相反；视角和相机输入顺序变化 | 机器人坐标相同的物体仍被选中，方向不能被像素顺序覆盖 |
| 目标只在任意一路可见，其他路无框 | 有足够证据的一路可以完成定位；无框不禁用该路检索 |
| 任意一路 Responses 框错、空框或框跨两个同类物体 | 不在 RGB 阶段登记；修正提案或 unknown，不继承错误提案身份 |
| 框和 mask 完全吻合、完全分离、松框/紧框、空心物体 | 指标数值及无效情况正确；高/低 IoU 均不能单独决定身份 |
| mask 近重复、大小包含、同框内两个不同物体 | 完全相同才合并查询别名；其他情况保留候选及完整性证据，不用 NMS 隐藏歧义 |
| 无框、不同相机、不同观测或缩放尺寸混用 | 无框指标为 null；拒绝不在同一图像坐标系的 IoU 比较 |
| 多个同色同形物体、不同形状但同 kind/color | 保留所有必要检索词和比较候选，正确去重，不按最高 SAM score 选目标 |
| ordinal/count/all；物体跨视角重复、遮挡、掩膜漏检 | 只按确认物理组计数；缺失可能改变答案时 unknown，不臆造完整集合 |
| 多层容纳/支撑/相对位置关系，二维重叠但三维分离 | 关系按同一世界坐标和视觉证据核验；二维重叠不构成关系证明 |
| 外观相同且三维几何无法区分，或历史物体遮挡后互换 | 保留 unknown，不用最近位置、旧目标描述或新 ID 掩盖歧义 |
| 深度无效、标定错误、不同 capture/代次混用 | 保留原始证据，禁止提交身份和执行；给出具体缺失原因 |
| 旧 RGB-only 记录、真实搬运、正常跨时刻视角改变 | ID 可经重新验证继承；历史位置不锁死移动物体 |
| 已绑定的第二个/左侧目标被移动，候选序号或侧别变化 | once 仍追踪原 ID；只有显式新一轮 each_selection 才重选 |
| 提交前取消/代次改变/中途异常/重复提交 | 无部分 ID、无半套 masks 或绑定；重复成功提交幂等 |
| 不在任务类别中的可见障碍 | 留在匿名碰撞图，既不丢障碍也不分配无关身份 |

验收使用参数化场景与冻结 RGBD 的等价变换，而非只写“第二个黑物体”和“左盒粉物体”两条专用分支。仿真真值仅供独立验收端对照；Luna 任务输入严格只有 Base RGBD、关节/夹爪反馈、标定、CAD 与用户任务。

## 与当前程序比较及成功率验证

当前程序已经具有 SAM3、独立候选深度、明显分离否决、分组一致性和历史参考。新方案不把这些已有能力算作新贡献。主要变化是：RGBD 核验前不提交身份；提案与掩膜之间增加数值证据；当前分组不受先前身份种子引导；任务空间条件显式采用机器人坐标；相同路径处理首次与后续观测。

预期收益是降低首次错误登记和后续错误继承，并改善提案框与正确掩膜的对应。IoU 不直接解决跨视角对应，也不补出不可见或不可区分的身份。增加检查可能增加 unknown 和耗时；是否提高关联成功率必须由固定分母的对照证明，不能只报告“已接受结果里的准确率”。

对照分为 A 当前程序、B 新架构但不提供数值 IoU 证据、C 新架构加本节 IoU 证据。A 与 C 在同一组原始任务、RGBD 观测序列和相同初始历史上作端到端配对；保留各自提案和分割差异。B 与 C 固定 Responses 提案、SAM3 候选、深度、模型版本和初始历史，只改变 overlap 数值及其诊断使用，隔离 IoU 贡献。每组使用独立数据库副本，防止一组污染另一组。真实动作测试另行重置场景，不复用不可能相同的执行结果。

开发集用于确定测量误差与诊断参数；不同布局/视角的验收集保持独立，测试前冻结参数。独立标注每个任务所需实例、可见候选对应以及根据所给证据是否可判定。标注不能进入算法输入。模型具有随机性时报告预先固定重复次数内的全部结果，不挑选成功尝试。

必须同时报告：

- 可判定任务所需关联的成功率 = 正确完成的所需关联数 / 所有所需且可判定的关联数；unknown 计为未完成。
- 错误提交比例 = 错误的身份/任务绑定提交数 / 全部提交数；没有提交时报告无分母，不能写 100% 准确。
- 正常可判定样本的 unknown 比例，以及不可判定样本的错误接受数量。
- 按真实物体轨迹统计 ID 切换、重复新建 ID 和跨相机掩膜对应的准确率/召回率；不能靠丢弃腕部视图提高表面准确率。
- 每阶段模型调用数、平均/P95 延迟、资源占用，以及单独统计的实际任务完成率。

验收要求：明确矛盾、过期帧、取消和不可判定的固定负例不得提交错误身份；C 在独立可判定集合上的成功率不能低于 A，且同时检查错误提交率和视图召回率。报告原始计数、配对差异及不确定范围；没有实测结果前只称设计预期，不给出提升百分比。如果仅降低误接受但增加拒绝到使正确关联减少，应报告为保守性改善，不能称整体关联成功率提高。
