# 独立物体任务与 Decisions 恢复

用户要求直接落实：每个待处理清单 ID 有自己的 TaskSpec 和子图；失败优先由 Decisions 处理；丰富外观描述与 SAM3 查询。

设计：在现有策略树增加 object_task 节点，包含单一输入 ID 的不可变 TaskSpec 和模型编写的 body 子图。根 TaskSpec 保留总任务、选择数量、顺序、最终双臂姿态；根图协调共享观测、清单确认和最终验收。节点执行时绑定自身来源/目的地/工作区，产物沿 root_input_id 继承要求。完成项跳过，不能重新搬运。修订可以改变子图，不能改变各物体目标。

恢复增加 recover 节点：一个可安全重复的能力调用、模型编写的备选恢复分支、有界尝试次数。Decisions 根据实际错误、证据和历史选择分支或声明耗尽；runtime 不生成动作。技能契约显式声明 recovery_retry_safe。物理动作不进入自动重放；部分执行失败仍保留副作用保护。耗尽后原结果交现有 Decisions 修订判断，再决定是否调用 Responses。

外观增加 appearance_keywords 与 segmentation_aliases。描述是提案，不是事实；SAM3 使用最多三个非重复短查询，逐查询归档并去重候选；Decisions 仍独立核对 ID。任何概率门槛和几何安全门不降低。

验收：先写反例测试，覆盖两个不同目的地/处理要求、产物继承、作用域恢复、完成项跳过、修订不可改目标、恢复选择与副作用保护、别名去重及证据；再跑相关和完整测试、前端构建、冻结真实服务对照、真实 MuJoCo 任务。不能把静态检查或纯感知探针称为物理成功。
