# 桌面与盒间搬运可靠性修改方案

2026 年 11 月 18 日。本文是拟议设计。实验保持停止。基线取自[本批逐轮复盘](../../../data/acceptance/flat-transfer-ten-20261118/failure-review.md)。

## 一、先打通已抓稳物体的放置执行

第 2、6、9 轮分别覆盖 B 臂黑件和 A 臂粉件。三次均完成抓取验证、放置规划，在松爪前被起点一致性检查拦下。它们可以直接作为独立的放置回归样本。

1. 在 `runner.py`、`base_client.py` 贯通规划起点、碰撞检查起点、派发前最新实测关节、各自的时间戳和反馈序号。失败主记录保存最早阻断任务的错误，恢复流程的错误另存。上报变化最大的关节及差值。
2. 检查当前持物记录、夹爪状态、目标与目的地 ID、地图版本及双臂状态。轨迹起点过期且确认尚未派发时，从新鲜、稳定的反馈准备连接段或重规划；包含连接段的实际下发轨迹必须通过碰撞、动态约束和持物模型检查。提交时再次核实起点。保留现有 0.05° 保护，有限恢复后仍漂移则返回带实测值的失败。
3. 分开处理抓取执行。对第 1、3 轮查提交到第 188 点时的命令阶段、目标关节、实测反馈、到位条件和超时起算点。对第 5 轮按执行 ID 和控制器回执核对是否派发、是否仍在动、夹爪是否持物。在状态确认前禁止自动重发可能已发生的动作。跨技能恢复显式写入任务图。
4. 沿用各自的配置 XY。释放基准取当前实测桌面高度或盒口最高处。初版沿用当前 TCP 计算，即基准高度加物体高度与抓取 TCP 到物底高度差两者的较大值，再加配置余量。把计算所得物底高度和实际松爪反馈一并归档。放置验证分开记录松爪位置、是否空爪、物体是否在目标支撑面或容器，以及最后一项由直接观测还是推定得到。

验收分三层。用归档重放验证错误归因，用录制或注入的反馈验证起点漂移和派发不确定的分支，后续在专用仿真内单独运行从已验证持物到释放的技能链。归档不足以证明修复后的控制器实际会完成动作。

## 二、用实际夹指和目标表面解释抓姿取舍

四次粉件输入约为 80 × 60 × 105 mm；四次排名第一的 GraspGen 候选均沿短边，实际选中候选均接近长边。使用归档的原始 100 个候选，在相同机器人、持物前场景和设置下复算。

- 在 `geometry.py` 与算法适配层，用 RAG 实际夹指几何核对 A/B 两侧前端 TCP、闭合轴、指垫可接触区和有效开度。分别报告模型 FK 误差和实物在仿真夹指间的位置。只有接触测量证明系统偏差后才改变标定。
- 给每个候选记录真实开口余量、两侧指面支持、靠近盒壁的间隙、IK、预抓、闭合、提起、进入了哪次 goalset、是否被求解器返回。区分“未提交”“未被选中”“已检查且失败”。使用受官方接口支持的候选分组。在满足真实夹指接触的候选中优先检查开口余量充足、盒壁余量大的方向；能沿短边可靠夹持时优先短边，允许受遮挡时选择其他可行方向。继续对最终轨迹做逐段检查。
- 当前 662 个目标表面体素中有 30 个与背景表面体素体积相交。仅在目标归属有当前多视角深度支持时修正对应背景观测，重新生成局部表面；真实盒壁、桌面、归属不清的障碍继续参与碰撞。对照修正前后同一短边候选的碰撞对象和距离。体素相交本身不能证明它导致某个候选失败。回放提供实例层、背景层和实际 GraspGen 输入的独立显示。
- 验收四组粉件候选和一个短边贴盒壁的反例。每次实际入选的候选都要给出可追溯的理由；确认第 9 轮原本通过的抓取仍可行。黑色 CAD 件按原有 CAD 位姿和抓姿库单独验收。

## 三、把实例关联、任务绑定和碰撞记忆分开

`current_instances.py` 负责本次采集的物体分组，`temporal_identity.py` 对照历史，`registration.py` 提交永久 ID，`runtime/controller.py` 管本次搬运的选择和完成账本。

| 问题 | 首选证据 | 歧义处理 |
|---|---|---|
| 同一相机是否重复分割 | mask IoU、双向覆盖率、深度表面及声明类别 | 箱体包含内容物时保留两件；只把相同物理表面的近似重复或碎片合并 |
| 同时刻的多相机是否看到同一物体 | 标定投影、可见部分的 mask 重叠、三维表面距离和双向唯一匹配 | CAD 位姿可补证。只把确有竞争的局部候选交给 Decisions；证据仍不足时保留临时组 |
| 新观测是否对应历史 ID | 桌子用世界坐标下的平面高度、法向、足迹和唯一匹配；活动物体结合历史观测、实测位置及抓放回执 | 相似活动物发生搬运、遮挡重现或竞争同一 ID 时，Decisions 比较受限历史候选。几何冲突时不写入错误绑定 |
| 是否登记为新实例 | 先确认当前物体独立存在，排除同帧重复，并与可能的旧 ID 核对 | 旧记录缺失或历史暂时不可见时区分“确为新增”和“尚不能判定”。注册使用幂等提交，一件物体只取得一个 ID |
| 本次抓谁、放哪 | 在已解析的角色条件上绑定目标与目的地；目标、目的地和当前持物分别记账 | 指定对象要求可区分；任选或逐个搬运时，允许 Decisions 在已确认且未完成的候选中选择，机械可行性由规划器判断 |

比值阈值可从 0.5–0.8 的候选范围开始，用有真值标注的同物、异物、遮挡和近邻样本校定；距离、高度、角度按其物理单位和传感误差独立设置。多视角只见不同表面时，低 IoU 不能单独否决对应。禁止用总分盖过已知的几何矛盾。

保留任务图中可见的 `ground_task` 和 `observe_scene`。前者产出可复用的观测、实例和角色绑定；后者在采集、标定、动作状态、场景证据和查询条件仍有效时直接消费结果。需要新观测时，只重新判定受到影响的物体与关系。Decisions 记录问题、候选、触发理由和消费结果的技能。以重复消费同一有效证据时新增调用为零、固定桌面保持 ID 为验收项。同步记录错配、新增重复 ID、漏配、unknown 和调用数，避免靠全部返回 unknown 来降低错配率。

碰撞地图保持全场景有效，已确认移动时更新旧位置和新位置并重算受影响区域；只有在新观测或可靠运动证据支持时清除旧占用。单次没看到的障碍继续保留；世界复位、标定变化或累计地图来源失效时全量重建。仿真真值只用于离线验收。

## 四、约束 Responses 输出并明确任务循环

对常规搬运，Responses 在一次编译中提取显式场景段、原文引用、对象条件、数量或顺序、来源、目的地及模板参数，选择已有单件或共享循环子图，由程序展开完整控制流及有限恢复边。四项角色分别核验引用，`source_table` 可以引用用户原文“桌面上”。引用必须存在于用户文本；无法无歧义导出时报告具体字段。声明缺失时要求补充；场景声明限制 Responses 框和 SAM3 物体查询，障碍深度独立保留。模型框只提供定位提示。

一次搬运把选中的目标和目的地锁定至本件完成，物体离开来源位置后继续沿用原 ID。固定桌面区域绑定区域 ID、支撑桌 ID 和实测高度；右盒绑定盒子 ID 和盒内释放 XY。多件任务在交付验证后才将该 ID 记为完成，再观察并选择下一件。覆盖不足时不能用当前候选列表为空证明已全部搬完。用“指定右侧一件”“任选一件”“两个都搬”及第 4 轮原始任务验证编译、绑定和完成条件。

## 五、复位与量化验收

1. 操作界面清楚区分停止任务、重新应用当前物体布局、完整仿真复位。任务清理结束后自动刷新按钮状态，显示禁用原因、配置版本、物理世界应用版本及错误。完整复位只作用于已确认的专用仿真，按仿真归属执行物体与机器人复位；新的世界使旧命令、旧地图及旧位姿失效，旧实验和历史记录保留。回执核对机器人初始状态、世界版本与物体布局。
2. 离线先用第 2/6/9 轮查放置执行，第 1/3/5 轮查反馈和派发，四组粉件候选查短边和体素，第 7/8 轮查桌子 ID，第 4 轮查编译。每项同时测已知成功和已知遮挡、歧义或派发状态不明的反例。
3. 后续获准进行仿真时，先单测复位、夹爪接触、抓取执行和持物放置，再运行两类任务各 5 次。按进入该技能的轮数分别报告规划、派发、抓取验证、释放和放置验证；整轮成功率以启动并纳入评估的轮数为分母。报告直接观测成功、仅推定成功、中止、失败与首个失败原因。小样本用于回归判断，部署可靠性需要更多独立布局。
