# 单臂抓放与数据库同步实施计划

> 执行方式：在当前工程逐项实施，不使用 sub-agent 或工作树；遵循项目隔离规则。

**目标：** 落实用户本轮七项要求与已确认修复方向：数据库为物体事实来源，Decisions 逐轮选择容易抓的目标，一次抓放限定同一臂，当前位置优先恢复，接通未知物体 TSDF 表面与 ESDF 碰撞。

**结构：** 数据库保存实例、观测、操作和版本；执行层只持有数据库读取快照、任务要求和执行账本。空间记忆消费数据库提交及几何来源，碰撞几何未同步时不可规划。完整 graph 显式声明感知、建图、重试和必要观测移动；同一抓放固定执行臂。

**技术：** 现有 Python/Pydantic/SQLite、MuJoCo、Decisions/Responses，cuRoboV2-Fast v0.9.0 / 42498cf4，SAM3、FoundationPose、GraspGen。官方 SDK 只读。

**规格：** 用户本轮七项要求；前轮核对中发现的单臂两端可达性、失败盲目换臂和 TSDF/ESDF 未启用问题。

## 约束与决策

- 不保留独立物体清单或初始固定执行队列。任务账本记录本任务责任，不成为第二份物体数据库。候选是当前数据库与观测的查询结果。
- 每轮在合格候选中由一次 Decisions choice 优先选择暴露、少遮挡、间隙充足的物体；用户明确顺序优先，无 0.8 门槛。
- 同一臂同时覆盖源位置与控制台固定释放 TCP，姿态与携物路径仍由官方数值规划核验。无共同可行臂就拒绝调用该抓放流程；不实现交接。
- 抓取规划失败只允许同一臂重新计算一次；第二次失败结束。服务/协议/场景错误保留真实错误，不包装成机械臂不可达。
- 明确空抓才允许恢复重抓；unknown 不当作空手。先在当前位置观测和更新几何，再从实际关节重新规划。
- 返回观测位姿由程序检查当前证据是否缺少目标身份、所需深度/几何或目的地；有足够证据无需返回。所有移动仍需空手、有效移动地图和数值运动检查；夹持 unknown 不自动空手回位。
- 数据库提交失败不得更新空间或对象快照。数据库成功提交后立即同步空间状态，失效几何在发布/attachment 等有来源更新前禁止使用。
- RGB/独立 mask/depth 输入保持本轮已授权原图方案；数值 TSDF/ESDF 不参与身份投影或视觉成功预判。
- 桌面 cuboid、CAD 物体 FoundationPose + CAD 碰撞 + 离线抓姿；未知物体以当前掩码 RGBD 建 TSDF，提取表面点供 GraspGen，ESDF 供碰撞。OBB 可保留数值包络用途，不能冒充 ESDF。
- 五容器总 CPU 4，SDK 不修改，不新建无用途镜像；部署仅同步本轮文件与明确退役文件。

## 验收关注

1. 相同外观多实例、被遮挡物体不能按初始顺序永久饿死；每次完成后重新选择。
2. 两端分别可达但没有共同臂时，不能启动抓放或隐式换手。
3. 空抓后物体可能移位，禁止复用旧目标位姿或旧关节作为规划起点。
4. 数据库写入失败、重复事件、几何失效及 attachment/释放状态必须保持版本一致。
5. 放置 unknown 只改善观测并重核验，禁止重放释放；持物 unknown 禁止空抓恢复。
