## 永久 ID 的作用

`asset_id` 表示型号，永久实例 ID 表示场景中的某一个物体。两个蓝盒共享同一 CAD 型号，但实例 ID、位姿、观察历史和任务角色不同。OBB 更新改变该实例的几何版本，不更换其身份。加工产物使用新 ID，记录与被消耗包装件的输入/输出关系。

简单的“把当前可见物体都搬走”可以不用永久账本。本项目的 ID 用于三相机关联、CAD/抓姿/attachment 绑定、局部更新保留其他物体、防止恢复时重复执行已完成动作，以及核对每件物体的加工与交付。它不应该触发每一步重新识别；已确认的型号和可复用的身份依据应保留。

## 三相机与 FoundationPose

SAM3 和 Decisions 先把各视角候选关联到永久实例 ID，并匹配 CAD 型号。三个相机的掩码都可参与身份判断；FoundationPose 选其中掩码内有效深度最多的相机，用该相机的 RGB、深度、掩码、CAD 和内参估计相机坐标位姿，再通过外参转到世界坐标。

对同 ID、同型号且动作上下文未变化的实例，用它自己的历史世界位姿初始化当前相机下的官方 `track_one`；新实例、抓放后或缺少可靠动作上下文时使用 `register`。模型 GPU 资源可以共享，实例位姿种子不共享。有效且源模型/坐标/采集绑定一致的输出直接采用，不做后续点云、轮廓、深度吻合检查或 ICP。这里采用的是用户要求的精度假设，不另行宣称配准精度已经验证。

## 放置位置

1. `perceive_placement_zone` 绑定容器内底面、物体表面或语言要求的支撑区域。Decisions 判断原始语言是否允许整区，还是包含额外相对位置/子区域要求。
2. 普通区域按 4→8→16 个子区域的中心生成 XY，最多 28 个，找到可用点就停止。整区已授权时，Decisions 通过结构化 choice 选择候选 ID；有额外语言约束时，还需判断候选足迹与原句是否一致。它无需输出自然语言坐标。
3. 选完 XY 才求 Z。保留抓取旋转，从硬净距及既有 0.1mm 跟踪余量开始，以 1mm 间隔寻找首个可行高度，不设固定 10mm 释放高度。
4. 检查完整持物/夹爪几何、当前碰撞世界、机器人离线位置包络和固定姿态 IK，再由 `plan_place` 检查接近、放下、撤离三段轨迹。位置包络通过不等于姿态和路径一定可行。

“指定区域”“设定区域”使用工作台配置 XY，不进入 XY 搜索；阻塞时报告失败，不自行挪动指定点。attachment 仍在 lift 成功、持物确认后建立。

## 当前核验与观测

按用户最新要求，verify_place 使用一次 Decisions 综合三相机 RGB，判断本次目的地关系和是否仍夹持，允许位置误差。不运行 SAM3、FoundationPose、OBB 或释放后深度测量；释放端点、夹爪实际反馈与版本检查保留。它不提供释放后毫米级位置证明。

生产 CAD+OBB 感知不再使用 CPU MuJoCo 机器人网格射线去除像素；原始深度不变。观测依据动作/场景/命令/反馈版本复用，失败不触发原位重复采集。OBB 随有效新观测更新，型号和永久实例身份在有效范围内保留。

当前完整任务仍有六次观测，暖态 build_scene 约 0.55–1.26 秒。黑件抓取规划仍约 30 秒。详细结果、测试日志、GPU 用法和恢复限制见 [本轮诊断](runtime-diagnosis-20261102.md)，不将历史 P50 的 245 秒结果当作当前版本。
