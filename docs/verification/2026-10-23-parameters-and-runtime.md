# 参数、调用边界与单件耗时复核

## 结果与责任边界

本次单件完整实验 `fc3aeb657fdd46b097761766eb7b702c` 成功，用时 **217.514 秒**：粉件抓放、模拟拆包、黑件抓取及投放、Decisions确认、双臂最终回观测位姿均完成。独立MuJoCo终态检查确认黑件CAD完全在右盒内、清单完成1件、无持物。初始Responses一次、全局建图两次。与已有318.643秒单件记录相比减少101.129秒，仍未达到180秒，也不能声称恢复了用户提到的186秒最佳纪录。不是相同随机抓姿的严格性能基准。

之前确有封装缺陷，先前将“SDK文件没改”扩大成“全部封装与官方一致”的结论不成立。缺失末端JointState.dt、夹爪状态传递、重复检查及缓存失效分别需要调用链和运行证据验证。50/75mm是项目自行选值，不是官方默认或用户要求。

## 本次参数修正

- 抓取、放置界面统一使用Approach/Lift命名；放置两项均100mm，Ubuntu当前保存设置和本地设置也已修改，不仅修改模型默认值。
- 放置的`place_retreat_*`存储键为兼容旧保存文件保留，界面明确为Lift。抓取Approach默认工具-Z 100mm，放置Approach默认世界+Z 100mm；符号不同源于参考系，不能直接改成同一个符号。
- 删除项目额外设置的`plan_timeout_s`、`place_timeout_s`及环境变量；不再用额外墙钟期限截断抓放算法链。官方公开的attempts、有限候选轮数、手动取消和网络请求超时仍存在。
- GraspGen方向预处理和执行臂夹爪对称选择保留，取消沿工具+Z额外深入10mm。原候选XYZ不变，再做batched IK。
- 删除旧支撑法向兼容入口对公开`non_terminal_scale`额外乘100000的隐式放大。当前demo的place Lift不走该入口，采用公开`linear_motion`默认scale=1。

## 官方接口与时间语义

锁定SDK提交`8e734f3ced1df898990bcd92de40abce475907db`，本次未改SDK/vendor。`scripts/audit_public_parameters.py`在运行容器核对IK、MotionPlanner构造和显式grasp/pose/linear_motion参数，13组检查通过；官方JointState的dt字段类型为`Optional[torch.Tensor]`。该脚本验证参数签名，不把它当成全部规划语义正确的证明。

官方`plan_grasp`没有公开max_attempts/finetune关键字，因此封装没有向其内部阶段注入这些设置；普通pose等公开支持的调用才使用对应高级设置。用户授权的时间伸长、停留、10mm净距和2cm体素属于明确的项目执行/场景设置，不冒称每个UI字段都是SDK关键字。

`JointState.dt`是官方优化状态的时间信息。place切换为开爪、无attachment模型后，下一段规划必须完整接收官方末端q/v/a/dt，而不是只传关节位置。执行后处理使用另一项`interpolation_dt=0.02s`作为采样周期：2倍时间伸长增加五次插值点，速度和加速度随时间缩放；独立停留保持关节目标，不乘2。dt与停留不冲突。

place不能只改grasp的名称：前两段保持闭爪attachment，Lift阶段为全开、detach。前两段调用公开`plan_grasp(plan_grasp_to_lift=False)`，Lift使用公开`linear_motion+plan_pose`。此前状态跨调用丢失发生在place组合边界，grasp官方内部三段没有同一序列化边界。

本次独立停留实测约1.00秒；放下后的检查/等待1.058秒、释放后1.155秒，均未乘2。开爪前等待、开爪动作、释放后等待仍是独立阶段，整个放下到Lift区间不能统称1秒。

独立MuJoCo FK复核本次100mm Lift：TCP上升99.146mm，最大横向偏移3.654mm，姿态变化0.209°，最大单关节活动范围20.002°；此为测量结果，不新增精度约束。最终双臂相对观测关节目标最大误差约0.000004°。

## 本次测试另外发现的停止原因

第一轮 `cd80dc95b619407b886f790659830ca7` 在149.133秒停止。回观测位姿后的Decisions给出unpack_result=1.00、wrapper_removed=1.00、observation_sufficient=0.92；真正失败是后续局部点云测量。

同一冻结RGBD重放：`black object on the table`和`black workpiece`均返回零分割，基础提示`black object`可得头部704个、右腕2505个桌面工件点。原局部分支遗漏基础提示，却统一报深度不足。现补上基础提示并记录分割、有效深度、去机器人、桌面及密度筛选点数；原图实际测量得到702个点。程序停止优先显示失败技能的具体原因，并保留模型原Stop文字。后续第二轮完整成功，未改变视觉判断阈值或用仿真真值替代测量。
