本次修正撤回 1096 球版本中不合理的静态大包络，运行配置改为 **1359 球**。相比最初 1362 球只少 3 个，**没有实现大幅减球**。少球候选出现新增漏面或错误自碰撞，未采用。当前模型也不是全部真实表面的严格包覆证明。

机械臂、夹爪、腕部相机仅删除被同 link 最终保留球完全包含的 70 个球。原中心、半径及球并集不变。Stand 保留原有球并集，补入官方拟合的主块 final 输出，修复已知约 16.45 mm 的缺口。新立柱按真实柱体段、末端侧壁和顶法兰处理，避免遗漏末端侧壁造成裸环。没有合并优化 history、手工调整 final 球中心/半径，或按缺口反复累加无上限小球。

新球来自固定 SDK commit `8e734f3ced1df898990bcd92de40abce475907db` 的公开 `curobo.sphere_fit.fit_spheres_to_mesh`。柱体使用一个真实等截面段的官方 final，经刚体平移复用；拟合参数、每球来源、34 个输入 mesh 和源资产哈希均存档。参数不一概称为官方默认：柱体使用 coverage/protrusion=1000/200，支架主块为 10000/10；SURFACE 的数量上限和半径分别显式记录。

低位球另有可达性证明：对 34 个运动 link 的真实 visual 和原 world-buffered 球，在所有关节角下用三角不等式求最低高度，下界保守取 127.787 mm。仅删除顶面加 50 mm 仍低于该下界的 64 个 Base 球；实际最小分离余量为 52.788 mm。该证明要求底座固定、原机器人尺寸和球模型不变，不覆盖新增长夹持物、移动底座或之后增大的碰撞球。

## 几何检查的结果和限度

保持原回归阈值不变：Base、Stand 的 raw 球外包围盒超出量分别为 15.000006、14.885881 mm，均通过原 15.001 mm 检查；撤回版本 Stand 为约 110.5 mm。**包围盒检查不等于实际曲面每处外凸都小于 15 mm。**

最终整机 zero 姿态的独立采样中，在可能可达高度内：Base 的 2305 个外露样本最大 gap 为 2.241 mm；Stand 的 1702 个外露样本最大 gap 为 6.957 mm，后者位于原有法兰。原肋板仍有约 32.455 mm 的局部外凸，Stand 原球仍有约 19.188 mm 的外轮廓外凸。这些剩余误差没有通过扩大 buffer 或更改 ignore 关系掩盖。被证明不可达的底部网格缺口单独报告。

这里的可见面和球边界统计是有限采样，开口 mesh 的内外判断存在歧义。不能据此宣称全部制造表面、任意姿态或连续执行都满足 10 mm 间距。

## 实际规划与回归

固定参数、固定场景，A 臂三个历史目标、B 臂两个历史目标各重复组成 16 项 batch；不是每臂 16 个不同抓取目标。真实调用 `plan_grasp_batch`，未驱动机器人。

| 测试 | 首次调用，含初始化 | 两次预热调用 | 每次成功数 |
|---|---:|---:|---|
| 新模型 A | 30.468 s | 6.810 / 6.874 s | 16 / 16 / 16 |
| 原始模型 B，对照 | 32.284 s | 6.801 / 7.773 s | 14 / 13 / 16 |
| 新模型 B | 30.961 s | 6.511 / 7.507 s | 14 / 13 / 16 |

B 臂部分候选失败在原模型中同样出现，两版同轮成功数一致；不声称所有 batch 必然全成功。共享 GPU 上的这组耗时不代表显著加速。

旧轨迹 1287 个不同姿态，以及新 A/B 轨迹 2189 个不同姿态均完成 CPU 检查，另各加入默认、零位姿态：没有 self sphere overlap。新轨迹最小 self gap 为 0.451465 mm，最小桌面球间距为 17.231377 mm。只检查 cuRobo 原始离散姿态，没有添加 Hermite 碰撞检查，也未改变原有执行策略。

本地完整 Python 测试为 279 passed / 56 skipped；其中 5 个缺少可选 rtree 的跳过项随后在临时依赖路径下通过，对应审计模块共 8 passed。其余 51 项 Windows 跳过的 Linux 启动脚本测试已在 Ubuntu 补跑，51 passed；Ubuntu 上的模型与查看器另为 10 passed，精确回放也通过。新增 replay 和修改的模型测试通过 Ruff。网页代码未改。

```bash
python scripts/replay_collision_correction.py --output /tmp/jev-reviewed-collision.yml
```

这是已记录输出的精确回放，不是重新运行优化器。工具检查输入哈希并拒绝覆盖运行模型；新拟合仍通过 `fit_collision_model.py` 生成独立候选并重新审查。输入 mesh 归档是按原几何操作事后重建，已在 manifest 标明。

只有 `collision_spheres` 数组改变；其余 YAML 深比较不变。SDK、算法镜像、tianji_base、skills、10 mm 阈值、seeds、buffer、self_collision_ignore 和开爪锁定值均未改变。更新模型缓存需要重新加载 JEV cuRobo 和网页后端，无需重建镜像。部署状态与镜像/配置哈希另见同目录 `deployment.json`。
