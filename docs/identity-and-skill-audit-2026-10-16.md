## 先说明清单解决什么问题

清单是任务账本：记录哪些实测物体属于原始指令、哪个正在执行、哪个已经完成、哪个暂缓、每个物体当前处于哪一段搬运。它不生成点云，不代替碰撞地图，也不证明视觉识别正确。

ID 关联是把新观测中的检测与账本里的旧对象对应起来。SAM3 的一个掩码只描述某一帧、某一视角的像素集合，既不是跨相机永久身份，也不是跨时间永久身份。仅仅给第一帧排序，不能让下一帧自动知道旧编号。

当前三种路线都涉及初始发现与抓前新观测，多物体还涉及重复抓放，中转路线必须再次抓同一物体。因此清单及其最小身份关联不是可有可无。单物体只观察一次、抓完就停止的特例可以简化，但不适合本项目的通用执行链。

清单直接用于：限制任务范围、确定数量和默认顺序、跳过完成项、保留中转身份、记录失败和暂缓、冻结放置分区容量，以及把当前目标 ID 绑定到应排除的碰撞实例层。障碍物也有感知 ID；它们不必获得搬运清单的 `#1/#2` 编号。

## 六种容易混淆的标识

| 标识 | 当前含义 |
|---|---|
| SAM3 掩码 | 某相机某帧的一次分割结果；查询别名也可能给同一物体多个掩码 |
| 当前实例 ID | 本次感知融合后新建的 `instance-…`；普通实例最初是随机 ID |
| 稳定对象 ID | 关联成功后，把本次临时 ID 改成历史 ID；任务状态和场景绑定使用它 |
| `display_id` | 人看的 #1、#2；确认任务成员后首次分配，之后保留，不每轮重排 |
| `observation_id` / `scene_token` | 分别标识观测与碰撞快照；对象 ID 相同不代表几何仍新鲜 |
| `feedback_id` / `generation` | 夹爪验收证据与会话版本；反馈不是新 RGBD，跨 reset 不直接继承证据 |

“固定 ID”与“#1”不是两套不同的物体：一个用于程序关联，一个用于人阅读。显示编号稳定依赖内部 ID 关联成功。

## 第一次清单如何形成

1. JEV 的 `bind_request` 从完整原文判断任务、路线、指定臂、目标共同属性、目的地共同属性、数量、顺序及额外环境查询。这里没有物体位置真值。
2. 初始 `observe_scene` 采集同步 RGBD，先用头部相机做发现。SAM3 使用任务提示和有限环境类别查询，包括 cube / sphere / cylinder / object，cube 最多补一次 block；容器单独查询。声明的环境颜色可补查询。不是无限遍历类别词典，也不能保证 generic object 检出所有物体。
3. 掩码只保留有限、有效、正深度；少于 30 个有效点不能生成普通实例。RGB 颜色统计、相机内外参、机器人自身模型和实测桌面用于处理当前可见返回。外参只改变坐标，不提供被遮挡表面的深度。
4. 去重、跨相机融合、机器人与支撑面过滤后，生成可见表面点云、当前实例、相机与像素来源及可测区域关系。
5. `TaskProgress.observe` 登记普通物体候选，初始 `membership=unknown`。盒子和 marker 有感知 ID，但不作为待搬普通物体登记。
6. `assess_task` 的 JEV 参数判断把候选分成 required / excluded / unknown。只有 required 才进入公开待搬清单。看到红色障碍物，不等于获准搬红色障碍物。
7. `assign_display_ids` 给首次确认的 required 成员编号：优先头部可见，再按头部相机光心到可见表面中心的欧氏距离由近到远，同距用头部横向坐标及内部 ID 稳定排序。它不是图像行号排序，也不是到执行臂 TCP 的距离排序。
8. 编号从 1 开始，完成后仍保留。默认执行剩余成员中的最小编号；明确要求“先某个、从远到近”等才采用 explicit 顺序。并列说“红色和绿色”不等于先红后绿。

未指定数量时 `requested_count=None`，数量应由实际观测和原始任务成员确定，不应假定 1，也不允许扩展到无关物体。当前全局数量截断存在分组配额缺口，详见问题 A2；不能把上述目标行为误写成已经完整验证的任意自然语言配额能力。

“盒子里的物体”使用实测容器底面与可见区域关系：物体可见点在 XY 上落入观测底面区域的比例达到 0.5，构成来源证据。这个 50% 不是“真实物体总表面至少看见一半”，也不是身份置信度。缺少唯一来源关系时不能直接认定 required。

初始化冻结后，新发现 ID 不自动增加到原始任务清单。这样可避免刚从盒中搬完目标，又把新看到的桌面障碍物加入任务。后续感知到的非任务对象仍可进入碰撞场景。

## 同一时刻：三个相机如何认为自己看到同一个物体

实现入口：[association.py](../src/jev_mujoco/association.py) 的 `associate_camera_detections` 和 [perception.py](../src/jev_mujoco/perception.py) 的 `_same_observed_instance`。

相机 3 为头部，2/1 为左右腕部；使用当前同步 RGBD 的标定变换，将掩码内点投影到同一世界坐标。每个实例组最多容纳同一相机的一个检测。已有头部检测时以头部为参考；没有头部时可由腕部证据成立，不要求三路都看到。

当前主要判断为：

- 颜色相同；三维轴对齐包围盒间的最小间隔不超过 35 mm。35 mm 不是要求相邻工件至少相距多少。
- 检查对方表面是否与本相机的前方第一深度返回冲突；至少 30 个可比点，超过 10% 被 3 mm 判据反驳则拒绝。
- 相同类别：投影到参考掩码，至少 30 点、共同视野中的支持比例至少 50%。这允许两个相机分别看到同一物体的不同面。
- 不同类别别名：还要求双向 5 mm 表面对应，各至少 30 点且占比至少 20%，双向掩码投影支持各至少 80%。
- 一个检测只能匹配一个组；匹配多个组或组内参考意见冲突，补充检测标记 ambiguous，不强行拼进去。

融合只叠加观测到的表面，再做 1 mm 点去重；融合不意味着补全背面。三个相机分别看到不同的对象也不会仅因数量相同就按检测序号配对。

当前去重并不保证“一实体永远一实例”：同相机 cube / block 别名有确认缺口 A3；极端相向视角中，“一个物体的互补表面”与“两个邻近遮挡物体”可能不可辨识，见边界 B1。

## 不同时刻：怎样给新掩码恢复旧 ID

实现入口：[association.py](../src/jev_mujoco/association.py) 的 `associate_inventory`。

### 先限制候选与对象状态

普通 cube / box / sphere / cylinder / object 都归为普通物体角色，再按颜色共同竞争，避免 SAM3 形状标签改变导致身份断开。bin、marker 保持各自角色。这里没有纹理特征网络，也没有 OpenAI 自动认同一物体。

每个历史 ID 的关联状态是 unmoved、held、released 或 placed。先关联尚未搬运的对象、持物及目的区域，再关联刚释放和已放置的对象。已搬对象不能回旧源位置抢走另一个相同工件的 ID。

### 未搬运对象

先检查已知颜色在历史和当前是否各只有一个相应角色对象，旧标签也必须具体。成立时用 `unique_appearance` 保留 ID。这实际上是“唯一已知颜色”的简化假设，不是完整外观识别：不会分析商标或纹理；同色但不同形状仍可能相互竞争。此分支不要求掩码或表面重合，允许物体移动。

非唯一颜色时，优先比较固定头部相机掩码。标定 ID、内参、相机位姿和图像尺寸必须相容：

`IoU = 交集像素数 / 并集像素数`

合格配对要求 IoU ≥ 0.5。若存在多个合格候选，仅当第一名比第二名至少高 0.15 才有唯一胜出者；而且旧→新和新→旧两个方向必须互相选择，避免两个旧 ID 争同一检测。不会简单按最近距离强行一一配完。

只有头部掩码不可比或缺失时，才退回三维可见表面：双向最近邻距离 ≤5 mm 的支持率均至少 20%，且配对唯一。如果头部掩码可以比较但 IoU 不足，不用表面匹配把它强行救回来。

### 已持物对象

关联参考为“抓前实测可见点云，经闭合时 TCP 变到工具系，再用当前 TCP 变回世界系”。它是刚性持物位置预测，假设没有滑移；不是当前相机实测，也不是隐藏物体真值。只在预测位置寻找表面支持，不同时保留旧源位置作为另一个候选。

正常成功流程抓后到放置不采 RGBD，因此这条分支不是每次 verify_grasp 都在跑。夹爪 held 证明持有状态，不证明拿对了哪一个 ID；持物记录把已选目标的历史身份带到下一阶段。

### 刚释放对象与已放置对象

先关联它上次完成阶段的目的盒/区域，再找当前测得位于该区域的同色候选。要求至少 50% 可见点 XY 位于目的区域；不是最终落稳证明。

刚释放时，在新位置还没有稳定掩码历史，不能用旧源掩码 IoU 去找。算法先匹配所有其他同色历史对象；它们都得到唯一对应后，如果目的区域只剩一个候选，才把刚搬对象旧 ID 赋给这个候选。

已放置对象如果已经有目的区域的实测历史，之后可以在该处继续用头部掩码/表面/唯一颜色规则。盒→桌→盒第二段选择新目的盒后，关联仍使用上一段已完成的桌面位置，不提前到最终盒中找它。

### 对不上的处理

- ambiguous：有支持配对，但不能唯一确定。
- unsupported：同色对象存在，但缺少足够位置/表面证据。
- unseen：没有相应当前候选；不等于物体已经完成或不存在。

不会静默删除旧完成记录，也不会因为新检测序号相同就继承身份。JEV 可显式判断某个未完成、可互换的歧义集合是否允许重枚举；已完成对象、已完成中转第一段的对象不能借此换 ID。重枚举也不是声称恢复了旧物理身份，旧记录保留 superseded。

关联成功后 runner 同时重命名当前对象 ID、掩码字典键和对象间关系中的 ID。历史点云留在 identity history 供关联，不当作当前实测障碍体素。身份不确定的候选不会默默加入新清单；所需对象缺失可能使本轮建图拒绝，后续恢复由 JEV 判断。

## 三个相同物体的完整例子

| 时刻 | SAM3 当前检测 | 关联依据 | 清单结果 |
|---|---|---|---|
| 初始 | 源区域三个红工件 | 头部由近到远首次编号 | ID-A=#1、ID-B=#2、ID-C=#3，均待搬 |
| 第一轮抓前 | 返回顺序可能变成 C、A、B | 固定头部掩码 IoU，双向唯一 | 仍是原 #1/#2/#3；不会按本轮顺序重编号 |
| 搬完 #1 | 开爪反馈确认释放 | 当前执行绑定为 ID-A | #1 已搬运；#2/#3 未搬运 |
| 第二轮抓前 | 源区域两个，目的区域一个 | 先匹配旧源位置 B、C；目的区剩余唯一候选归 A | #1 在目的地当障碍；继续 #2 |
| 有一个同色工件被遮住 | 无法匹配所有同色同伴 | 不足以唯一归属目的区候选 | 未解决项保留 unknown；不能据编号猜身份 |

掩码数量有用，但只看总数不够：两帧都三个掩码，并不能排除重复分割、漏一个又多一个，或抓错同色对象。当前 `transfer_count_evidence` 还要求头部可见 ID 总集合不变、来源恰少当前目标、目的恰多当前目标、其余 ID 的区域关系不变且无关联未知。条件不足返回 unknown；该辅助证据不负责写入完成状态。

完全一样的工件在不可见期间互换位置，没有额外可观测特征时，单靠 RGBD/SAM3 不能保证恢复物理身份。现有规则适用于“未搬工件不大幅移动”的实验假设，不应宣传为通用跟踪准确率保证。

## 清单具体保存什么、何时算完成

| 内容 | 当前用途 |
|---|---|
| 内部 ID、display_id、membership | 身份、显示顺序、是否获准搬运 |
| 类别、颜色、来源位置/关系 | 解释原始任务归属；已选择/完成项保留来源语义 |
| 最近属性、最近实测位置、观测引用、可见状态 | 描述新的测量，避免用历史位置冒充当前位置 |
| selected / completed / deferred / pending / superseded | 当前选择、终态、暂缓、中转、重枚举历史 |
| 关联状态及关联证据 | 已匹配、不可见或歧义，以及使用了哪条规则 |
| 目的 ID、stage_index、completed_stages、阶段执行臂 | 单段与中转路线，第二段仍抓同一 ID |
| feedback_id、失败原因、尝试次数 | 可复核的动作验收与恢复依据 |

大图、掩码和点云保存在观测数据中，以 observation reference 关联；不把所有像素重复塞进 JEV 的文本清单。

持物 verified 在 holding context 中维护，清单 record 不一定单独改成 held；图像标注会依据有效 holding 显示“夹持中”。`verify_grasp` 只按命令/位置/稳定窗口判 held / empty / unknown，不观测、不建立 attachment。

`verify_place` 要求完整执行、已释放、开爪且当前反馈 empty；成功后记录 release feedback，把当前 ID 加入完成记录。它符合当前简化要求，但只证明“执行了释放且夹爪空”，不证明最终落点、落稳或没有弹出区域。最后一个物体完成后不会为了清单再强行拍照。

盒→桌→盒第一段成功只新增 completed_stages，状态变 pending、stage_index=1；不进入最终 completed_ids。第二段仍用原 ID，阶段允许另选执行臂。

已完成项不删除、不重新编号、不再选择，但下一轮实测后仍作为障碍。暂缓项保留未完成原因。清单初次声明的放置数量按阶段/目的地冻结，避免搬完一个后重新缩小 N、改变剩余区域划分。

标注来自当前帧真实掩码，显示名称、#编号、内部 ID 和状态；普通障碍显示“障碍物·不搬运”。原始 RGB 没有被写入感知标签。未分析的新帧不能借用旧掩码当本帧识别结果。

## ID 关联、场景变化与准确率不是同一件事

身份回答“是否是旧物体”；变化检测回答“它或环境是否移动”；完成判断回答“本次任务动作是否达到验收条件”。三者可以有不同阈值，不能混成同一个重叠百分比。

当前固定头部变化检测使用：掩码 IoU 0.75、中心偏移 3 px、深度差 10 mm、RGB 模糊后最大通道差 30/255、变化比例 8%、至少 30 像素、机器人遮挡比例 20%。明确深度变化，或掩码和 RGB 同时变化，支持 changed；证据冲突/不足支持 unknown。当前正常流程仍每轮抓前重建，不以 expected_only 跳过建图。

0.5 的身份 IoU、0.75 的变化 IoU、0.95 的别名覆盖率、0.5 的区域 XY 比例是不同判据。物体上的 confidence 是 SAM3 分割分数；`score_is_probability=False` 表明关联分数不是概率。JEV 的 confidence 也不是经过真实机器人身份数据校准的准确率。

当前版本没有足够标注的真实重复工件数据支持一个可靠的 ID 准确率数字。本次反例也证明不能说“100%不会拆分/混淆”。历史离线报告不等于当前部署的统计准确率。

## questions 审查覆盖

实际问题主要在 [decisions.py](../src/jev_mujoco/decisions.py) 和 [task_request.py](../src/jev_mujoco/task_request.py)。JEV 读取压缩状态、问题 instructions / criteria 及 Registry contract；不会自动把每份人读 SKILL.md 全文当输入。

TypeSafe 同请求中的问题独立使用共同输入状态，不能假定后一问已经知道前一问的答案；选项缺失也不能靠模型聪明补出。审查依据：[State](https://docs.typesafe.ai/concepts/state)、[Choice](https://docs.typesafe.ai/primitives/choice)、[fan-out](https://docs.typesafe.ai/patterns/fan-out)。当前主提问已按共同状态解释，但消费者仍有下列缺口。

| 提问族 | 已核实内容与边界 |
|---|---|
| bind_request | task、route、arm、scope、visual_semantics、源/目的属性、quantity、selection_order、环境颜色角色；保留完整原文，属性为共同感知查询，不代替成员判定 |
| assess_task | progress、逐实例 membership、unseen relevance；检查来源、原清单与完成历史；发现 A2 / A4 |
| choose_target | required / 未完成 / 未暂缓候选，missing / ambiguous，默认编号顺序及中转同 ID；集合选择不设置信门槛 |
| choose_destination | 依据阶段限制 bin / marker；中转最终盒不能是初始源盒；有 missing / ambiguous |
| choose_arm | 用户指定直接绑定；默认依据单臂中心可达表；可达不冒充完整抓姿/路径可行 |
| choose_skill | 16 个 contract 加 stop 都提供；模型选择后校验，不替模型自动选下一项；旧独立 place 文案不一致 |
| choose_recovery | JEV 选择 reobserve / retry_grasp / retry_place / defer / retry_plan / stop；原失败、预算、持物和场景证据在输入中；执行算法不自行恢复 |
| choose_identity_policy | preserve / 受限 reenumerate_ambiguous；不允许抹去完成/中转历史 |
| choose_visual_purpose | 用已有证据判断语义或变化辅助目的；不负责凭空确定身份 |

## 坐标、单位与放置的专项核查

当前没有发现第二处已证实的夹爪末端/安装 TCP 混用。已读 A/B 命名与 FK、米/毫米、角度/弧度、四元数 xyzw/wxyz、世界/工具点云变换、抓姿转换、世界 yaw 和释放端点检查。

令安装 TCP 的世界位姿为 `(R,t)`，用户使用的固定夹持参考点在 TCP 系中为：

`g = [0, 0, 0.185] m`

夹爪参考点世界位置为 `p_g = t + Rg`。指定放置 XY 为 q，则：

`t_xy = q_xy - (Rg)_xy`

规划器仍接收安装 TCP；用户期望到达 q 的是夹爪参考点。它不取物体可见点云中心，避免视角变化让“末端”漂移。

附件球在同一 TCP 系中的中心/半径为 `(c_i,r_i)`，支撑面高度 h，则：

`t_z = h + 0.015 - min_i((R c_i)_z - r_i)`

这是上传碰撞球最低点距支撑面 15 mm。10 mm 是 hard clearance；实际执行端点另有 2 mm 位置容差及姿态检查。松爪前用实际 TCP 和同一组上传球重新计算间距；不能用命令目标代替实际到位，也不再叠加盒沿等额外高度。

yaw 为世界 Z 轴左乘 `Rz(theta) R_grasp`，18 个候选 0°–340°、间隔20°，保持抓取滚转/俯仰。每个位置先做 IK，再查完整轨迹；当前位置耗尽才换位置。N=1 用区域面积中心；N>1 用不小于 N 的最小偶数等面积径向分区中心，仍做尺寸、边界、占用及轨迹碰撞检查。分区中心本身不是无碰撞保证。

GraspGen 的 grasp frame 到 EE 的 195 mm 与机器人 TCP 到夹持参考的 185 mm 是两个已明确命名的转换量，不能因为数字不同就直接改成一样，也不能把它们作为环境物体真值。

## 已证实问题与建议修正边界

### A1 — P1，放置执行沿用旧的持物与夹爪反馈

[runner.py](../src/jev_mujoco/runner.py) 的 `prepare_attachment` 会检查当前 held；但 `execute_place` 只检查缓存 verified/attached。`measured_state` 又把闭合时双臂夹爪角度覆盖到实时 robot_snapshot 中。

A/B 两臂均复现：当前执行臂 0.8 rad 被判 empty，execute_place 仍进入 approach 验证，发送缓存 0.48 rad；对侧实时0.1也变成缓存0.0。复现到第一次验证调用即停止，无运动。

建议：持物执行入口及有限阶段边界检查当前反馈；保持“真实测量”与“规划锁定的模型参数”分开。空/未知返回明确证据，由 JEV 选恢复，不在内部自动重抓。

### A2 — P1，只有总数上限，分组数量可被静默破坏

要求2红1绿，观察到3个近红、2个远绿，注入 JEV 五个都 required 后，默认 inventory 分支按距离只留总数3，变成3红。完成这3项并注入 complete，终态接受 succeeded。

这证明消费校验没有保存/核对各组配额，并且会覆盖成员判断；不表示真实 JEV 每次都会给这种答案。建议保留语义组数量约束，冲突返回重新判断，不以全局截断替代分组选择。不要硬编码红绿优先。

### A3 — P2，同类查询别名可把一个实体拆为两个实例

存档 RGBD 的头部为360×640，同一红物体掩码1162px，cube与block合成结果平移2px，双向覆盖93.46%，低于同相机去重95%。后续同类实例又被通用语义去重跳过，生成两个ID。

两实例有1019/989个实测点，947点坐标完全相同，5mm支持率100%/97.17%，却没有 duplicate 或 unresolved 报告。此实验仅替换分割输出，没有改 RGBD/标定，也没有声称真实SAM3已输出过这两个掩码。

如果后续建图仍出现这对实例，两个实例层共享实测返回，只排除选中ID会留下重叠障碍；这是消费代码的条件性后果，未实跑 GPU 证明必然无解。

建议统一处理同相机别名的像素归属和强实测表面重复证据；不能简单降低距离阈值，把两个相邻同色工件合并。

### A4 — P2，成员与完成判断被当作无门槛偏好

`assess_task` 的 progress/member/unseen 与集合 choose_target 使用 require_confidence=False。配置门槛0.6时，注入0.01的成员/完成回答也被接收；可构造要求红色却排除唯一红色、零完成记录仍接受complete，或绿色被错判required后允许选中。

这是低置信答案的消费者边界实验，不是实际模型错误率。建议区分“已确认等价目标的顺序偏好”与“决定搬不搬、是否完成”的身份判断；后者不应无门槛放行。

### A5 — P2，修改成员归属后旧编号仍占数量额度

数量1，A先required获得#1，B excluded；执行前合法修正为A excluded、B required后，旧record的#1仍占名额，程序把B又改成excluded。最终为needs_attention，不是误报成功。

建议显示编号只负责稳定展示，名额根据当前有效required成员计数；不要让历史显示编号反向覆盖JEV成员决定。

### A6 — P2，抓取总等待时限遗漏 IK

plan_grasp 的 evaluate_arms 未传 timeout_s，后续轨迹调用才给完整 plan_timeout_s。实测把上限设0.1s、假IK耗时0.3s，真实Runner仍返回succeeded（本次约0.30s）。与文档“总等待上限覆盖各批”不符。

建议使用同一次规划的截止时间，IK与轨迹共享剩余等待预算。等待取消不等于强行中断GPU请求，迟到结果仍不能执行。

### A7 — P2，独立 place 的提示与实现矛盾

choose_skill 仍写“独立place需本轮观察目的地”；当前runner、README和skill流程是复用同会话已验证持物保存的观测与场景，不再RGBD。需要统一提示，不应靠模型自行猜哪份说明有效。本次未证明该文案已经引发某次现场误调用。

### A8 — 较低优先级，英文数词候选覆盖不足

quantity_candidates 仅支持英文one–ten；eleven没有数量问题，twenty-one只有1，a dozen也只有1。原文保留可能让后续JEV避免误搬，但硬数量约束已经不完整。中文当前用例不因此直接失败；应明确支持边界或补齐数词候选，不能把缺选项说成模型判断差。

## 设计限制和诊断问题

**B1：跨相机不可辨识。** 合成两台相向相机分别看到相隔20mm的同色同类面，另一面都在本相机第一返回后，投影也落入掩码，当前算法会合成一组。该相机变换有效，但没有证明是当前双臂可到达视角；它界定一般性保证的上限，不是已发生部署事故。强行要求共同表面也会误拒同一物体互补视角，不能简单改一个阈值宣称解决。

**B2：唯一颜色假设。** 历史与当前各只有一个具体同色普通物体时，哪怕相距1m、表面重叠0也可保留ID。旧物体离开、另一个同色进入不能由这些证据唯一排除。这是当前简化设计，不是几何确认。

**B3：全无效帧诊断。** 两帧均零有效深度、无实例掩码、RGB相同，可返回expected_only。应改为观测不足unknown。当前每轮抓前仍重建，此问题只证实诊断字段误判，不能说它绕过了当前建图。正常从有深度突然变无深度是另一种输入。

## 2026-10-17 开源关联方案核查

当前服务调用 SAM3 `segment_text`：每张图独立分割；全局ID由项目固定清单和RGBD关联维护。RGB特征是归一化中位颜色，几何证据是标定后的表面重合、候选清单和动作后的预测位置，并非完整外观识别或视频追踪。人体视觉还会利用轮廓、纹理、遮挡前后的连续变化和动作上下文；不能把现有三维颜色向量称为等价能力。

- [SAM3 官方视频跟踪](https://github.com/facebookresearch/sam3)：已有文本/视觉提示的分割与跟踪接口。适合优先验证每个相机连续视频中的身份保持；跨头部和双腕仍需共同世界坐标、固定全局清单与动作记录。当前集成没有视频会话，未新增或升级模型，未在本项目测得跟踪延迟。
- [FoundationPose](https://github.com/NVlabs/FoundationPose)：物体6D位姿估计与跟踪；模型式需要物体模型，无模型式需要参考图及重建准备。不能直接把仿真隐藏物体网格当感知输入。对当前少量物体并非直接替换ID字典就能接入。
- [M3T / ICG](https://github.com/DLR-RM/3DObjectTracking)：利用轮廓、RGB/深度的模型式跟踪，适合已有物体网格和初始化的连续图像。当前仅初始可见RGBD的条件仍缺少其模型准备。

结论：存在开源方案，但不能声称当前项目已经接入。先用保存的连续相机帧对SAM3跟踪做单相机身份/延迟验证，再判断是否值得替换当前逐帧接口；不要为这些简单场景一次加入多套跟踪器或以猜测匹配填补缺失证据。当前原始绿/红双物体实跑已验证固定清单及两轮ID关联，但不证明任意遮挡、同色重叠及大视角跳变都已解决。
