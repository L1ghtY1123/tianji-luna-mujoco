# 物体清单、观测标注与 skill 审核（2026-10-15）

本次基线为 `5536cea`。逐项核对实际 Registry、contract、runner、感知与清单实现；以下描述实现边界，不把单元测试当作机器人运动成功。统一技能说明仍是 [JEV skill 手册](jev-skills-guide.md)。

## 1. 清单怎样生成和计数

1. 初始头部 RGBD 经 SAM3 得到检测掩码，有效深度给出可见表面。一个掩码不是永久身份；同一物体被不同提示或相机重复检测时，先按掩码/几何证据去重、合并。每个独立实例获得内部 ID。盒子、标记、障碍也有 ID。
2. JEV 根据原指令、可见属性和实测关系，把可搬对象判为 `required`、`excluded` 或 `unknown`。例如“把盒子里的物体搬到黄色区域”：盒内对象才是目标，桌上其余对象是障碍；不能因为发现了它就把它加入搬运清单。来源不明保留 unknown，不能猜成盒内物体。
3. 只有 required 成员分配人看的任务编号 1、2、3……。按首次头部观测的距离由近到远排列，之后不随相机检测顺序重新编号。指定 N 个但未指定个体时，按这个顺序取 N 个；其余对象仍保留障碍身份。指令指定个体/次序时，由 JEV 按原文绑定。
4. 三条搬运路线的初始任务成员确定后，不因后续又发现对象而自动扩大范围。已完成项保留在清单历史中，从待办集合移出；计数依据这份记录，不是拿当前掩码数量相减。
5. `verify_place` 完整执行、释放记录和实际开爪反馈通过后，才完成本阶段。按用户选定的简化验收，完成表示“释放已确认”，不表示最终落稳位置已由视觉验证。另存 `destination_visual_evidence`。

| 记录/展示状态 | 意义 | 是否计为整体已完成 |
|---|---|---|
| observed / 未搬运 | 已确认属于任务，尚未搬运 | 否 |
| selected / 当前目标 | 本轮绑定的目标 | 否 |
| verified holding / 夹持中 | 夹爪反馈确认持有，绑定同一 ID | 否 |
| pending / 中转完成·待下一段 | 盒→桌→盒的桌面中转完成 | 否 |
| completed / 已搬运·释放已确认 | 本物体所需路线阶段均通过释放验收 | 是 |
| deferred / 未完成·暂缓 | JEV 决定暂缓，保留原因 | 否 |
| superseded / 身份待确认 | JEV 显式要求对歧义待办重新编号，旧记录留历史 | 否 |

同一 ID 保存已知属性、首次/最近观测依据、任务成员角色、显示编号、阶段、执行臂/目的地绑定、失败次数/原因和完成记录。掩码、RGBD 与点云放在对应观测档案中，不把所有大数组重复塞进 JEV 上下文。清单与碰撞场景是两份不同数据；场景只排除本轮目标，其他实测对象仍是障碍。

## 2. 为什么仍然需要 ID 关联

SAM3 重新分割只返回当前图像的掩码，不保证这次的“第一个”就是上次的“第一个”。因此固定编号不能代替关联。这里有两种独立关联：

- **同一时刻跨相机**：用注册深度得到共同坐标下的可见表面，并核对重投影、掩码覆盖和深度一致性；同一物体只计一次。不要求三路都看见。
- **不同时刻**：把当前检测对应回历史 ID，之后才更新该 ID 的位置和观测依据。新掩码不能凭序号占用旧身份。

跨时刻的有界规则：先处理盒子及未搬运的静止同类，再处理当前持有/已释放物体。特征不同且当前/历史中同类别同颜色各只有一个时，使用唯一外观候选；同类多个物体在头部标定可比时，以掩码 IoU ≥0.50、最佳候选比次优至少高 0.15，且互相唯一的配对为依据。头部不可比较才使用 5 mm 邻域内双向实测表面覆盖（各至少 20%）等已有几何条件；不能用相机当前检测次序配对。

持有状态只搜索与抓取参考、当前 TCP 推导位置一致的候选。释放后的目标不再争抢原来位置的同类对象：先配对其余未搬运对象，再在本次目的区域筛选剩下的候选（至少 50% 可见点的 XY 位于实测区域内）。同类仍不唯一就保留歧义；不自动造出新目标、改旧 ID 或宣告完成。目的区域投影比例不是整物体可见率，也不是识别准确率。

“是否移动”另用掩码、RGB、深度联合比较。当前变化判据包括 IoU 0.75、中心位移 3 px、3×3 平滑后 RGB 通道差 30/255、深度差 10 mm，以及区域变化面积；这些初始工程阈值与身份匹配门槛不同。身份关联报告方法、候选和分数；**没有标注真机数据集支持，不能声称准确率达到某百分比**。

## 3. 每次观测的 RGB 怎样标注

- 头部与两个腕部均支持：名称、完整内部 ID、任务编号（仅目标）、状态；盒子与障碍也显示 ID。
- 框来自该相机当前 `instance_masks`；标签坐标依各图原始比例，头部 16:9 与腕部 4:3 不混用。该路看不见则不画框；不把别路框投到此图，不从仿真模型取框。
- 原始采集和分析完成分别归档。仅采集的动作结果帧显示“未分析：尚无本帧掩码与 ID 关联”；没有为了画框暗中多调用 SAM3。JEV 选择几何/场景分析后，同一帧生成新的标注版本。
- 持物验证、任务归属、选中、完成、暂缓变化时，如果当前帧已经关联，刷新其标签状态。新采集尚未分析则不能套用上一张图的物体位置。
- 原 RGB 作为算法输入不变；SVG 内嵌原图和展示标签，JSON 保存状态。实验事件 `observation_annotated` 提供三路可查看/下载的 SVG，历史版本不覆盖。
- 每秒刷新的视频预览不是任务观测，也没有逐帧跑 SAM3；标签在“最近任务观察”与实验回放中查看。

## 4. 没点名的物体怎样发现

目前确实使用有限提示集合：每个被分析相机补查 `cube`、`sphere`、`cylinder`、`object`，结合用户指定的类别、颜色和环境描述；cube 没有限色或无结果时，仅补一次对应的 block 同义词。需要盒子时另查 open box。不是无限枚举类别，也不是发现一次失败就不断扩词。相同帧/提示使用 128 项有界缓存。

同一物体被多个提示检测时按掩码和可见几何去重。由检测得到的实例不自动成为任务成员。障碍 ID 与目标使用同一套关联，没有增加另一个识别网络或 OpenAI 请求。

这套提示覆盖当前受控实验常见工件，**不保证识别任意未知物体**。语义建图模式只保留识别实例与桌面 cuboid，未分割背景会被删除；初始观测运动图仍保留有效深度背景。声明/历史对象缺失会返回证据不足，但“从未识别过的未知障碍”仍是能力边界，不能说系统已经知道场景中的所有物体。

## 5. 释放高度以 attachment 球底为准

对每个候选 yaw，使用实际上传的球心 `c_i` 和半径 `r_i`：

`TCP_z = measured_floor_z + 0.010 - min((R @ c_i).z - r_i)`

保持 roll/pitch；18 个世界 yaw 只改变方向。盒内用当前实测盒底，桌面区域用实测支撑面。开爪前以实际 TCP 重新变换同一组球，位置/球底间距误差须 ≤2 mm、姿态误差 ≤2°。不另加盒沿高度、体素补偿或 clearance；无解返回 JEV。

球是有限可见表面的保守近似，不能把球底说成物体真实底面。旧 direct 的预测体素位移仍用独立 `nominal_object_floor_gap_m`，不把球底间距当成物体自由落下的距离。
