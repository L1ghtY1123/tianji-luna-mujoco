## 故障证据

- 未写数量时，旧代码仍人为提供 quantity=1 候选。本轮去掉无字面数量时的数量问题；目标成员仍由 JEV 按指令和实际观测确认。
- 完整隔离复现发现“红色和绿色”被旧提问归为 explicit 顺序，已确认两项成员后仍连续 target_ambiguous。修正顺序语义后，普通并列按清单编号；明确先后仍由 JEV 理解。5 项真实 JEV 逐个目标重放、10 项请求烟测通过，证据在 `order-results/`。
- 原生产任务每处 18 yaw，边界筛选后两处共 6 个目标，全部在含持物碰撞 IK 阶段被拒绝，没有进入放置轨迹规划。旧 UI 仍停留在 prepare_attachment，并把 IK 显示为轨迹批次，容易误读。现在记录实际阶段、IK 残差和计数，错误结论区分 IK 拒绝与轨迹失败。
- 新完整隔离复现得到 36 个区域合法候选、全部 held IK 拒绝。精确重放发现近收敛解世界碰撞成本为零，但自碰撞成本恒定；两个持物球与 gripL_Link4_R 的末端机器人球重叠约 3.2–3.6 mm。实测点距 Link4_R STL 最小 11.735 mm；两持物球到真实 STL 仍有正间隙，说明该例为机器人球外凸造成的假碰撞，不应通过删除 Link4 检查或减少持物不确定性解决。

## 夹爪 Link4 局部重拟合

只替换四个夹爪 Link4，每个从4球改为14球，总数309→349，最大半径18.877 mm（原最大20.562 mm）。同名连杆在双手间复用模板；手内按既有张开夹爪 Base 坐标 Y 镜像，再映回各连杆坐标。模板来源为项目侧确定性三角片包围球拟合，不是官方 MORPHIT 输出；其他连杆、碰撞 buffer、忽略关系和关节限位未改。

独立递归包含检查覆盖完整 collision STL 表面及内部体积，也覆盖完整 visual OBJ 三角面；OBJ/STL 导出存在亚微米舍入差，最终统一加1 µm资产余量。该证明只适用于本轮四个刚性 Link4，不能扩大到整个机器人。对应记录的 attachment 与机器人球 CPU 最小间隙69.7466 µm，FP32重算69.8054 µm，GPU 精确重放无自碰撞；此间隙只描述当前持物，不保证任意新抓姿。

早期349球候选虽通过持物 IK，却使张开夹爪的左右 Link4 球相互重叠3.925 mm，离线工作空间全被拒绝，候选未部署。最终拟合加入开爪镜像中面约束，后处理后的每侧实测间距0.976386 mm，两侧球净距1.952772 mm；默认/零位及观测位姿回归通过，再分别验证两臂工作空间首1024候选恢复可达点后才完整重建。生成器在覆盖扩半径后另检查最终半径、附件/中面正间距和350球预算，避免只验证优化前的约束。不能用持物单姿态验证替代张开模型验证。

复现入口为 `scripts/refit_link4_collision.py`，冻结几何与实测约束见 `resources/curobo/link4-refit-20261016.json`，独立覆盖证书入口为 `scripts/audit_link4_coverage.py`，完整失败输入重放入口为 `tests/recorded_carrying_ik_gpu_probe.py`。最终 YAML SHA256 为 `3b2566219c97f5570f3d5c1dec1618f08b215004d29012a36f9d9476255debe6`。
