# 清单、图与视觉证据的实际关系

本说明针对 2026-10-28 当前实现，区分已实现行为和未验证的泛化能力。

## 整体关系

控制关系和观测内部数据流分别见 [统一架构说明](object-tasks-and-recovery.md)。总编排控制所有技能；SAM3 和 Decisions 属于被调用技能内部的数据处理及判断，不能画成与编排独立运行的流程。

任务目标是外部约束；清单是持续维护的状态；图是利用该状态采取行动的策略。清单和编排不是互相替代的两种顶层控制器。当前初始 Responses 在同一请求中输出候选清单、任务要求 和全任务图，随后由图中的观测与清单确认能力核验，不能把候选当成事实。

## 三种框，以及框的使用者

| 类型 | 坐标或身份的来源 | 图片由谁绘制 | 发送/使用者 | 不代表什么 |
| --- | --- | --- | --- | --- |
| Responses 初始参考框 | Responses 的实体描述、相机编号及归一化 bbox 提议；运行时分配永久 ID | 程序 | 随参考 RGB 发送给 Decisions | 不是分割掩码，不是已证实身份或三维边界 |
| SAM3 当前候选框 | SAM3 掩码的二维外接矩形 | 程序 | 随当前 RGB 发送给 Decisions，定位要回答的候选 | 候选编号不是永久 ID，盒子框内有包裹不代表包裹属于盒子掩码 |
| ID 身份结果框 | 已接受的 ID 与当前实例掩码对应；容器可有严格的静止测量对应证据 | 程序 | SVG 供人审计；运行程序使用底层对应、掩码和几何 | SVG 本身不再喂给模型，不证明夹持/完成或地图已发布 |

模型输入页和相机卡片读取真正归档的请求图片。旧实验结果图保持原样，不给未确认的候选补造 ID。相机卡片分别说明 RGB 来源、框来源、身份来源、去向，并展示 参考框与候选框输入及原始判断。初始参考框可能只有一个参考视角；当前候选框可以在三路相机都有。参考图未画某个视角的初始参考框，不等于没有发送那一路的 RGB。

## 为什么分割不能替代身份

SAM3 回答的是“哪些像素属于本次提示对应的可见区域”。例如同一粉色包裹在头部是 C2，在左腕是 C4；下一次分割候选可能重新编号。它不维护“这个包裹曾经搬过、现在完成了吗”的任务账本。

永久 ID 使多个视角、不同时间、目标点云、碰撞层与动作记录能够指向同一实体。否则可能把同一件物体重复计数，把另一个相似物体当成已搬过的物体，或把新掩码更新到错误的碰撞层。VLA 输入和输出是不同实体：包装件退役，产物得到新 ID，并保留输入—工序—输出关联；不能把粉色 ID 直接改成黑色。

Decisions 比较当前 SAM3 候选的 RGB 主体与初始/产物历史参考，判断是不是同一个实体。运行时只将通过门槛且不冲突的判断绑定到 ID，然后按 ID 合并跨相机实测点，保留相机/像素来源。同相机的相同表面不能分给两个不同物体。未知候选保留诊断，但不进入该 ID 的地图。

当前身份流程并非完全不使用深度。RGB 是视觉判断主要输入；应用还提供标定 RGBD 的候选世界位置/边界作为辅助上下文，使用掩码、深度、标定做几何融合和严格的静止容器对应。模型不能用语义判断取代数值几何检查。单纯同色、同位置或曾执行抓取，均不能单独证明身份。

## 每个阶段做什么、为什么

1. **任务入口。** 输入人话任务、三路原始 RGB、工作空间/不可见配置区域/技能合同。Responses 输出候选清单、不可变任务要求和全任务图。目的：在低调用次数下将对象、目标、数量、处理需求和恢复条件一起考虑。
2. **observe_scene。** 由图显式调用；复用仍有效的同次采集或按参数 fresh 采集。SAM3 产生掩码；Decisions 关联身份并判断可见性与是否存在未列出的任务候选；数值代码生成实测几何。目的：把自然语言提议落实到可规划的物理实体，不把模型框当点云。
3. **confirm_inventory。** 由图显式调用；输入当前关联观测及 任务要求，Decisions 判断来源、目的地、目标成员关系，代码按确认清单冻结数量和排序。输出已确认清单，或 unknown/failure。该能力不移动、不拍照、不重试。目的：避免使用未经确认的初始猜测开始搬运，并使确认失败进入图的补观测分支。
4. **逐对象执行。** 图可循环已确认的 ID，也可写显式实体节点。选择目标、目的地和臂；模型选择全局/局部建图范围；技能生成抓姿、求 IK/轨迹、执行和核验。清单记录每个 ID 的动作和证据。目的：动作顺序可变，而坐标、碰撞及状态版本检查有稳定边界。
5. **动作后判断。** 根据所调用能力，Decisions 核验脱离夹爪、桌面/容器关系、处理产物或图条件；数值代码核验配置 XY 区域、姿态、实际关节与地图新鲜度。不同问题不能共用一个“看见了”的结论。复用同一图片不等于复用模型回答。
6. **verify_task_completion。** 图内能力，检查每个输入及产物的完成账本、各条完成条件、需要时的来源完整性、最终实际双臂位姿。视觉不足返回 unknown；后续动作使完成证明失效。目的：已执行完动作但缺证据时，仍可由原图选择补观测，而不重放已完成的物理动作。

图的 `if`、有界 `retry`、目标循环和显式修订均由 Responses 生成。Decisions 解释事实/条件或提出允许的操作选择；执行器不私自添加观测、回位或搬运。如果原图没有可用分支，Decisions 可判断是否确需 Responses 修订；这仍是例外路径。图可以选择停止，缺少安全可执行的观测动作也仍可能需要外部处理，不能承诺所有遮挡都自动解决。

## 截图中只有头部 ID 框的证据

实验 `7dc80ee07b3c42efba9155ba8447fc08`，采集 `rgbd-2-156a856e650c428bad1439efd7a5b827`，Decisions 事件 13，结果标注事件 26：

| 候选 | SAM3 分数 | Decisions 原始输出 | 最终关联 |
| --- | ---: | --- | --- |
| 左腕盒子 C3 | 0.89453125 | 选左盒，confidence 0.50 | 低于 0.80，未纳入 |
| 左腕粉色物体 C4 | 0.9375 | 选粉色物体，confidence 0.66 | 低于 0.80，未纳入 |
| 右腕盒子 C5 | 0.83984375 | 选右盒，confidence 0.71 | 低于 0.80，未纳入 |
| 头部 C0/C1/C2 | 0.90625 / 0.91796875 / 0.9375 | 同次采集对应谓词均为 1.00 | 纳入 |

因此既不是腕部没有 RGB，也不是 SAM3 没检测到。旧展示把“候选存在、身份未确认”隐藏在调用详情里了。相似盒子跨视角的身份问题仍是模型可靠性限制，不能从清晰 RGB 推断它必然给出高置信度。服务没有返回模型内部推理，不能虚构它为什么犹豫。

冻结请求的逐 ID 谓词比较中，左腕粉色身份可达 1.00，但两个盒子仍有拒绝/冲突。此诊断未改写旧实验、未降低门槛、未冒充物理执行通过。

## 多物体与泛化边界

当前图面向整个任务，清单面向每个实体。初始 Responses 为每个候选输入 ID 输出独立的 `object_task`，其中包含独立 任务要求 和 body 物体编排；每个对象有独立进度、产物和完成证据。共享的臂、地图、先后顺序及最终回位由全任务图统筹。并不是清单中每件物体各自再调用一次 Responses。

每个输入条目现在拥有独立来源、最终目的地、processing 和完成条件，处理产物沿输入谱系继承相应要求。实现与验收边界见 [独立物体任务](object-tasks-and-recovery.md)。普通单目的地抓放不依赖粉色、蓝盒或 VLA；实际成功率仍取决于视觉身份、有效表面、规划和动作核验。结构支持独立要求不等于任意多对象任务已经实测通过，任意抓放和复杂重排尚未获得验证。
