# 历史故障与观测时序核对（2026-11-07）

统计现存远端归档、保留的旧归档导出和本地完整状态文件，按 run_id 去重。运行事件区分实际 skill 失败、子图向上传递和最终停止。原始汇总、逐故障证据与复算入口保存在 `data/runs/history-timing-20261107`。这些实验跨版本，归档也有保留选择，不能据此计算当前版本稳定成功率。

本轮优先修改执行层数据时序，保留数值规划、碰撞检查、物体身份阈值、机器人参数和 SDK。必要的技能契约调整仅涉及 observe_scene、identify_target、plan_grasp 的证据前提。

## 本轮修复

1. 支撑证据过期：恢复观测改变采集版本，永久 ID 不变，但已有支撑证明仍属于旧采集。新增明确的 `source_support_current` 契约字段，编译器拒绝未经恢复此前提的重规划路径；同采集证明复用，历史位置不再跳过当前支撑确认。
2. 重复观测缓存：上层因历史变化要求重分析，下层旧缓存却只按采集/外观键返回旧结果。删除重复缓存，保留按完整身份历史、标定和 CAD 运动上下文复用的单一执行层缓存。
3. 观测写入顺序：此前先改内存、后写数据库；写失败时两者可能不一致。现在先准备两个记忆的候选更新，提交实例记录事务，再替换内存，最后更新任务账本与参考。任何采集编号不一致先拒绝。支撑判断的事实回执同样先提交数据库，提交失败不把内存标成已确认。
4. 测量与发布混淆：新的几何测量标记场景待发布，保留旧场景及其日期，不把观测成功当作碰撞场景更新成功。
5. 图修订错误归属：本轮在线实验中，子图任务绑定错误被标到 InitialPlan 根层级，导致程序错误地放弃剩余修订机会。该校验移到 graph 字段，校验规则不变，仍冻结实体和根任务，最多两次修订。动态选中输入/产物使用共享子图，schema 说明其 owner 不能是 `$selected` 等运行时绑定。

第二次实验还复现重复边 ID、引用不存在节点。输出字段与最终检查补充通用命名说明：从准确 source 与 outcome 派生 ID，避免不同节点缩写相撞。校验反馈现在报告两条重名边各自的 source/outcome、缺失端点的名称及 source/target 方向，便于准确修订。没有自动改名、删除边或补写子图；该提示本身不保证模型以后不会犯错。

- `support-contract-probe.py`：以实验 `5613e38cff47448cbceace742ba9cc89` 的真实 graph 重放静态校验，旧契约接受、新契约拒绝缺失支撑刷新路径；当前支撑只问一次，unknown 不覆盖旧证明。

上述组件通过不等于完整任务成功。历史统计使用修改前归档；本轮新实验单独列出，避免把修订中的代码混进基线。

## 数据增删改查及发布时机

观测是身份、可见性及位置的主要来源，但不是所有状态变化的唯一触发器。真实动作回执到达时先记录发生了什么、使哪些旧证据失效；后续观测确认现在在哪里。两者分别有时间和来源，不能用动作回执冒充新视觉位置，也不能在下一次观测之前继续把动作前的地图当作有效地图。

|事件|时间记忆|空间记忆|执行层/Graph|
|---|---|---|---|
|首次候选/新物体确认|确认后登记永久 ID；候选和 unknown 不冒充已确认实例|仅接收已关联的测量|在线 graph 不按最初物体数量固定展开|
|接受新观测|事务更新可见性、测量日期、参考掩码与历史；提交失败不替换内存|记录新测量，标记待发布|账本随后更新；当前支撑证据失效|
|本次看不到|保持 active 与永久 ID，标记 unseen，保留旧测量日期|旧障碍仍保留且注明历史/缺测|可选择显式观测恢复，不自动删除或创建替身|
|实际运动/释放回执|先记录发生的动作并使旧位置依据失效；回执不声称最终视觉位置|失效或预测变化明确标明，不能冒充实测|后续阶段失败不能抹掉已发生的动作|
|视觉确认加工/退役|输入消耗与新产物用原子事务登记，保存谱系；明确移除保存其理由|下一次发布按退役与新测量更新|任务失败不复活已消耗输入；新产物独立 ID|
|build_scene 发布成功|不改物体身份、操作历史或任务结论|验证版本后接受发布并清除已满足的待更新状态|规划只能使用相符的场景、目标和采集|
|查询|随时读取有日期的副本|读取测量或发布快照，二者区分|查询不生成新事实、不触发隐式动作|

## Decisions 不确定结果的证据范围

能同时恢复原始回答与消费方 diagnostic_checks 的记录中，实例关联有 58 个 unknown、放置接近目标有 4 个、当前支撑有 1 个。实例关联样本还包含 399 个 yes、296 个 no；明确 no 是排除错误候选的有效结果。另有 2,251 条实例关联回答未保存消费结果，不能据其分数反推当时程序是否判为 unknown。上述是单题调用数，不是失败实验数，也不足以推算全部历史的 unknown 比例。

本轮没有调整 Decisions 阈值或把 unknown 改成成功。修正的是 Decisions 上游输入与下游持久化时序：变化的身份历史/CAD 信息必须送达感知；当前支撑证明必须绑定当前采集；接受的证明必须先入库再发布到内存。
