# 语义放置模式与容器释放验证

## 接口与边界

- Responses 只在初始在线编排选择 `identify_destination.release_mode`。`surface_setdown` 是支撑面轻放，`container_release` 是任务允许的盒沿上方释放。不新增 plan_pose skill。
- 模式存于当前物体的任务/转移绑定，经抓姿筛查、placement intent、XY 候选、Z 求解、规划、执行回执传递；不是实例时间记忆中的物理状态。重新绑定目的地会撤销旧计划。
- 数值配置 `container_release_gap_m` 默认 0.01 m，控制台以 mm 显示。完整持物 CAD/OBB 最低点名义高于已发布容器上沿 10 mm，保留既有 IK 位置容差。实际盒底高度独立保留。模型不能输入高度或更改数值设置。
- 每个 XY 只求一个盒上释放高度，保留完整物体投影、持物/夹爪、工作空间、IK、全机环境/自碰撞及执行反馈检查。失败不会自动升高、换模式或放宽间距。
- `plan_place` 按显式模式复用既有 `/tools/plan_carried_pose`（官方 plan_pose）或三段式路径；`execute_place` 按同一模式核对阶段并停稳开爪。盒上释放不伪造 approach/retreat、不隐藏移动。释放使空间几何失效，视觉 verify_place 判定落点，后续地图更新仍由 graph 编排。
- 初始 prompt 保存通用、经故障证实的编排经验，不保存成品 graph。明确区分动作前规划失败与部分动作失败的事实前提。Decisions 的分支输入补充 inline 成功续接路径、结果边、子图及入口剩余次数，只允许选择图内分支。

## 当前结论与未解决项

10 mm 盒沿上方释放及在线语义模式已部署，单物体完整链路有一次独立审计通过的实验。双物体完整任务仍未通过，不能宣称稳定成功率。当前暴露的阻断包括初始图编排结构错误、部分抓取候选的真实数值拒绝，以及清楚可见的区域放置仍返回低概率。v42 已实际验证 Decisions 选择规划恢复和释放后的证据恢复，并分别回到抓取与核验检查点。

最终静态检查：Python compileall、src 的 Ruff F 规则、修改模块 Ruff、层导入隔离检查通过；两臂释放几何/分发、固定 XY、恢复选择/次数、身份恢复覆盖、规划恢复覆盖检查通过。41 个应用/契约/文档文件逐一核对部署哈希。cuRobo 使用现有固定源码版本 `8e734f3ced1df898990bcd92de40abce475907db` 的公开接口；本次没有修改官方 SDK 或新建镜像。实验已结束，没有后台任务继续运行。
