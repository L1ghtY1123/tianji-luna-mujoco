- 最终验收区分历史加工/交付和当前来源残留。source_has_remaining_input 仅看本问题中的当前三相机 RGB：完成要求明确 no，yes/unknown 均不能通过。模型 refusal 保留为 unknown / model_refusal，其他有效回答保留，不捏造概率或重试到成功。

## 控制检查

- 真实生成图的受控规划失败注入：原 A 臂规划失败后沿已有 router 选择 B，重新生成抓姿/规划后接回任务；没有重放抓取执行，图不变。这是控制执行器探针，不是物理恢复成功率实验。
- 缺失结果边在编译检查中拒绝，运行时也明确停止；改变节点数组顺序不改变执行路线。
- 同一失败几何换节点 ID 仍被拒绝；改变真实目标输入后不被该重复检查误挡。
- 来源残留冻结图对照，保持共享历史上下文：有粉色包裹时 presence=yes（0.90）；空盒时 presence=no（0.00）。没有改变 0.8/0.2 判断门槛。
- 有类型 refusal 的解析探针：保留 unknown / model_refusal，无虚构置信度，其他有效答案照常保留。另用原拒答实验的冻结请求，明确里程碑与来源闭合的分工后全部验收条件通过。
- Python 静态检查、全部源文件 AST、21 个契约加载及前端构建通过。前端仍有既有的单包大于 500 kB 提示。
