# Decisions 与数据库审计

审计范围：实际任务入口、全部 Decisions 请求生产者、原始图像和工作空间过滤、回答解析、初始和观测登记、永久 ID、参考图和掩码持久化、物体状态事务、空间记忆订阅和发布、回放。

当前结果：六处可复现的程序错误及身份提问的主体/类别歧义已修复；101 条旧记录的当前状态已备份并规范化，永久 ID、原始观测和历史事件保留，当前数据库 698 个记录。最终冻结观测 12/12 候选关联正确，CAD/FoundationPose 与碰撞场景发布通过。两次最新实际失败输入也已通过正式登记器复测；完整搬运尚未验证通过，不能宣称稳定成功。

工作顺序：

1. 保存当前代码基线及失败输入，逐调用记录问题、图像来源、选项、回答及写库消费方。
2. 使用未改动的失败实验逐候选核对身份；ID 集合完整不代表身份正确。
3. 对可复现的程序错误先建立检查，修复同一根因并同步部署；不添加置信度门槛、数值身份推断或强制成功。
4. 核对登记事务、原始参考、状态版本及地图发布；检查异常路径和任务重启。
5. 完成静态检查、针对性回归、真实浏览器和实际入口验证，分别报告通过与未通过项目。

## 已复现并修复的程序错误

| 错误 | 修复 | 证据 |
|---|---|---|
| 已有 ID 且身份来源为 Decisions 时跳过本次视觉确认，把 Responses 的 existing_id 当成当前事实 | 所有当前候选都经独立视觉确认，existing_id 只作提议 | 已登记粉色 ID + 错误蓝盒 existing_id，修复前绕过判断，修复后拒绝且原记录不变 |

| 几何观测的 kind/color 覆盖数据库已登记语义 | 已登记属性保留，当前数值颜色继续作为测量诊断；新实例才初始化属性 | 粉色物体记录收到蓝色容器测量，不再被数值更新改写 |
| 持久化参考框使用几何掩码，而数据库保存身份掩码 | 两者均读取当前原始身份掩码；初始参考也保留 silhouette_mask | 全幅身份掩码 + 中心小块几何掩码，参考框现在与身份掩码一致 |
| 合并同 ID、同相机的已接受片段只合并几何掩码，漏合并 raw_identity_mask | 原始身份掩码同步合并，保留每片判断证据 | 两个已接受片段的原始身份像素均保留 |
| 发送模型前按图片字节去重，把其他相机或历史实例图片替换为“同上第 N 张图片” | 请求保留原本编排的每张图片及其角色、时间；仅归档存储按哈希共享文件 | 完全相同像素、不同相机/日期的四张图片，修复前只发一张，修复后四张均保留且顺序不变 |

选物体题也在每个 ID 选项上附已登记描述，不再依赖模型从共享 JSON 查裸 ID。

身份提问明确使用 SAME PHYSICAL INSTANCE，区分“同一个物体”和“外观同类物体”。已有 SAM3 主体在登记 choice 中提供独立当前掩码，避免只靠同一张照片里相邻物体的文字位置描述。参考图仍使用原始 RGB 和描述。右盒新实例样本及原左盒、原粉件的同一实例对照均通过；不是把所有选择推成 new_instance。

官方协议复核：gpt-6-luna、input 中的原始图像、question 的图片 instructions、choice.description 均属于官方支持字段。项目原有 64 个选项的额外限制已对齐官方 255 上限，201 个合法选项的类型验证通过，超过上限明确拒绝，不裁掉数据库 ID。[官方 Decisions 指南](https://developers.openai.com/api/docs/guides/decisions)、[API 参考](https://developers.openai.com/api/reference/resources/decisions/methods/create)。

另修复回放修订版的模板来源丢失：仅修改 root 的 Responses 修订保留原子图模板来源；显式替换为自定义 body 或删除的子图不继续冒充固定模板。最新失败实验真实浏览器可查看完整 77 节点、9 面板及固定模板、恢复分支，无页面错误。系统回位图单独保留。

## 实际图像与筛选边界

| 消费者 | 当前实际来源 |
|---|---|
| 初始 Responses | `capture.views`，即工作空间过滤后的 RGB；已有登记外观候选可并回 |
| 全部 Decisions 的通用图像编码 | 优先 `capture.raw_views`，原始 RGB；按题需要附独立掩码或深度 |
| 初始登记 Decisions | 空库 presence 用指定相机原始 RGB 核对描述；后续 identity choice 用该 RGB 和已有 SAM3 当前主体掩码，参考图原始 RGB；明确比较同一个物理实例 |
| 实例关联 | 三相机原始 RGB + 当前主体独立掩码；当前主体相机优先。有日期的参考使用原始 RGB、实例描述与参考框元数据，避免混入历史过滤掩码及其他候选掩码 |
| 首次 CAD 检索 | 当前原始 RGB + 身份绑定掩码 + CAD 预览 |
| verify_grasp | Lift 后当前原始腕部 RGB 优先及其他原始视角，无需 SAM3、夹爪角度或随动判定 |
| verify_place | 当前及释放前原始 RGB、深度；执行回执只证实释放动作，不能证明落点 |
| SAM3、FoundationPose 和几何建图 | `capture.views`，工作空间并已登记外观候选的 RGBD；FP 用当前身份掩码、有效深度最充分的一路及标定 |

黑背景不等于 Decisions 实际收到了同一张图。裁掉目标可见几何可能影响 SAM3 / FoundationPose；已登记候选并回可以保留边界外外观，但不能宣称任何程度的裁切都无影响。无关背景不会仅因在 Decisions 原始 RGB 中可见就自动写入数据库：须有候选、身份确认，新登记还须工作空间内有效深度。掩码只用作指出正在问哪片区域，VLM 不靠它进行三维数值计算。

## 全部 Decisions 用途核对

| 题目 | 类型 | 数据写入或消费 |
|---|---|---|
| 首次登记 / 已有实例比较 | 空库 presence 二值；其余全合法 ID + new_instance/reject/unknown | 登记器分配或引用永久 ID，不由 Responses 定 ID |
| 当前 SAM3 候选身份 | 全合法 ID + new_instance/reject/unknown | 当前观测绑定；接受后才测量、更新数据库和几何 |
| 首次 CAD 检索 | CAD 目录选项 + 无匹配 / unknown | 仅模型候选，当前 FoundationPose 后才发布姿态 |
| 下一个目标 | 当前合格 ID + unknown | 任务当前选择，不是永久身份或运动可行性证明 |
| 新出现对象的任务归属 | 二值 | 本次执行账本，不写物体数据库任务进度 |
| 未被当前数值证据确定的支撑关系 | 逐个二值 | 有日期的物理支撑记录；数值已确定时不再调用 |
| Lift 后夹持 | 二值 | yes 才 attachment；no 与 unknown 保留差异 |
| 释放、retreat 后落点 | 二值 | 视觉成功才记录交付；开爪回执不能替代 |
| 加工产物与原包装消失 | 两个独立二值题 | 两者确认及执行来源绑定后原子登记产物谱系 |
| 来源是否仍有输入 / 额外视觉完成条件 | 独立二值 | 任务验收；普通计数、顺序和回位由回执或关节反馈核对 |
| 额外视角信息是否缺失、graph 的 rule=visual | 声明的二值 / 选项 | 仅沿已有 graph 边；不能补技能或放宽数值约束 |

非视觉建图范围、选臂、标准完成回执、已知错误恢复及统一失败回位不调用 Decisions。所有模型回答经过同一概率最大项规则，confidence 仅审计；精确平分、拒答、unknown 不变成成功。

## 数据库与空间记忆

时间记忆通过 SQLite ObjectDatabase 保存：永久 ID、类别/外观描述、原始参考采集与独立身份掩码、分割查询、CAD 绑定、可见性、带来源的最近位置/姿态引用、支撑和区域、物理运动/交付回执、加工输入输出谱系，以及追加历史与提交版本。实际表为 entities/history/captures/instance_masks/object_changes。RGBD 和标定绑定原采集；任务节点、任务完成状态和当前碰撞有效性不写入物体记录。

空间记忆保存碰撞几何、来源/scene_token、采集、有效性、dirty ID 与数据库版本。数据库事务提交后订阅更新空间状态；几何相关改变阻止继续规划，直到当前场景发布。支持 CAD、未知物体 ESDF 及桌面 cuboid，不能把数据库里有 ID 当成已有完整碰撞几何。

自然语言未点名的可见外部碰撞物可由 Responses 提出并登记；SAM3 查询来自数据库外观/别名及通用 `movable object`，并非只分割任务点名物。分割候选不是数据库事实。当前机制不保证识别任意杂物，不把遗漏或未观测区域说成自由空间。
