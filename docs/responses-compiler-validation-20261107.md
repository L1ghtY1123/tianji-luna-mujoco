# Responses 编译与失败记忆

## 失败来源

核对最近 9 次实验的 17 次 Responses 请求，7 次首稿被拒绝，8 次实验最终编译通过，1 次在两轮修订后停止。这些图校验失败调用返回 HTTP 200。应用发现了不存在的节点或子图、不可达节点、恢复覆盖遗漏、未绑定的 `$product` 和未满足的技能前提。

此前 `GRAPH_RULES` 中的经验是手写说明。编译器只读取实例记忆，没有跨任务读取和保存编排失败记录。修订输入只保留上一轮错误。拓扑或数据流校验提前抛出错误，部分独立问题延迟到下一轮才出现。

JSON Schema 约束字段、类型和枚举。引用是否存在、调用路径是否建立 `$product`、恢复是否满足运动前提属于应用图语义检查。Structured Outputs 的内容仍可能出错，官方建议拆分任务和使用验证评估。[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

Graph-as-Policy 的生成过程先声明顶层子图接口，再生成子图内部状态机，使用明确的输入、输出、出口和已注册工具。本项目继续使用当前 version=2 协议及一次初稿、最多两次执行前修订的预算，落实声明顺序、作用域、绑定和契约检查。[Coordinator](https://github.com/graph-robots/graph-as-policy/blob/53e8049d1e30aa2b55e941914361fca645694e87/gap/agent/prompts/coordinator.md)、[Subgraph agent](https://github.com/graph-robots/graph-as-policy/blob/53e8049d1e30aa2b55e941914361fca645694e87/gap/agent/prompts/subgraph_agent.md)

## 当前实现

- `CompilationMemory` 独立保存编排失败。SQLite 事务按请求哈希去重，记录采集、实验来源、错误、相关技能和可用的数据流反例。`PolicyController` 注入存储，`ResponsesCompiler` 在生成前读取，在拒绝图后写入。
- 当前输入按可执行技能契约的指纹选择记录。说明文字的变化保留匹配，参数、前提、效果、结果绑定和结果集合的变化更新指纹。历史记录按错误族汇总，保留次数、约束和两个实际反例。实例记忆通过原接口提供。
- 60 份可用归档中导入 29 次图编译失败。导入结束时有 14 次匹配当前契约，15 次保留为其他契约版本。最近 17 次请求同时使用当前契约重检，8 份原已通过图继续通过。
- 输出 schema 先声明根节点及其子图调用接口，再填充所有引用的子图体，局部节点列表先于入口和边。图修订携带此前各轮错误，保留冻结任务、候选清单和传感器输入。
- 修订通过 `root`、`subgraphs`、`remove_subgraph_ids` 明确编辑作用域。省略的定义保留，替换使用完整节点和边，删除需要显式列出 ID。应用声明编辑后重新校验整图，审计同时保存原始修订和完整 `graph_proposal`。回放兼容既有整图归档与当前作用域修订。
- 数据流和恢复覆盖错误在同轮反馈。缺失绑定提供实际路径、可用绑定、生产者和选择新输入导致的重置规则。未调用子图错误列出具体名称。
- 当拓扑错误仅涉及不可达节点或未调用子图时，对可达部分建立诊断副本，补充数据流与恢复覆盖错误。原始图继续返回校验失败，后续可执行图仍由 Responses 输出。

## 本地验证

证据位于 `data/runs/responses-compiler-20261107`。

- `regression_probe.py` 在修改前复现了独立错误被隐藏、引用先于声明、编译器缺少失败记忆，以及未调用子图错误缺少名称。修改后通过。
- `memory_pipeline_probe.py` 重检 17 次真实归档，验证数据库重开、重复导入、并发去重、契约版本筛选、错误族归一化和畸形图记录。实际编译入口通过 HTTP 边界回放验证记忆入参、冻结输入、修订历史、三次调用上限及错误图拒绝。
- 不可达声明与 `$product` 缺失同时存在的用例，修改前只返回拓扑错误，修改后同时报告拓扑、绑定及恢复覆盖错误。
- `scoped_revision_probe.py` 使用 `frozen-04` 的真实中间版本，验证只修改 `view_repair` 会保留 `item_cycle` 及其余作用域。显式删除仍被调用的子图会触发整图拒绝。原图对象保持原值，最终接受图来自完整校验。
- `replay_revision_probe.mjs` 验证回放选择完整 `graph_proposal`，既有整图输出继续正确显示。
- 原有 `contract-feedback-probe.py` 和 `compiler-input-probe.py` 通过，前提依赖诊断和精简技能输入的可执行字段继续保留。
- 全部源码 Ruff F 检查通过，158 个 Python 模块可解析，22 份技能契约加载通过。
- 前端 Vite 构建成功，51 个模块完成构建，仍提示 OrbitControls chunk 超过 500 kB。

## 在线验证记录

`frozen-01` 的诊断脚本将图片尺寸标记为 4×4，已从冻结输入验收结果中排除。随后修正为原始 640×480，JPEG 原字节和哈希继续核对。

`frozen-02` 使用原始尺寸及图片，运行 v18 编译器。三轮依次暴露未调用子图、恢复入口前提冲突、修订删除规划失败恢复分支，最终编译失败。该记录促成 v19 的具体子图诊断和 v20 的可达部分综合诊断。最终版本的在线结果在后续验收记录中列出。

| 作用域修订前的验证 | Responses 次数 | 编译结果 | 编译模型耗时 |
| --- | --- | --- | --- |
| `frozen-03`，原单物体输入 | 1 | 首稿通过 | 170.931 秒 |
| `b17722a7de4f4b0da713733195c98029`，正常双物体入口 | 2 | 首稿引用缺失子图，第一次修订通过 | 427.800 秒 |

`frozen-03` 的实际请求包含 18 次匹配当前契约的失败记忆和 9 类约束，图片原字节、相机顺序和尺寸与原归档一致。

双物体实验已执行通过校验的在线 graph。初始登记对两个粉色对象的比较分别返回 0.54、0.48，身份仍未确认，两个候选没有获得永久 ID。运行时选择结果为空，最终核验失败，已声明恢复用尽，整体 `needs_attention`。该实验验证了编译和真实入口衔接，完整拆包交付失败。

`frozen-04` 在 v20 下仍编译失败。首稿遗漏 `item_cycle`，第一次修订补上该子图，第二次修订在重写完整图时再次遗漏它。这一真实回退促成 v21 的作用域编辑协议，已生成且未请求修改的子图由应用保留。

`repair-01` 的初始失败来自归档，表中计数只包含实际 HTTP 修订请求。两个诊断均核对原 JPEG 字节、相机顺序和 640×480 尺寸。诊断只执行编译。

正常双物体入口的修订只替换根图，四个子图逐项保持原始定义，冻结任务与候选清单逐项一致。`repair-01` 只替换 `transfer_body`，保留 `input_cycle`。两次修订的原始编辑和合成后的完整图均在归档中可核对。

完整双物体实验最终 `needs_attention`。第一件输入 408 完成拆包及产物 410 交付，第二件输入 407 完成拆包并登记产物 411，随后 `build_scene` 返回 `inventory_map_incomplete`，缺少 411 的有效碰撞层。独立 MuJoCo 验收确认右盒产物 1/2、账本完成 1/2、已有谱系正确、当前空手、双臂尚未完成最终回位。完整交付验收失败。

本轮编译及真实修订验证通过，首稿仍出现过最终位姿前提错误。整机可靠性还受产物关联与几何获取失败影响。相关证据为 `live-scope-repair-verification.json`、`run-11-state.json`、`run-11-qa.json`、`frozen-05-result.json` 和 `repair-01-result.json`。
