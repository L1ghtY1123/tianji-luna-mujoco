# Configured release height with held IK

Production `resolve_placement` keeps every existing XY candidate and its full grasp rotation. For each XY, it computes the initial complete-object floor gap from the registered CAD support vertices (which retain all model extrema) or bound OBB corners. The maximum Z increase is the configured `place_max_release_gap_m` minus that initial gap. The shared list contains 1mm samples and the exact final bound when fractional. `PlanningSettings` supplies configuration validation; there is no independent 20mm production cap.

The calibrated workspace and the unchanged attachment/gripper world query use this same list. The service retains the first world-clear sample separately, then submits qualified samples once through the existing public held `/tools/solve_ik_batch` path, with the original IK thresholds, full carrying binding and measured A/B gripper/arm feedback. Real samples are split into batches of at most 100; existing capacity padding is reported and ignored as additional evidence. World-colliding samples never enter IK. The GPU world-query lock is released before entering the native IK operation, which acquires the same non-reentrant lock itself.

The chosen result is the lowest **sampled** goal passing workspace, tool-world and full-arm held IK checks. Both its target and public achieved-FK complete-object floor gaps must stay within the configured maximum. A failed IK sample retains its original solver metrics and is not relabeled as a tool collision or proof of geometric impossibility. Proofs preserve independent per-sample causes, the first world-clear height, selected height, geometry hashes, immutable query binding, batch counts, ignored padding and measured timing. An exhausted search reports its actual evidence and does not establish whole-region infeasibility.

`apply_release_height` and release verification replay the same proof against the bound geometry. Actual release feedback independently rechecks the complete CAD/OBB floor gap, original hard clearance and region constraints. Production signed resolutions require the held-IK proof; the old geometry-only height query remains explicitly labeled compatibility behavior and cannot authorize a production resolved candidate. Endpoint success remains `trajectory_checked=false`; `plan_place` and execution retain their complete trajectory and feedback checks.

The resolution retains its original dual-arm/gripper feedback. `plan_place` obtains new feedback and checks both arms and fingers using the existing numerical-consistency contract of 1e-6 rad, also used for placement retry identity. Both snapshots and their differences are reported; larger changes invalidate the resolution. This does not change IK, collision, servo or release thresholds. The planner always receives the new measured feedback and performs its original checks. Geometry, scene, settings and other resolution inputs still require the exact original digest.

CPU regression includes the archived B3 registered CAD and public achieved FK: +21mm gives about 48.908mm object-floor gap, +22mm about 49.929mm, while +23mm exceeds the unchanged 50mm limit and is rejected despite its legal requested gap. This is an FK/gap replay, not a new GPU solve or physical execution. The prior real 0–20mm diagnostic used 5mm spacing, so it cannot establish that +21mm is the lowest feasible 1mm sample. The same fixture preserves resolve-to-plan feedback differences: B joints changed by at most 5.223e-13 rad and the B gripper by 1.423e-7 rad. Tests exercise service locking, compatibility rejection, stale/tampered evidence, actual release gap and batch coverage. Real deployment and end-to-end execution remain separately assessed by the main experiment.
