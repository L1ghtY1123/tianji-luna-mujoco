## 证据与原因

Decisions 的 predicate 返回概率，程序将 >=0.8 映射为 yes、<=0.2 映射为 no，中间映射为 unknown。接口语义见 [OpenAI Decisions 官方说明](https://developers.openai.com/api/docs/guides/decisions)。这些样本不是服务输出了自然语言“unknown”。

原请求混合了历史目标裁剪、三相机当前原图、当前区域标注，以及两份完整任务要求。完整要求还包括后续拆包、最终右盒交付和回位。问题使用笼统的 reference object、support surface、the gripper，没有清楚绑定双臂中的执行臂及腕部相机。单纯缩短问题、加粗区域框都没有稳定解决问题；相关失败探针仍保存在 data/performance-unpack-20261101。

另外，解析层把明确的视觉否定也归入 unknown。这是独立的程序缺陷，不应称为模型置信不足。

## 当前实现

- 已由 Decisions 授权整区的 `entire_region`：共享 input 只提供身份与当前目的要求。每个 question 的 instructions 携带自己的当前三相机图像，历史目标裁剪不会成为当前落点图片。
- `place_result` 写明清单中的目标 color/kind 和目的支撑 color/kind，例如粉色物体是否在白色桌面上。`placement_near_target` 单独使用本次 RGB 的区域投影，允许大致落点误差。
- `workpiece_still_held` 明确执行臂、腕部相机、实际夹爪反馈。A/左臂对应相机 2，B/右臂对应相机 1；保留三视角，最后显示执行臂的直接视图。另一臂空手不构成本臂释放的证据。
- `candidate_selection` 仍保留原始相对位置、姿态和本次转移条件。没有用整区简化丢掉额外语言要求。
- 全部必要事实明确且有否定时，视觉结果为 rejected，skill 返回 `failure / visual_placement_rejected`；概率不确定仍为 unknown。原始回答、失败项和缺失项分别保存。两者均不自动插入运动或重试。
- question 内的图像按原始字节独立归档；回放显示问题文字、所属图片、相机和当前/历史来源。
