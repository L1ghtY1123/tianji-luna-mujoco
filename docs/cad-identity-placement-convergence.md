# 永久 ID、三相机 CAD 位姿与放置位置

2026-10-31。本轮只收敛已有接口：初始 Responses 生成 graph；运行时 Decisions 做有类型的选择或判断，skills 计算几何并执行。`plan_grasp`、`plan_place`、`plan_pose` 保持 cuRobo 轨迹规划含义。

## 一个实例一条几何记录

当前 SAM3 掩码 → Decisions 关联永久实例 ID → 为这个 ID 检索 CAD → 当前位姿估计与验证 → 发布几何。

掩码与 CAD 的匹配输入是原始指令、该实例描述、各相机掩码保留的主体 RGB，以及 CAD 目录的参考渲染图。Decisions 返回目录选项编号、`no_catalog_candidate` 或 `unknown`，不输出模型路径或位姿。选项编号映射受控目录 asset_id，FoundationPose 几何验证通过后才确认 ID→CAD；不能只凭“蓝色”绑定蓝盒。

- 永久 ID 标识物理实例，CAD asset_id 标识模型。两个同款蓝盒有两个永久 ID，可以共用一个 CAD；各有自己的世界位姿。
- 同一 ID 的不同相机掩码组成一次观测证据，各相机候选编号不是永久 ID。
- 已验证的 ID→CAD 对应可在同一仿真代次缓存，CAD 文件哈希变化会失效。世界位姿每次观测重新估计并验证。
- 没有目录候选的实例用当前实测 OBB；每次有效观测替换这个 ID 的旧 OBB，避免历次包围盒累积膨胀。局部观测没看到、且没有动作失效证据的实体保留历史层，明确标出来源时间。
- `unknown` 不等于“没有 CAD”。已提出或绑定 CAD 后，配准失败返回错误给 graph，不偷偷降级成 OBB。

当前帧若有通过深度追踪验证的容器锚点、且该 ID 已绑定验证过的 CAD，先检查候选点集与锚点的最短可能距离。超过 CAD 最大直径加原有测量容差，就从该候选身份选项中排除这个 ID，阻止远隔的两盒混成同一 ID。只排除不可能的匹配，不替模型指定另一个 ID。没有当前锚点或已验证 CAD 时不使用此排除。

## 三相机如何使用 FoundationPose

对同一个永久 ID，收集三台相机中身份已确认的 RGBD、SAM3 原始轮廓、内参和外参。各相机同一次采集的数据不可混用。RGB、深度与 SAM3 掩码必须在同一像素坐标系；腕相机外参使用本次关节反馈下的相机位姿，不能复用手臂移动前的外参。

1. 按掩码内有效深度数量排序，同数按相机 ID 排序。同相机同 ID 的掩码合并一次。
2. 从有效深度最多的视角调用官方 FoundationPose `register`，输入该视角 RGB、深度、K、SAM3 轮廓和已选 CAD。
3. 换到世界坐标：`T_world_object = T_world_camera @ T_camera_object`，CAD 源坐标原点换算只做一次。
4. 用所有已关联视角的实测点、深度和轮廓验证这个世界位姿，保持原尺寸容差、比例和有界刚体细化规则。
5. 几何验证拒绝时才按排序用下一视角重新估计，每相机最多一次。全部拒绝就失败。服务或数据来源错误立即失败。

不平均三个独立姿态。通过验证的一个世界位姿是该 ID 此次唯一 CAD 位姿；`view_estimation` 记录尝试、拒绝原因和最终视角。一台相机可见也可工作，但只能声称由实际可见证据验证。

抓取规划还依赖当前直接支撑。Responses 未填写 `initial_parent_id` 且没有 `current_region` 时，`identify_target` 必须调用现有 Decisions 支撑判断，而不能跳过后让 lift 错报缺少源容器。确认结果同时写回清单与实测快照，未知仍返回 graph；不能由 CAD 或任务目的地猜支撑。

## 放置 XY 由技能搜索，语言由 Decisions 限定

目的地绑定只用一个 `destination_requirement_matches` 判断，引用完整原始指令、具体 ID、描述和当前/初始图片，确认“左边那个盒子”等实体选择；不认证空位。

语义判断另附所有当前实测实例的定位图：由当前已关联 SAM3 掩码生成框，短标签映射永久 ID，原始 RGB 和原问题不变。观测代次、相机帧、标定和 RGB 哈希必须一致，掩码哈希归档。定位框只说明正在问哪个可见物体，不能当作符合语言要求的答案。

`perceive_placement_zone` 取得该实体内底面或承托面的多边形与高度，保留完整原始自然语言，并问 Decisions：“原始指令是否允许这个区域内任意物理可行的位置？”

- “放进盒子”“放到桌面”：整个区域获认可后，由数值搜索选空位。
- “放在杯子左边”“放到盒子右后角”：整个区域未获认可时仍是搜索范围。`resolve_placement` 将最多 12 个通过数值检查的带编号候选投影到当前相机图像，单批询问哪些候选符合完整指令，保留正面接受项。Decisions 返回编号对应的判断，不需生成自然语言或 XYZ。例如一批问题是“候选 P1 的完整物体足迹是否位于指定杯子的左侧？”、“P2 是否符合？”，结果是各题的概率；只有达到原接受门槛的候选可交给轨迹规划。方向仍须绑定明确视角，未知不自动换到机器人坐标。

`resolve_placement` 保持抓取绑定的旋转与实际偏心关系，用完整 CAD/OBB 足迹生成区域内有限 XY 网格：先查最多 96 个分散点，无数值可行点才查原网格余点，最多 25×25 加中心。每个 XY 从解析最低高度向上按 1 mm 搜索至配置离面上限，检查离线工作空间包络、夹爪与 attachment 球对 CAD/OBB/cuboid 场景的碰撞、持物 IK、实际 FK 下完整物体离面间隙，选最低合格高度。已有物体占用参与同一个场景查询，不靠语言猜测占用。

`plan_place` 再验证接近、下降释放、撤离三段轨迹，包括全机器人、另一臂和路径碰撞。没有合法候选就返回失败，由 Decisions 选择 graph 分支，或按注册能力生成并校验恢复 node/edge；不改成 `plan_pose`，不中途调用 Responses 选择位置。
