# 当前感知、判断与耗时修正

timing-54 已同步到 Ubuntu。P51、P52 两轮完整仿真成功，扣除初始 Responses 后分别为 225.133 秒和 214.805 秒。下面区分实际修改、旧版基线与本轮验收。

## 修改范围

- 生产 CAD+OBB 感知停止 CPU MuJoCo 机器人表面射线过滤。SAM3 仍决定像素，原始深度保持不变；桌面/OBB 测量与 cuRobo 全机碰撞检查保留。旧体素兼容路径与显式注入的离线过滤器不改写。
- `verify_place` 按用户最新要求改为一轮三相机 RGB + Decisions，同时判断目的地关系及是否仍夹持。不再执行 SAM3、FoundationPose、OBB 或释放后落点测量。不宣称知道释放后毫米级坐标。释放端点、夹爪反馈、动作与采集版本校验保留；确认后的地图位置是执行反馈预测，后续观测才刷新实测几何。
- `observe_scene` 的参数说明与实现统一：版本/动作/反馈未变则复用，不因名为 fresh、图像年龄或 unknown 自动重拍。失败的相同输入不重复完整分析。
- 25 份技能用途说明删除旧版规则和历史补丁叙述。Decisions 共用规则区分当前视觉事实、已经确认的绑定、语言解释、操作提议；放置候选问题仅判断本次位置/姿态，不混入加工、CAD 或最终回位。
- `move_to_observe(viewpoint=...)` 提供配置位姿和两个不同腕部倾角提议，后两者在配置位姿基础上将两臂第六关节分别偏置 +12°/-12°。需通过实际关节界限、当前地图 cuRobo 双臂规划和执行检查，不能保证一定看清。它们不满足用户的“回配置观测位姿”完成条件。同一位姿不能伪称换视角。没有当前地图时仍不能盲目移动。
- 场景预览不再将已创建的全部 CAD 三角形列表深拷贝第二遍；保留完整三角形和来源哈希。借用的可变地图元数据仍独立复制。

## 失败应如何区分

`identity_*` 将 SAM3 候选对应到永久物体 ID；两个蓝盒各有自己的实例 ID。`cad_model` 将已关联主体与 CAD 参考图/描述对应，输出型号提议。SAM 名称只提供线索，box/basket/container 等别名不要求逐字等于 CAD 名称。FoundationPose 用选定型号估计位姿。型号可按实例缓存，新观测位姿按动作上下文更新。

选中 CAD 后的 `observed_support_unknown` 是支撑关系问题，不能称作 CAD 匹配失败。当前型号提议不再使用 0.8 置信门槛；事实判断仍保留原门槛，不能把 unknown 当 yes。桌面/盒内问题只问直接支撑或直接容器：盒子在桌面上时，盒内物体的直接容器是盒子。已确认的拆包产物桌面关系保留到其证据失效，不立即再问同一个问题。

历史失败确实包括初始蓝盒身份 unknown、候选与身份来源不一致、支撑关系 unknown、旧版 CAD confidence 拒绝、placement 语义 unknown、恢复参数不合法，以及 Responses graph 前提不合法。它们不是一个原因，也不能归因于 Decisions 服务都很慢。每次报告应保留问题、原回答/概率、门槛、对象 ID、采集和动作阶段。

## ID 含义

| ID | 作用 |
|---|---|
| 永久物体 ID | 某个物理实例；绑定 CAD/OBB、位姿、持物、处理与交付历史 |
| CAD asset/model ID | 库内型号；两个蓝盒可以共享一个型号 |
| graph/subgraph/node/edge ID | GaP 图结构和恢复边的寻址；不是新增物体身份 |
| region/slot/candidate ID | 配置区域或临时落点提议；Decisions 选择它们而不输出 XYZ |
| observation ID、generation、scene_token | 采集、仿真代次与地图版本，防止旧图/旧轨迹混用 |
| run/call/request/plan/binding/feedback ID | 运行归档、模型调用和动作证据关联；无任务语义 |

用户主要操作永久物体 ID、CAD 型号和配置区域；内部追踪 ID 不应变成额外识别任务。

## 回观测位姿与恢复边界

交付后回配置观测位姿并观测来自 2026-10-29 用户要求，放在 `completion_requirements.after_each_object` 中；实际动作是 Responses 编写的显式 node。runtime 检查要求是否完成，不偷偷插入运动。整个任务最后回任务开始位姿是另一条要求。

恢复由 Decisions 在满足真实前提的能力中选择，再归档/校验新的 node/edge。过去只有固定观测位姿，不能把再次调用它称为不同视角恢复。本轮增加不同视角参数，但无有效地图的初始感知失败仍无法安全移动，不能声称所有失败都可自动恢复。

## P50 的真实耗时依据

P50 是修改前成功运行：扣除初始 Responses 为 245.305 秒。33 次 Decisions 合计 45.108 秒，单次中位数 1.368 秒、最长 1.940 秒。六次 observe_scene 合计 55.202 秒；两次 verify_place 合计 21.290 秒，其中包含后来已取消的重感知。

cuRobo 使用锁定官方实现、CUDA、CUDA Graph 与公开 BatchMotionPlanner API。黑件一批 IK 中，实际 IK/硬检查/FK 为 0.0193 秒，机器人配置更新为 2.642 秒；四候选原生 plan_grasp 调用 13.850 秒，另有配置更新 2.654 秒。这里是服务阶段墙钟时间，不是 Nsight GPU kernel profile。不能把“用了 CUDA”说成已充分优化。

暖 build_scene 的一次 service 总计 1.309 秒，其中 mapper 0.133 秒、覆盖诊断 0.029 秒，预览/发布 1.075 秒。CPU MuJoCo 网格射线是感知自体像素过滤；深度投影覆盖诊断与 GPU 机器人分割/碰撞是不同操作。

FoundationPose 输入网格约 2000 面，但原碰撞蓝盒为 33082 面、黑件为 90916 面。当前未声称已把所有 CAD 碰撞资产降到 2000 面；此项仍需独立验证形状近似与实际规划收益。

两轮均完成粉色 OBB+GraspGen、配置 XY 放置、拆包、独立黑件 ID、CAD+对应臂离线抓姿、右盒放置、交付后回配置观测位姿并观测，以及最终实际关节和任务完成核验。没有 skill/algorithm 错误。每次 verify_place 只有一个 Decisions 请求、两个 predicate，没有 SAM3/FP/深度落点重测。技能剩余耗时包含反馈/采集、执行链绑定、结果保存和地图实体失效处理，不等于模型 HTTP 延迟。

六次 observe_scene 分别是初始、粉色释放后、粉色交付回位后、拆包后、黑件释放后、黑件交付回位后；都复用了已有有效采集，没有失败后原位重拍。释放后的两次分析用于恢复可供运动的实测碰撞地图；纯视觉“放好了”不冒充精确的新几何。回位后的两次观测由既有用户要求产生。当前没有把这六次称为已经最少或足够快。

P51 初始 observe：分割/深度 1.971 秒、桌面/检测几何 0.815 秒、身份关联 2.405 秒、几何过滤与 CAD/OBB 6.556 秒。后续身份关联阶段为 1.584–5.575 秒，包含视觉请求与对应处理；已缓存型号的单盒 CAD 更新约 0.14–0.18 秒。observe_scene 不执行轨迹碰撞检测。

P51 初始建图服务 2.178 秒，其中一次 GPU 机器人分割器配置 0.817 秒、mapper 1.066 秒；暖态这两项约 0.002–0.003 秒、0.096–0.137 秒。预览/发布约 0.158–0.624 秒，较 P50 黑件建图的 1.075 秒减少，但不是固定输入的严格配对基准。

新增两个腕部倾角在 P51 当前地图上，通过真实公开 GPU 双臂规划和完整轨迹碰撞验证，规划接口墙钟为 1.633 秒和 1.480 秒；没有驱动机器人，不能据此宣称已验证它们改善遮挡。
