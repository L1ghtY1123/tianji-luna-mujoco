本次完成用户批准的两项实现：按来源实测支撑面与实际抓取 TCP 计算释放高度；改善标注并允许在提交永久 ID 前纠正错误初选。Responses 与 Decisions 都保持 `gpt-6-luna`。当前任务边界仍是同一臂覆盖来源和固定目的地、固定 CAD、保留抓取旋转。

## 当前合同与实现

控制台 Z 现在是物体底面相对目标支撑面的间隙，默认 10 mm；XY 仍是控制台配置的 TCP 位置。桌面使用实测桌面 Z，容器使用当前测量的盒口最高点。计算为：

```
物体底面目标 Z = 目标支撑面 Z + 配置底面间隙
TCP 目标 Z = 实际抓取 TCP Z + 物体底面目标 Z − 来源实测支撑面 Z
```

这个公式保留实际抓取旋转，假设物体原先直接受来源支撑面承托、抓后相对夹爪不滑动。物体堆叠、错误支撑绑定、滑移或旋转变化仍会破坏该假设，不能把公式成立解释为真实落点一定正确。缺失来源支撑证据时明确失败。选臂阶段尚无实际抓取 TCP，只使用明确标注的估计值；抓取后重新检查同一臂的实际放置目标。

旧 `place_tcp_height_m` / `container_release_tcp_height_m` 已退役，旧保存值 110/100 mm 不会被误解释为新的底面间隙。新字段是 `place_bottom_clearance_m` / `container_release_bottom_clearance_m`。碰撞球仍校验目标和轨迹，但不参与决定目标高度，也不触发自动抬高目标。

身份流程现在是：单视角暂选 → 当前跨相机物理分组 → 一轮当前多视角与日期参考联合复核 → 必要时重新归组 → 原有归属冲突裁决与有限重选 → 提交永久 ID。复核明确说明“跨相机属于同一个物体”并不等于“属于请求的身份”，允许改选、`no_match` 或 `unknown`。历史参考不足时仍保留有限的旧参考回退，不重复同一输入直到满意。

标签锚定在自身掩码的可见表面内，长标签或狭窄表面使用指向自身表面的引线。保留真实轮廓和内部孔洞，不改分割、不填色覆盖物体。颜色由标签确定，有限调色板可能复用颜色，文字标签仍是标识依据。证据输入版本为 `surface-label-multiview-review-v3`。

主要入口：`src/luna_mujoco/demo_placement.py`、`planning_settings.py`、`transfer_reachability.py`、`task_subjects.py`、`subject_assignment.py`、`raw_visual_input.py`。同步更新技能合同、README 与开发约束。

## 未解决问题

1. 未知物体 TSDF 附着球包络仍可能过度伸出真实底面，阻断本来按底面间隙生成的放置目标。本次没有删除碰撞检查，也没有通过修改目标高度绕过问题。
2. 粉色物体暴露了抓取和失败收尾的持物判断不一致，不能承诺任意失败都一定回观测位姿；本次实际行为是无法确认安全回位条件时停住。
3. 推测交付会把“已在容器内”与“进入控制台小区域”混淆，黑色 CAD 已提供一个反例。还需要审查松爪前后证据、抓取偏心与落地滑移，以及当前视角是否足以识别越界。
4. 多视角复核增加 Decisions 输入和延迟；全部使用 Luna 并不意味着调用量不变。冻结结果证明能纠正一个错误初选，不能证明跨时刻身份已稳定，也未覆盖完整遮挡、相同物体换位等反例。
5. 干扰物场景中，固定区域与测得容器范围不一致。程序在抓取前拒绝执行；当前证据尚不能区分容器位姿估计偏差、区域匹配边界或身份错误，需要结合该次测量继续定位。
