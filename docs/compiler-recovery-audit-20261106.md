# Responses 编排与观测恢复专项核对

## 证据与优先级

统计延续 `reliability-audit-20261106.md` 的 12 次正常入口实验，各次版本不同。3/12 首稿通过、9/12 首稿失败；合计 22 次 Responses 调用均发生在执行前。校验累计报告 10 条路径前提错误、4 条重复出边、1 条不可达节点、1 条旧版修订改任务；另有 1 次旧版输出截断。错误条数不是实验数。

按最终停止原因去重：Responses 2 次，身份连续性 3 次，抓取/放置数值规划 3 次，碰撞几何/地图前提 2 次，夹爪执行 1 次，完整成功 1 次。后三组共 6 次属于技能/执行链，但不能把身份错误传播出的地图失败也重复算进该组。最近 477 次 Decisions 的 40 个事实 unknown 全在身份关联；unknown 不一定终止任务，高置信度也不等于关联正确。

优先修 Responses 是因为它经常阻塞开局并占用修订时间，不是因为它占所有最终失败的多数。当前轮先处理反复出现的恢复数据流和结构修订错误，再用正常入口验证下一个真正阻塞点。

## 已复现的编排错误及修复

实验 `296d96634dce41a498dc05d9ea31cf83` 的初稿，两处抓取恢复都是 observe_scene 后直接回 generate_grasps。重新观测使旧 placement_zone_ready=false；后续 resolve_placement 要求它为 true，所以编译拒绝是正确行为。下一版又同时留下 c_bind_work_area 的两条 success 出边及两个失去入口的节点。

- prompt 明确 success、非 success、失效、保留、参数条件的事实语义；要求追踪恢复后的整段后继，而非只检查重试节点。
- 按“子图接口 → 正常路径 → 有限恢复 → 每条后继依赖”组织编排指导；拓扑仍由任务和技能决定。
- 校验错误增加 fact_dependencies：该路径最后一次修改事实的节点/结果，以及从注册契约推导的产生该事实的技能和条件参数。程序只报告依赖，不修图、不补动作、不改变校验门槛。
- 修订明确替换原有 (source,on) 路由，清除废弃断开节点，禁止追加同键出边。原物体提议和任务要求继续冻结。

## 恢复策略调整

优先由 Decisions 选择 Responses 已编排的：回配置观测位姿 → observe_scene → 恢复失效的前提 → 原检查点。配置回位不再另问“是否遮挡”。额外腕部视角仍需一个明确的视觉缺失判断。

空手、合法 observation 地图、关节/碰撞/轨迹检查和部分执行保护保留。首次地图建立前可能只能原位观测；持物时不能进入空手观测链；已经释放或加工后只能恢复证据和核验，不能重做物理效果。重复同一输入复用已有判断，有限恢复不能靠循环刷 yes。观测也不能直接解决固定抓姿的 IK 不可达。

### 冻结输入编排

使用同一归档三相机 JPEG 原字节、原自然语言及初始事实，在独立编译进程测试，不执行机器人动作。

| 版本 | Responses 调用数 | 编译结果 | 模型耗时 |
|---|---:|---|---:|
| 原实验 | 3 | 初稿恢复丢前提，第一次修订重复边/不可达，第二次修订通过 | 约 526 秒 |
| 新 prompt 第一版 | 1 | 首稿静态校验通过；恢复覆盖仍不足 | 221.257 秒 |
| 补强恢复覆盖的第二版 | 1 | 首稿通过，生成独立 recover_view 及各检查点恢复选择 | 217.354 秒 |

第一版虽合法，仍将一些可恢复身份缺证直接结束，并重复询问腕部视角的视觉前提。第二版明确要求独立审查恢复覆盖，不得仅为通过校验删除合法恢复；还清除了 identify_target/observe_scene 技能文档中与配置回位新规则冲突的旧说明。第二版包含选择不确定、输入/产物身份、目的绑定、区域/运动前抓取规划等恢复。其 recover_view 为 build_scene(observation) → move_to_observe(configured) → observe_scene，返回后重新建立区域等前提；释放后仍只重核验，不重播动作。

两次单样本编译成功不等于稳定首稿通过率。每次完整实验仍从自然语言在线编排，不执行这些归档成品图。

### 完整实验 1：编译通过，暴露当前支撑判断问题

`7814cbd08a244592a4894d04b495039c`：双物体正常入口，首稿通过，1 次 Responses，运行中 0 次 Responses，总计 499.70 秒。第一件抓取、放置、拆包和产物交付成功；第二件 ID169 已关联，但 identify_target 的 current_support 选择两次 unknown。图确实执行了配置回位和重新观测，随后恢复次数耗尽。

原问题为多选：候选 ID167、170、171、none_of_listed、unknown。模型选对 167，但 confidence=0.5。输入包含目标点云边界和历史桌面，缺少两个当前候选盒子的已测 CAD/支撑面。首图只看到另一侧黑件，目标与相应容器同时标注的视角排在最后。历史初始容器提议仍在记忆，但原实现只在提议采集等于当前采集时使用，之后改问全量多选。

冻结消融均保存，未重试相同有效回答来刷 yes：

| 输入/提问变化 | 结果 |
|---|---|
| 只增加候选 CAD/支撑几何 | 错选 171，confidence=0.44；仍 unknown，改进失败 |
| 原视图顺序，增加几何，问正确关系谓词 | P=0.0，错误；改进失败 |
| 目标及候选同框视角优先，原多选 | 正确 167，confidence=0.74；仍 unknown |
| 同框视角优先，聚焦正确关系谓词，不加候选几何 | P=0.97 |
| 同样输入，问错误容器关系 | P=0.0 |
| 同框视角优先、正确关系谓词、补充候选几何 | P=0.90 |

采用的修复：保留全部相机，优先呈现同时定位关系双方的视图；历史关系只作带来源/时间的待验证假设，当前关系由单独谓词确认。明确 no 后排除该候选，再问一个不同的剩余候选选择题；unknown 原样返回，不改写历史、不降低阈值。没有历史提议仍保留选择能力。候选已测几何按当前采集/实例绑定投影，旧几何明确排除，不代替 Decisions 判定支撑。

另修复真实调度错误：remaining_traversals=0 的 recover 仍出现在模型选项里。现在只向 Decisions 提供未耗尽操作和 unknown 弃选；原图和完整分支记录仍保留。无可用操作时返回执行层 unknown，不制造模型判断。

`support-geometry-probe.py` 验证两个候选几何传递及旧采集排除；`support-flow-probe.py` 调用实际 controller 方法，验证历史提议不是事实、no 后只排除该候选并提出一个不同问题；四项前述检查及 Ruff 重新通过。

后续完整仿真实验使用上述最终修复；冻结结果不是端到端成功率。

补充限制：把最终完整的带时间/来源假设状态加入旧失败帧后，正确谓词 P=0.76，仍 unknown；另一个更短的角色说明变体仅 P=0.56，没有采用。错误历史假设控制均为 P=0.0。不能只引用上表 0.90/0.97 而声称支撑判断已全面稳定。该问题的真实入口结果见下一次实验。

### 完整实验 2：支撑判断通过，放置路径失败

`40199120c3ef4fb2931e6be0e9894e89`：双物体正常入口，首稿通过，Responses 246.201 秒、总时长 483.74 秒，运行中 Responses=0。两次实际 current_support 谓词均为 P=0.99。第一件完整交付；第二件 ID177 的身份、支撑、抓取、放置 XYZ/IK 求解均通过，plan_place 接近阶段失败，仍持物。独立验收 1/2，整体失败。

发现并修复独立数据流缺陷：plan_place 顶层 candidate_failures 在 outcome_state 中丢失，graph 只收到空 details。现在保存 resolution_id、尝试数量、错误码、失败阶段和 SDK 文本，重复投影保持一致；failure_report 将其归为 motion_planning，阶段为 approach。旧 resolve_placement 的 12 次拒绝统计回归仍通过。

Responses prompt/plan_place 契约同时说明：持物时不能进入空手观测恢复；在没有执行放置动作、前提仍有效时，可由 Decisions 选择图中有限的同一授权目标规划重试，保持数值检查。此说明不插入重试、不改变目标、也不保证求解成功。后续完整实验验证生成图与实际结果。

编排要求同时补充释放后核验的恢复覆盖：只回到 verify_place，保留原释放回执；不能并入会重复抓放/加工的前置恢复分支。当前地图不足时先建立移动前提，全部跨技能动作仍由初始 Responses 编排。后续实验验证。

继续追踪发现 `return_pose.py` 的 observation_motion_scene_ready / prepare_empty_hand_motion_scene 把 pending_transfer.verified 当作唯一释放条件，导致“目的区域 unknown → 不能回位补充观测”的循环依赖。修复将其与移动依据分开：语义未确认时要求绑定一致的真实释放/开爪回执、明确的 not-held 视觉事实、包含目标且采集于释放后的当前 observation 碰撞地图。缺一仍拒绝；不使用释放前保留地图，不改变 pending_transfer.verified，不绕过运动检查。已有完全核验后的路径保留。

`released-observation-motion-probe.py` 改前失败、改后通过。反例覆盖地图缺失/过期、目标缺失、错误代次、错误释放回执、目标不匹配、仍持物或夹持未知；这些情况均拒绝观测移动。此检查使用隔离构造的状态，不是一次物理恢复成功记录。完整仿真需另行验证。
