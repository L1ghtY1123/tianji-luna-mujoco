# 终止失败的统一回位

具体恢复分支用尽，或者编译、执行出现未处理异常时，系统执行固定的 `terminal_failure_return` 图。它包含独立可审计的停止、必要观测、建图和回位节点，不由 Responses 临时生成。Responses 看见 21 个任务能力；另外 4 个收尾能力仅供系统固定图使用。

1. `prepare_failure_return` 取消尚未执行的电机命令，保持夹爪目标，取得新的运动 epoch，保存原任务失败及实际关节。已到配置观测位姿且夹爪状态满足收尾条件时立即停止。
2. 当前地图有效且空手明确时，直接规划回位；当前视觉核验、attachment 和场景绑定均有效的持物情况，保留物体碰撞几何和夹爪目标回位。两臂均从实际当前关节开始。
3. 部分执行、夹持未确认或场景失效时，`observe_after_failure` 在当前位置采集原始 RGBD，用一次视觉二值判断检查两只夹爪是否持物。不根据开合角度推断泡棉夹持。明确空手才清理临时持物状态、关联实例并提交当前测量；`build_failure_scene` 发布数据库版本一致的 cuboid + CAD + ESDF。视觉未知或缺少可靠持物几何时不能盲目移动。
4. `return_after_failure` 调用 cuRoboV2-Fast 双臂规划及实际命令轨迹检查，保留世界/自碰撞、关节、场景版本、持物和轨迹起点检查。实际关节确认到观测位姿后，已确认空手的夹爪经张开姿态碰撞检查后张开，并按实际反馈验收。持物回位保持夹持目标。收尾完成后再次停止。

回位成功只写 `failure_return.status=returned`，原任务仍为 `needs_attention`。原任务失败独立保留，回位不能证明任务成功。已在观测位姿写 `already_at_observation`。回位无安全路径、地图无法发布、持物不能确认或服务不可用时写 `blocked`，记录具体原因并保持停止；收尾失败不再递归发起收尾。

所有根失败/未知出口在执行前接入这个固定图并完整校验、归档及显示。图预算耗尽、未声明结果、意外异常等绕过正常出口的情况，在任务边界使用同一固定图兜底。用户取消保持立即停止语义，不擅自启动新运动。

验证证据在 `data/runs/single-arm-memory-20261111`：终止路由注入覆盖空手、持物、地图刷新、已到位、回位失败及原任务失败保留；控制检查覆盖停止 epoch、实际关节起点、先检查再运动、持物未知拒绝及单次收尾。当前应用入口也已在隔离数据目录构造并执行真实停止节点；这不等同于全部故障下都存在可行回位路径。

实际仿真：独立只有机器人与工作台的场景，从当前 RGBD 拟合 80,359 个桌面内点发布 cuboid；双臂各偏离配置观测关节 5°，执行生产固定收尾图，最终最大误差 A=0.0000039745°、B=0.0000039745°，再次停止，保留 needs_attention 和注入原始失败。双臂后处理旧校验曾报 CUROBO_INVALID_CONFIG，已在项目适配层替换为现有公开 RobotCollisionChecker 的完整命令检查；SDK 未修改。

完整抓放入口另有失败实验：5c7dfb14a1b149099bd548cc00df15fb，在开局蓝盒实例确认时得到否定回答而未执行运动；终止收尾记录 already_at_observation。该实验未完成抓放，不作为抓放成功证据。持物回位目前只有路由、绑定与数值接口检查，尚无完整持物物理回位实测。

日志故障不会阻止已满足几何和持物前提的终止回位：系统收尾不依赖普通任务日志写入或进度回执更新；新的几何测量仍必须成功提交数据库和发布场景。普通任务继续受原日志前提约束。
