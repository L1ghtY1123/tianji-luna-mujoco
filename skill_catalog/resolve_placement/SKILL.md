# resolve_placement

Resolve a held-object pose inside the bound placement zone and release_mode. surface_setdown searches the lowest allowed support gap. container_release uses one height per XY: complete-object lowest point above the published container rim by the operator-configured gap, default 10 mm; existing IK tolerance applies to achieved feedback. Check complete footprint, gripper/held collision, workspace and held IK. It does not search higher heights or silently switch mode. Configured XY is fixed. Otherwise propose centers of 4, then 8, then 16 subdivisions as needed: Decisions chooses an XY candidate ID before numerical Z search. Accept the first feasible candidate in the preference-ordered search. Keep the grasp orientation unless the task explicitly requires another supported orientation. For surface_setdown only, start Z at the hard clearance plus the recorded tracking reserve and raise within its configured bound. Check held-object/gripper geometry, current collision world, offline workspace and fixed-orientation IK. Decisions chooses semantics and candidate IDs; it does not certify numerical safety. Whole-region choices are operation proposals, not high-confidence physical facts. Extra spatial clauses use current annotated candidate footprints. plan_place separately checks the trajectory for the bound release mode. Unknown never silently selects an alternate configured XY. Geometry and region binding must precede grasping. Explicit capture_mode=fresh while holding only supplies current candidate images against valid geometry; it does not establish observed=true or repair a stale scene. All visible candidates explicitly rejected returns failure; missing or ambiguous candidate evidence returns unknown. An accepted candidate is sufficient. On numerical search exhaustion, graph-facing details.placement_search preserves attempted counts, rejection codes, search limits and whole_destination_infeasible=false. These failures describe sampled XY with the current grasp orientation and scene, not infeasibility of the entire destination.

Inputs, typed arguments, prerequisites, effects and recoverable results are defined in `contract.json` and the registered parameter schema. Responses authors normal and recovery routes; Decisions only selects existing branches. This skill executes only its selected operation. Current policy: `docs/cad-runtime-policy-20261102.md`.

The bound region and collision geometry must already be valid before grasping. While holding, an explicit `capture_mode=fresh` can acquire candidate images for a spatial-language judgment; it does not run SAM3/FoundationPose/OBB, rebuild the map or establish `observed=true`. Missing geometry cannot be repaired by these images. `observe_scene` and `perceive_placement_zone` are not held-object recovery operations.

For semantic selection, an accepted candidate is sufficient. If every proposed candidate is visible and explicitly rejected, return failure (`placement_candidates_rejected`). Unseen or ambiguous candidates leave unknown when no candidate is accepted; a negative answer is not a visibility diagnosis.

When numerical search is exhausted, `placement_no_candidate` preserves the attempted-candidate counts, rejection reasons and search limit in Graph/Decisions evidence (`details.placement_search`). This describes sampled XY under the current grasp orientation and scene; it does not prove the whole destination infeasible. The graph owns any subsequent recovery.

For free-region XY proposals, provide the current measured and valid published collision-layer footprint gaps with travel distance. placement_preference=clearance prefers larger measured horizontal separation up to the configured soft-clearance distance, then shorter travel; reach prefers shorter travel. A missing gap supplies no separation evidence. These rankings guide Decisions while full numerical collision checks determine feasibility.

For preference=clearance, search candidates meeting the measured soft-clearance goal across 4, 8 and 16 subdivisions before trying the deferred lower-clearance candidates. The deferred candidates remain eligible after that search, ordered by decreasing measured gap. This preference orders at most 28 XY proposals and uses the same endpoint and trajectory checks.
