# Tianji Luna MuJoCo

观测时序修正：接受的实例更新先提交数据库，再更新内存与任务账本；几何变化使碰撞场景待发布。当前支撑证据与永久 ID 分开，重新观测后的再次抓取需由在线 graph 显式恢复 `source_support_current`，不插入隐藏技能。历史失败核对与验证见 [历史故障和观测时序](docs/history-timing-validation-20261107.md)。

恢复策略由 Responses 编排、Decisions 依据具体失败选择有限分支。配置回位和满足前提的腕部换视角均可用于观测恢复；已在配置位姿时，应判断所选分支能否改变缺失证据。配置回位无需额外遮挡许可题，空手、有效地图和实际运动检查保留。编译校验反馈包含失败路径上最后一次前提变更及注册的事实产生技能；修订仍只在执行前进行，不能改写清单和根任务。

正常主线的空手身份或支撑 unknown 校验观测恢复覆盖。单一路径可直接连接恢复技能，多种恢复方案才需要 Decisions 选择。数值抓取失败依据具体拒绝证据进入有界替代路径或结束。

精简编排输入中的技能 contract 同样包含观测恢复要求；生成前的末尾检查区分原样重规划与观测恢复。候选池 `pool_expansion_not_permitted` 仅限制技能内部扩展冻结候选池，不表示整个 graph 不可恢复。静态图合法与恢复覆盖充分仍需分别验收。

开局优先一次 Responses，按作用域输出显式路由组 `sources/outcomes/target/max_traversals`。作用域公共失败去向由 `on_failure/on_unknown` 明确声明。程序逐项展开并生成边 ID，完整图继续经过拓扑、数据流、恢复覆盖和完成条件校验。产物登记保存同次采集的唯一测量掩码、框与位置参考，后续身份关联复用这些定位证据。编排经验库同时保存按契约筛选的真实终止技能失败，开局用于检查相应前提和恢复路径。

自然语言和三相机初始 RGB 输入 GPT-6 Luna Responses，结合技能契约、配置区域及 CAD 目录，生成物体清单和显式 graph。运行时由 Decisions 判断当前证据、选择已声明的正常与恢复分支，由机器人 skills 完成感知、几何、规划与执行。

系统只提供在线编排模式。归档 graph 的展示与导出用于审阅，不提供直接加载成品 graph 执行的产品入口。

Skill 是带参数、前提和明确结果的稳定操作接口，内部步骤固定。Responses 在满足任务依赖后，优先编排可见抓取面暴露、遮挡少、周围间隙充足的物体。实际选臂、IK 与碰撞验证由对应技能完成。主要完整实验使用两个输入物体。

## 当前实现

- **层间数据边界**。Graph 使用 `InitialPlan`、`TaskSpec` 和 `GraphSkillResult`。时间记忆数据库由 `ObjectMemory` 与持久化 `WorldInventory` 提供，保存实例及历史。空间记忆由 `SpatialMemory` 持有，内容为碰撞场景及其来源、版本、启用和有效性状态。原始观测、测量缓存、配置区域归执行层，任务账本记录本次执行责任。Decisions 的单题输入由 `DecisionQuery` 校验。回放分别显示时间记忆数据库的提交快照和空间记忆的碰撞几何。数据归属和传递时机见 [在线 graph 架构](docs/native-graph-implementation.md)。

  Graph 的 router 通过 `GraphDecisionRequest/GraphDecisionResult` 传递问题、绑定、原失败及有限分支，执行适配器不再反读执行器字段。执行层持有记忆服务；技能 context 只放数据，碰撞检查和释放核验接收 `CollisionSnapshot/ReleaseLedgerSnapshot`。加工证据函数返回 `ProductRegistration`，由执行层提交原有数据库事务。检查范围与证据见 [分层数据边界验证](docs/layer-boundaries-validation-20261107.md)。

- **逐题证据范围**。通用判断按用途和题目投影 state；来源剩余物体判断不携带完成账本，纯放置语言问题不携带当前图像。拆包和放置分别构建视觉输入，夹爪机械反馈只留在执行层。全部 Decisions HTTP 题目经 `WireDecisionQuestion` 校验。恢复选择读取声明的子图、相关契约和原始失败。支撑明确否定与 unknown 分开返回。旧的运行中 Responses 视觉辅助入口已删除。审查范围及限制见 [Decisions 输入核对](docs/decisions-input-audit-20261105.md)。

- **Responses 编排与校验**。输出 `version=2` 的 graph/subgraph/node/edge。首轮通过即执行，图校验失败时在任务技能开始前最多修订两次。修订通过 `root`、`subgraphs` 和 `remove_subgraph_ids` 明确替换、添加或删除作用域，省略的作用域保留。程序应用这些编辑后，与冻结的候选清单、根任务要求组合并重新校验完整图。每次归档保存模型原始输出和合成后的完整 `graph_proposal`，供回放逐版审阅。数据流错误附带实际符号路径及缺失前提。
- **编排失败记忆**。编译器把图校验失败按请求哈希持久化到 `data/runs/compilation-memory.sqlite3`，新任务读取与当前可执行技能契约匹配的历史约束和反例。记录包含错误、原请求来源、相关技能及数据流反例，按错误族汇总进入 Responses。重置任务保留这份编排记忆。独立的数据流与恢复覆盖错误同轮报告，后续修订保留前几轮错误记录。输出 schema 先列根节点以声明任务子图接口，再填充子图定义；局部节点先于入口和边。验证见 [Responses 编译与失败记忆](docs/responses-compiler-validation-20261107.md)。
- **编排推理预算**。GPT-6 Luna Responses 使用 high 推理强度、64000 输出 token 上限（包含推理和最终 JSON），输出紧凑 JSON，并复用共享子图。单次编排超时默认 600 秒。每任务最多一次初稿加两次图修订。回放展示各版完整图及校验错误，运行时 Decisions 按最终图选择分支。恢复 router 用 choices 明确列出可选 edge.on，收到原失败及各分支剩余次数。可恢复失败由 Decisions 选择声明的有限恢复路径，无合法恢复时明确结束。
- **按需实例关联**。每轮实例关联使用执行层投影的 association_scope。当前输入及其产物优先，已交付实例保留物理历史并按需比较。单个身份谓词的历史证据限定到被比较实例，当前已接受主体继续保留标注与几何，帮助区分相似物体。新实例登记前仍检查全部可用历史身份。已交付内容物只有在入盒回执、有效空间占据和当前容器 RGBD 对应一致，且通过已有容器位置稳定性检查，且候选完整有效表面位于占据范围内时，才记录为 deferred_candidates。记录包含采集、场景版本、容器、回执、测量范围和占据范围，identity_assigned=false。来源盒、工作区及未完成物体的已知支撑容器继续完整关联。占据失效、容器对应缺失、候选伸出范围或后续任务重新操作该容器时，恢复通常关联。空间记忆继续保留交付实例的占据；单件位姿保持未测量。association_scope 参与观测复用键。

- **Decisions 输入**。已接受的当前身份提供可见事实。清单完整性不作为执行前提，任务语义沿用已编译要求。新实例待确认提议独立反馈，碰撞依赖来自当前测量、保留及受动作影响的图层和当前操作对象。新增实例、身份不确定和恢复所需可见性按需独立判断。当前视图每相机一张，身份关联按需加入历史参考。身份选项保留实例的完整历史参考说明。图像标签、state 和 question 使用一致名称，哈希与来源审计留在程序侧。放置核验的独立问题共享三相机图像。恢复分支读取结构化结果摘要，完整规划调试数组留在实验日志。
- **永久物体 ID**：清单绑定实例及操作历史；CAD asset ID 表示模型，允许多个实例共享一个 CAD。graph 可用共享 subgraph 循环处理 $selected，执行账本记录实际选中输入的处理责任。
- **几何**：桌面使用 cuboid，未知物体使用当前观测更新的 OBB，已匹配 CAD 的物体使用 FoundationPose 当前位姿。生产模式为 `cad_obb`。
- **CAD 配准**：SAM3 掩码、RGBD、内外参和匹配 CAD 输入 FoundationPose；选择有效深度最多的一个相机，输出转换到统一世界坐标。执行层从物体操作历史与空间失效状态投影跟踪上下文，已知实例的物理上下文未变时，以上一帧位姿初始化当前帧 track_one；有变化时重新配准。不读取 graph 进度，也不将历史位姿当新测量。保留来源、标定及坐标绑定检查，不做额外几何残差复核或 ICP。
- **抓取**：有离线抓姿的 CAD 按执行臂选择对应抓姿；未知 OBB 使用 GraspGen。选臂依据任务约束、工作空间和可达性，颜色不绑定机械臂。
- **容器抬升**：使用已发布 CAD/OBB 包络计算邻近障碍高度，保留障碍同样参与；不再要求已消耗输入具有当前掩码。正式退役 ID 与物理几何分开处理。
- **attachment**：抬升成功且确认持物后建立；持物模型随臂、抓取变换、场景版本绑定。
- **放置**：`perceive_placement_zone` 给出目标区域；普通区域按 4→8→16 分区提出 XY，Decisions 按语言约束、当前实测与已发布几何的水平间距及移动距离选择，遵循 clearance/reach 偏好；数值算法检查工作空间并求接近碰撞阈值的 Z。工作台指定区域使用配置 XY。`resolve_placement` 产生当前落点，`plan_place` 只规划该落点，不再保留另一套网格/yaw 搜索或旧 `plan_place_batch` 接口。
- **技能清理**：当前 22 个注册能力，包括显式空抓恢复 `recover_failed_grasp`；旧 `plan_transport / execute_transport / drop / verify_drop` 契约和执行器已删除，容器几何共用 `robot_skills/container_geometry.py`。
- **抓取碰撞一致性**。官方三段式接口按执行臂临时排除两侧 Link3、Link4 链接，接近段恢复，调用返回或异常时再次恢复。实际命令逐段检查环境、另一臂、非接触部件和目标接触条件。第三段实际抬升成功且机械反馈通过后建立 OBB/CAD attachment，回执绑定物体、执行臂、任务、采集和场景。
- **夹爪进入间隙**。未知物体抓取端点使用完整实测点云与张开接触垫碰撞网格凸包检查，计入配置的测量不确定性和碰撞余量。闭合预测使用轨迹端点 FK，越界反馈保留实际角度、命令、限位和稳定窗口统计。
- **初始身份输入**。登记阶段接入共享 SAM3 分割和注册 RGBD，提供当前掩码及参考表面投影证据，按当前比较主体限定几何摘要。
- **轨迹**：调用固定版本的官方 cuRobo。抓取默认每批两个候选；已确定的放置目标使用 BatchMotionPlanner、batch=1。放置包含接近、放下及释放后的撤离。
- **抓取池耗尽**：未知 OBB 的候选经完整数值拒绝后，可在技能内部继续下一有界候选池；CAD/OBB/cuboid 场景与双臂碰撞证据正确参与该判断。有限数值端点误差超限同样属于候选拒绝，允许继续既定额度的候选池；无效 FK、非有限数据或绑定不符仍停止。碰撞和端点门槛、CAD 离线池与 Responses graph 不受此搜索改变。
- verify_place 对普通 container_release 校验执行绑定、实际盒上释放与开爪，按用户规则建立入盒回执。该分支无需 Decisions。surface_setdown 和额外落地关系使用同次三相机 RGB 逐题核验。空间记忆允许以已测容器包围范围覆盖已入盒且无法逐件定位的内容物，并记录规则和几何来源。
- **判断结果**：区分命题概率不确定、事实选择低置信度、明确 unknown 和拒答；回放显示原始答案及程序采用的规则。恢复 router 保留完整判断证据。放置的任一必要条件明确不满足即为失败，不被另一项 unknown 掩盖。
- **来源绑定**。沿用 TaskSpec 的来源要求。current_support 独立核验当前物体的直接支撑或容器，完成时检查来源是否还有匹配输入。
- **观测覆盖**：观测成功不代表全部待处理物体都可见。腕部相机随动作改变方向；当前缺少目标时返回明确缺失结果，由 Responses 编排的可见性恢复分支处理，不隐式回位或重拍。
- **恢复证据**。连续 router 通过 last_failure 引用技能失败及绑定主体，last_result 保留紧邻节点的回答。抓取几何的可见性与实例识别分别提问。
- 批处理每件交付后由 Responses graph 显式回配置 observation 位姿并重新观测，再选择当前输入。all/count 使用共享子图，初始数量不限制运行时成员。最新观测确认来源盒已空即结束本批。最终双臂回位由实际关节反馈验收。VLA 起始姿态仍属于加工技能前提。
- **共享子图**：物理节点按输入永久 ID、声明的子图调用路径和动作节点防止重播，允许不同输入或不同声明调用复用同一子图；循环重入同一次动作仍拒绝。子图之间继承当前事实，开始新物体不会自动恢复观测或地图。
- **补充视角**：技能直接判断是否缺少任务所需视觉信息，裁切/遮挡等原因单独诊断；不因无法确定具体原因而否定已确认的信息缺口。原视觉阈值、显式恢复边和运动检查保留。
- **图与回放**：按主图、任务子图、失败处理/恢复分组；正常路线与失败处理各自成图，跨视图入口与返回边可以跳转。保留完整节点和边，未执行节点保留灰色。每行从左到右，正常连续路线用虚线折行连接；跨节点分支用带目标编号的跳转连接，点击定位。未走分支为灰色，实际转移标次数。共享子图默认显示最近一次调用，可切换任一次或累计记录；第一件成功不会覆盖第二件未执行的后续步骤。节点本次失败、证据不足、已进入分支与任务最终结果分别说明，实际调用次序与当时物体 ID 单独记录；Responses 次数按开局编译/正式执行划分。碰撞场景用半透明差异色和归档名称，原始 ID 收进详情。
- **抓取失败语义**：`planning_no_valid_candidate` 只说明当前臂的已评估候选没有通过全部检查，不证明其他臂也不可行；是否安排合法替代由 Responses 生成的恢复边决定。

## 目录与职责

算法代码只有一个维护仓库：`../tianji-algorithms`。Luna 不再保留 `vendor/`、`services/`、`src/tianji_foundationpose/` 或算法注册库副本。

| 位置 | 职责 |
| --- | --- |
| `src/luna_mujoco/` | 应用编排、MuJoCo 仿真、场景与机器人技能；专用 `geometry_service` 保留应用接口 |
| `skill_catalog/` | 技能契约、参数和前提/效果 |
| `resources/robot/` | 本机器人碰撞配置与几何审计，不含算法代码或 SDK 清单 |
| `resources/`、`assets/` | CAD、标定、工作空间、URDF 和网格 |
| `scripts/`、`web/` | 应用维护工具、工作台与回放 |
| `data/` | 实验、运行日志、回放网格和应用规划参数 |
| `../tianji-algorithms/services/` | 唯一的算法客户端、协议与服务适配源码，统一包 `tianji-algorithm-services` |
| `../tianji-algorithms/manifests/` | 官方 SDK 版本及源码校验清单 |
| `../tianji-algorithms/data/luna/foundationpose-registry/` | Luna 使用的 FoundationPose 注册数据，独立于源码 |

SAM3、GraspGen 和 FoundationPose 的服务定义统一位于算法仓库的 `deploy/luna-algorithms.compose.yaml`；本项目 Compose 通过 `include` 使用它。应用及 cuRobo 容器只读挂载同一份算法服务源码，代码中不再临时插入 `vendor` 路径。FoundationPose 客户端和服务共享同一个 `tianji_foundationpose` 包；Luna 所需缓存/跟踪适配在算法仓库的 `services/luna_foundationpose/`。

算法仓库的通用 cuRobo HTTP 服务不替代 Luna 的场景/持物接口；Luna 的 `geometry_service` 从统一包导入算法边界。官方 SDK 与权重仍在算法仓库维护，端口、镜像版本及现有协议保持。

独立 CAD 库位于 `/home/guangyu/projects/CAD`，通过 `LUNA_CAD_ROOT=/opt/cad` 只读挂载；`resources/cad/` 是应用静态副本。

固定/精确 XY 的抓取前放置端点筛选与正式放置共用冻结实测表面质心作为物体位置参考；只筛选该指定 XY，不以区域内另一位置作为通过证据。普通区域继续原有有限分区。该筛选只检查固定夹爪端点，不宣称全臂 IK、持物或完整轨迹已通过。

跨视角身份输入补充同次采集的实测表面投影：将已确认实例的三维点投影到待判断相机，与当前 SAM3 掩码及深度比较。Decisions 仍独立判断身份，不增加问题，不用几何匹配代替永久 ID 裁决；部分表面覆盖与完整轮廓 IoU 明确区分。

时间记忆按事实逐项更新：视觉确认的支撑不因子区域核验 unknown 而丢失；开爪事件不能清除已有视觉支撑。身份请求明确区分初始同采集提议、已确认同采集实例、历史实例与产物首次定位。未见只更新 visibility；ObjectRetirement 需要明确来源、观测和回执，移除/消耗保留历史及 ID。removed 与 consumed 均退出当前身份候选，保留退出原因与历史；不自动恢复退役 ID。暂时未见的活动实例仍可正常跨观测关联。空间记忆用退役 ID 更新活动几何集合，不以未见直接删除碰撞对象。

VLA 效果定义统一来自 resources/vla_unpack.json 的 effect：粉色包装输入、独立黑色产物、视觉确认后消耗输入。动作回执不代替视觉事实。ObjectMemory 的退役接口供明确的执行回执/操作者确认使用；本次不增加“看不见即删除”的自动判断或隐藏 graph 节点。

身份问题明确写出当前 mask、待比较永久实例和该实例的日期参考描述。已确认同采集位置与历史位置分开措辞；容器与内容物即使框重叠也不是同一实例。RGB、掩码、深度和状态不变，只修改问题表述；保持原概率阈值，正例与反例共同验证。

Responses 只编排已注册技能并填写其任务参数，不能修改技能实现、抓姿补偿或数值规划设置。generate_grasps 不接受模型调参字段；未知 OBB 的 GraspGen 抓姿沿执行臂末端局部 +Z 增加 10mm，在 IK 前只应用一次。两臂保持各自安装朝向，CAD 离线抓姿不应用该补偿。

编译恢复覆盖检查：正常主线中，契约可能返回身份/支撑 unknown 的空手检查点，必须提供 Decisions 分支选择，能够经配置观测回位后重新观测。路线可由调用方子图负责；恢复专用检查点不要求再次恢复。检查器不插入节点、不改图、不推断物体状态；仍独立检查技能前提与边界次数。


### 放置模式与恢复输入（2026-11-06）

Responses 在 identify_destination 显式选择 `release_mode`：`surface_setdown` 轻放到支撑面；`container_release` 在任务允许投放时于容器上方释放。模式从抓取筛查贯穿落点、规划、执行和核验。盒上释放用既有携物 plan_pose，不新增 skill；完整物体最低点名义高于已发布盒沿 10 mm，可在控制台调整，实际反馈受既有 IK 位置容差约束。底面与盒沿分别保存。完整物体投影须在有效盒口内，保留持物、夹爪、全机碰撞检查；无解不自动改模式或抬高。释放使空间几何失效，下一次规划前必须按 graph 更新。

抓取第二段及闭合的接触许可限定为当前目标与执行臂两侧 Link3、Link4 的配对，共 34 个配置球。这些链接与其他环境物体、另一臂、其余部件与目标及自碰撞继续使用原数值检查。

多个当前合格输入通过 select_target 的单题 Decisions 按任务与当前视觉、测量信息选择。单候选和明确顺序直接处理，后续规划继续验证数值可行性。
